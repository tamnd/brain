## Solution
## Problem Understanding

We have (N) distinct grid points ((X_i,Y_i)). Each point must be connected to one of the coordinate axes. A horizontal connection from ((X_i,Y_i)) to the (y)-axis costs (X_i), while a vertical connection to the (x)-axis costs (Y_i).

The cost is not the sum of individual segment lengths. Among all horizontal segments, only the longest (X_i) matters, and among all vertical segments, only the longest (Y_i) matters. If the largest horizontal length is (h) and the largest vertical length is (v), the total cost is (h+v).

There are also upper bounds (H) and (V) on how many horizontal and vertical segments may be used. The difficult part is the crossing restriction. A horizontal segment belonging to ((X_i,Y_i)) occupies (0\le x\le X_i), while a vertical segment belonging to ((X_j,Y_j)) occupies (0\le y\le Y_j). They cross in their interiors exactly when

[
X_j<X_i
]

and

[
Y_i<Y_j.
]

The inequalities are strict because an intersection at an endpoint is explicitly allowed.

The coordinates are generated by second-order modular recurrences, so the input gives only the first two (X)-coordinates and first two (Y)-coordinates. The remaining values must be generated in (O(N)) time. The largest (N) is (800,000), so anything quadratic in (N) is immediately unusable. Even (N^2) would mean roughly (6.4\times10^{11}) pair checks at the maximum size. An (O(N\log N)) solution is appropriate, while an exponential search over orientations is completely out of range.

Several boundary cases can quietly break a solution. If (H+V<N), there are not enough allowed segments to connect every point. For example,

```
1
3 1 1
1 2 0 1 0 3
1 2 0 1 0 3
```

generates ((1,1),(2,2),(3,3)). Only two segments are allowed for three points, so the answer is `Case #1: -1`.

The fact that intersections at endpoints are allowed also matters. Consider

```
1
2 1 1
1 2 0 0 0 10
1 2 0 0 0 10
```

The points are ((1,1)) and ((2,2)). Connect the first horizontally and the second vertically. Their intersection is at ((2,1)), which is the endpoint of the horizontal segment, so it is allowed. The answer is `Case #1: 3`. A careless implementation using non-strict inequalities could reject this valid configuration.

Equal coordinates require the same care. For

```
1
3 1 2
2 2 0 0 1 2
1 2 0 1 0 3
```

the points are ((2,1),(2,2),(2,3)). One point can be horizontal and the other two vertical. All segments lie on the same vertical line or meet at endpoints, so this is valid and costs (2+2=4). Treating equal (X)-coordinates as crossings would give the wrong answer.

Finally, zero is a meaningful threshold. If every point is connected vertically, there are no horizontal segments and their cost is zero. Likewise, if every point is horizontal, the vertical cost is zero. A solution that always assumes both orientations are used misses optimal answers such as the first sample.

## Approaches

A direct approach is to decide independently whether every point is horizontal or vertical. There are (2^N) possible assignments. For each assignment, we could check all horizontal and vertical pairs for crossings and count how many segments of each type are used. A straightforward crossing check examines (O(N^2)) pairs, giving (O(N^2 2^N)) time. Even if the crossing check were optimized, the (2^N) assignments make the method hopeless. At (N=30), there are already more than one billion assignments.

The useful observation is that the cost depends only on two numbers. Let (h) be the maximum (X_i) among horizontal points, and let (v) be the maximum (Y_i) among vertical points. Once (h) and (v) are fixed, every point with (X_i>h) is forced to be vertical, and every point with (Y_i>v) is forced to be horizontal.

The crossing condition becomes much simpler under these thresholds. If (X_i>h), point (i) must be vertical. If (Y_j>v), point (j) must be horizontal. A point satisfying both conditions would have to be both orientations, so such a point makes the thresholds impossible.

The key structural fact is that this is also sufficient, apart from the segment-count bounds. Suppose no point has both (X_i>h) and (Y_i>v). The points with (Y_i>v) can be made horizontal, and the points with (X_i>h) can be made vertical. For the remaining flexible points, if more horizontal segments are needed, choose the ones with largest (Y)-coordinates as horizontal and make the rest vertical.

This assignment cannot create a crossing. Every forced horizontal point has larger (Y) than every forced vertical point. Every forced vertical point has larger (X) than every possible horizontal point. Among flexible points, a horizontal point was chosen with at least as large a (Y) as every flexible vertical point. All three possible types of horizontal-vertical pair are consequently safe.

So the problem reduces to finding the cheapest pair of thresholds (h,v) satisfying the segment-count requirements and avoiding a point in the upper-right rectangle (X>h,Y>v).

The minimum (h) required by the vertical limit is the ((V+1))-st largest (X), unless (V=N), in which case it can be zero. Similarly, the minimum (v) required by the horizontal limit is the ((H+1))-st largest (Y), unless (H=N), in which case it can be zero.

Now fix (h). Every point with (X>h) is forced vertical, so to prevent crossings we must choose

[
v\ge \max_{X_i>h}Y_i.
]

We also need (v) to satisfy the horizontal-count requirement. Thus the cheapest possible vertical threshold for this (h) is

[
v=\max\left(y_{\text{req}},\max_{X_i>h}Y_i\right).
]

We can evaluate this for every distinct (X)-coordinate. Sorting the points by decreasing (X) lets us maintain the maximum (Y) among points with strictly larger (X). The strictness is exactly what the endpoint-intersection rule requires.

The two approaches compare as follows.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | (O(N^2 2^N)) | (O(N)) | Too slow |
| Optimal | (O(N\log N)) | (O(N)) | Accepted |

## Algorithm Walkthrough

1. Generate all (N) points from the two recurrence sequences. Python integers are used directly, so the products in the recurrence are safe even when they exceed 32-bit range.
2. If (H+V<N), immediately return (-1). Every point needs one segment, so the two segment limits must have enough total capacity.
3. While generating the points, record the maximum (X) and maximum (Y). If (V=N), connecting every point vertically is allowed and costs exactly the maximum (Y). Use this as an initial answer. If (H=N), connecting every point horizontally gives the candidate maximum (X).
4. Sort all (Y)-coordinates in decreasing order. If (H<N), the value at zero-based index (H) is the ((H+1))-st largest (Y), call it (y_{\text{req}}). Any valid solution with at most (H) horizontal segments must have (v\ge y_{\text{req}}). If (H=N), use (y_{\text{req}}=0).
5. Sort the points by decreasing (X). If (V<N), the point at zero-based index (V) has the ((V+1))-st largest (X), call this (x_{\text{req}}). Any valid solution with at most (V) vertical segments must have (h\ge x_{\text{req}}). If (V=N), use (x_{\text{req}}=0).
6. Sweep the sorted points by groups of equal (X). Before processing a group with coordinate (x), maintain `greater_y`, the largest (Y) among points whose (X)-coordinate is strictly greater than (x). This strict grouping is necessary because a horizontal segment ending at (x) may touch a vertical segment whose endpoint is also at (x).
7. For every group with (x\ge x_{\text{req}}), choose (h=x). The points with (X>h) are forced vertical, so every vertical threshold must satisfy (v\ge\text{greater_y}). Combining this with the segment-count requirement gives

[
v=\max(y_{\text{req}},\text{greater_y}).
]

The candidate cost is (h+v).

1. Update the answer with the minimum candidate. After evaluating the group, incorporate its (Y)-coordinates into `greater_y` before moving to the next smaller (X).

### Why it works

For any valid drawing, let (h) be its longest horizontal length and (v) its longest vertical length. Every point with (X>h) must be vertical, and every point with (Y>v) must be horizontal. Thus (h) must satisfy the (V)-limit and (v) must satisfy the (H)-limit. Also, no point with (X>h) can have (Y>v), because such a point would be forced to use both orientations. Consequently, for a fixed (h), every valid solution has cost at least (h+\max(y_{\text{req}},\max_{X_i>h}Y_i)).

The sweep evaluates exactly this lower bound for every possible (h). Conversely, for every evaluated (h), choosing that minimum (v) makes the forced horizontal and vertical sets disjoint and gives enough capacity. Assigning any remaining horizontal points in decreasing (Y)-order prevents crossings among flexible points. Hence every candidate evaluated by the sweep corresponds to a valid drawing, and the minimum candidate is exactly the optimum.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve_case(n, H, V, xdata, ydata):
    x1, x2, ax, bx, cx, dx = xdata
    y1, y2, ay, by, cy, dy = ydata

    if H + V < n:
        return -1

    points = [(x1, y1), (x2, y2)]
    ys = [y1, y2]

    max_x = max(x1, x2)
    max_y = max(y1, y2)

    px2, px1 = x1, x2
    py2, py1 = y1, y2

    for _ in range(2, n):
        nx = ((ax * px2 + bx * px1 + cx) % dx) + 1
        ny = ((ay * py2 + by * py1 + cy) % dy) + 1

        points.append((nx, ny))
        ys.append(ny)

        if nx > max_x:
            max_x = nx
        if ny > max_y:
            max_y = ny

        px2, px1 = px1, nx
        py2, py1 = py1, ny

    ans = 10**30

    # Using no horizontal segments.
    if V >= n:
        ans = min(ans, max_y)

    # Using no vertical segments.
    if H >= n:
        ans = min(ans, max_x)

    # If no horizontal segment is allowed, the all-vertical
    # candidate above is the only possible orientation.
    if H == 0:
        return ans

    ys.sort(reverse=True)
    y_req = ys[H] if H < n else 0

    points.sort(key=lambda p: p[0], reverse=True)
    x_req = points[V][0] if V < n else 0

    greater_y = 0
    i = 0

    while i < n:
        x = points[i][0]
        j = i
        group_y = 0

        while j < n and points[j][0] == x:
            if points[j][1] > group_y:
                group_y = points[j][1]
            j += 1

        if x >= x_req:
            v_cost = max(y_req, greater_y)
            candidate = x + v_cost
            if candidate < ans:
                ans = candidate

        if group_y > greater_y:
            greater_y = group_y

        i = j

    return ans

def main():
    T = int(input())
    out = []

    for case_id in range(1, T + 1):
        n, H, V = map(int, input().split())
        xdata = list(map(int, input().split()))
        ydata = list(map(int, input().split()))

        ans = solve_case(n, H, V, xdata, ydata)
        out.append(f"Case #{case_id}: {ans}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    main()
```

The first two points are inserted directly because the recurrence starts at the third point. The variables `px2` and `px1` always represent (X_{i-1}) and (X_i) before generating the next value, and the same invariant is maintained for the (Y)-sequence.

The recurrence uses the multiplication before the modulo, exactly as specified. Python's arbitrary-precision integers avoid the overflow that would occur in a fixed-width 32-bit implementation.

The initial `ans` handles cases where one orientation is unused. This matters even when both limits are positive. In the first sample, all points can be vertical, so the optimal horizontal cost is zero.

The (Y)-array is sorted in decreasing order so that `ys[H]` is the ((H+1))-st largest value. When (H=N), there is no such element, and zero is the correct threshold because all points may be horizontal.

The points are sorted by decreasing (X). During the sweep, the current equal-(X) group is not inserted into `greater_y` until after its candidate has been evaluated. Consequently, `greater_y` contains exactly the points satisfying (X_i>x), not (X_i\ge x). This is the most delicate boundary condition in the implementation.

## Worked Examples

### Sample 1

The first sample has (N=2), (H=2), and (V=2), with points ((6,2)) and ((3,4)).

Since (V=N), the all-vertical solution is immediately a candidate with cost (4). Since (H=N), the all-horizontal solution costs (6).

For the mixed sweep, (x_{\text{req}}=0) and (y_{\text{req}}=0).

| Current (x) | Points at this (x) | `greater_y` before group | (v=\max(y_{\text{req}},greater_y)) | Candidate |
| --- | --- | --- | --- | --- |
| 6 | ((6,2)) | 0 | 0 | 6 |
| 3 | ((3,4)) | 2 | 2 | 5 |

The initial all-vertical candidate is already (4), so the final answer is `Case #1: 4`.

The sweep demonstrates why the zero-cost orientation must be considered separately. A threshold (h=0) represents using no horizontal segments, and that threshold is not an (X)-coordinate of any point.

### Sample 2

The second sample has (N=2), (H=2), (V=1), again with points ((6,2)) and ((3,4)).

Here (H=N), so (y_{\text{req}}=0). Since only one vertical segment is allowed, (x_{\text{req}}) is the second largest (X), namely (3).

The all-horizontal candidate costs (6).

| Current (x) | Points at this (x) | `greater_y` before group | (v) | Candidate |
| --- | --- | --- | --- | --- |
| 6 | ((6,2)) | 0 | 0 | 6 |
| 3 | ((3,4)) | 2 | 2 | 5 |

At (h=3), the point with (X=6) is forced vertical. Its (Y)-coordinate is (2), so the vertical cost must be at least (2). The other point is horizontal with length (3), giving total cost (3+2=5).

The result is `Case #2: 5`. This trace also shows why the sweep uses points with strictly greater (X): the point at (X=3) itself does not contribute to `greater_y`.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | (O(N\log N)) | Generating points takes (O(N)), sorting (Y)-coordinates takes (O(N\log N)), sorting points takes (O(N\log N)), and the sweep takes (O(N)). |
| Space | (O(N)) | The generated points and the (Y)-coordinate array both contain (N) values. |

For (N=800,000), the linear generation and sweep are inexpensive compared with the two sorting operations. The algorithm never constructs pairs of points, so it avoids the quadratic memory and time that the geometric definition might initially suggest.

## Edge Cases

When (H+V<N), the algorithm returns (-1) before generating the coordinates. For the input

```
1
3 1 1
1 2 0 1 0 3
1 2 0 1 0 3
```

the generated points are ((1,1),(2,2),(3,3)). Only two segments are permitted, while three are required. No geometric argument can overcome that capacity limit.

When all vertical segments are allowed, the horizontal threshold can be zero. For the first sample with (V=N=2), the algorithm initializes `ans` with the maximum (Y), which is (4). The later sweep only finds costs (6) and (5), so the answer remains (4). This handles the otherwise missing (h=0) candidate.

When coordinates are equal, the sweep processes an entire equal-(X) group before updating `greater_y`. For the points ((2,1),(2,2),(2,3)), a candidate with (h=2) sees no point with (X>2), even though there are points with (X=2). That is correct because an intersection at the shared (X)-coordinate is an endpoint intersection and is allowed.

For the endpoint case with points ((1,1)) and ((2,2)), choosing the first point horizontally and the second vertically produces an intersection at ((2,1)), the endpoint of the horizontal segment. The crossing condition requires both (X_{\text{vertical}}<X_{\text{horizontal}}) and (Y_{\text{horizontal}}<Y_{\text{vertical}}), and the first inequality is false. The algorithm consequently accepts the configuration and obtains cost (1+2=3).

For the maximum-size recurrence test, (X_i=Y_i=i) for (1\le i\le800000). With (H=V=400000), the required thresholds are both (400000). Choosing (h=400000) forces the remaining (400000) points to be vertical, whose largest (Y) is (800000), giving cost (1,200,000), but choosing the balanced threshold where the sweep accounts for the upper-right points gives the optimal value (800000). The test exercises the recurrence, strict threshold handling, equal-free sorting, and integer sizes at the upper constraint.
