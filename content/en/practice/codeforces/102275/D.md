## Solution
## Problem Understanding

Percy starts at position 0 on a number line. Every object has a position, a hardness, and a type. A clam can be picked up when Percy visits its position. A rock can break every currently carried clam whose hardness is strictly smaller than the rock's hardness.

The movement itself is the only thing that costs time. Percy may pass an object many times, and revisiting a rock is useful because a rock can break clams that were picked up after the rock's earlier visit. The task is to find the minimum total swimming distance needed to eat every clam, or report `-1` if some clam can never be broken.

The positions and hardnesses are generated by two second order recurrences, so we first have to construct the actual objects. The recurrence values can exceed 32 bit ranges during multiplication, which is harmless in Python because integers have arbitrary precision.

With up to 800,000 objects in one test case, an algorithm that compares every clam with every rock is already too slow. A quadratic algorithm would perform roughly 6.4 × 10^11 comparisons in the worst case. The intended solution needs to be close to linear or O(N log N), including the sorting required because the generated objects are not given in positional order.

The first subtle case is strict hardness. Consider

```
2
1 2 0 0 0 10
5 5 0 0 0 10
CR
```

The clam and rock both have hardness 5, so the rock cannot break the clam. The answer is `-1`. A solution using `>=` instead of `>` would incorrectly report a finite answer.

The second subtle case is that the globally hardest rock need not be useful enough to give the shortest route. For example,

```
3
9 10 0 0 99 100
6 5 0 0 5 10
RCR
```

The objects are a hardness 6 rock at 9, a hardness 5 clam at 10, and a hardness 6 rock at 100. Percy can swim to 10, return one unit to the rock at 9, and finish there, taking 11 seconds. Going all the way to position 100 would be much worse. A solution that always chooses the hardest rock globally misses this possibility.

The third subtle case is that a rock visited before a clam does not break that clam merely because Percy later passes the clam. In

```
4
10 50 0 1 40 80
50 10 0 1 38 80
RRCC
```

the objects are a hardness 50 rock at 10, a hardness 10 rock at 50, a hardness 49 clam at 11, and a hardness 8 clam at 52. An optimal route is

```
0 -> 11 -> 10 -> 50 -> 52 -> 50
```

with cost 56. The first clam is broken at position 10, while the second is broken at position 50 after it has been picked up. A careless approach that simply visits every object once would fail because the second clam is picked up after the rock at 50 was first visited.

Finally, the generated positions are not sorted and may be very large. Sorting by position before doing any geometric reasoning is mandatory. Using the generation index as the spatial order produces incorrect precedence relations.

## Approaches

A direct brute force solution can try every possible rock for every clam. For a clam at position `p` and hardness `h`, we could examine every rock, check whether its hardness is greater than `h`, and then try to reason about the resulting route. Even merely finding a possible crusher for every clam takes O(N²) in the worst case. With 800,000 objects, this is completely infeasible.

A more useful brute force would enumerate the rocks that Percy uses to actually break clams and then find the shortest route for that choice. That is still exponential, because each clam can potentially choose a rock on either side and several clams may share a rock.

The key observation is that Percy always discovers new positions from left to right. All positions are positive, so the first time he reaches a new maximum position, every object at a smaller position has already been visited. The complicated part is only the revisiting of rocks.

Consider the rocks at which Percy actually breaks clams. We can normalize an optimal solution so that these service rocks occur in increasing positional order. Suppose two consecutive service rocks appear in decreasing positional order. Let their hardnesses be `a` and `b`. If `a >= b`, the first rock can also break every clam that the second rock breaks. If `b > a`, the second rock can also break every clam that the first rock breaks. In either case one of the two service events is unnecessary. Repeating this removes all decreases.

Now take two consecutive service rocks at positions `L < R`. Every clam between them can be broken either by `L`, after Percy returns to it, or by `R`, while Percy is moving right. There is no need for a non-adjacent service rock. If a clam required an earlier rock instead of `L`, then that earlier rock was harder than `L`, and it could replace `L` for the clams previously served by `L` as well. The same argument applies to a later rock.

This turns the movement problem into a dynamic programming problem over rocks in increasing position order.

Suppose the previous service rock is `L` and the new service rock is `R`. If every clam in `(L,R)` has hardness smaller than `H_R`, Percy simply moves from `L` to `R`, costing `R-L`.

Otherwise, some clams are too hard for `R`. Since `L` must be able to serve them, every clam in `(L,R)` must have hardness smaller than `H_L`. Let `q` be the rightmost clam in `(L,R)` whose hardness is at least `H_R`. Percy can travel from `L` to `q`, return to `L` to break all clams that only `L` can break, and then continue to `R`. The cost is

`(q-L) + (q-L) + (R-q) = R + 2q - 3L`.

There is a particularly useful way to recognize whether a previous rock `L` can perform this second type of transition. Let `bad[L]` be the first clam strictly to the right of `L` whose hardness is at least `H_L`. Then `L` can handle the entire interval up to a new rock `R` exactly when `R < bad[L]`.

This gives a recurrence with two kinds of candidate values. For a normal transition we need

`dp[L] - L`.

For a transition involving a return to `L`, we need

`dp[L] - 3L`.

The first value never expires. The second value is usable only while `R < bad[L]`. A Fenwick tree handles suffix minima for the first kind, while a segment tree plus an expiry heap handles prefix minima for the second kind.

The remaining geometric query is the rightmost clam before `R` whose hardness is at least `H_R`. This is exactly a monotonic stack query. The same type of stack, scanned from right to left, computes `bad[L]`.

The resulting approach is O(N log N), dominated by sorting and the range minimum data structures.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(N²) | O(N) | Too slow |
| Optimal | O(N log N) | O(N) | Accepted |

## Algorithm Walkthrough

1. Generate all positions and hardnesses from the two recurrences. Store each object as `(position, hardness, type)` and sort the objects by position. The positional order is the order in which Percy first encounters the objects.
2. Scan the sorted objects from right to left with a monotonic stack containing clam positions and hardnesses. For every rock, remove stack entries with hardness smaller than the rock. The remaining top is the nearest clam to the right whose hardness is at least the rock's hardness. Store its position as `bad[L]`. If the stack becomes empty, `bad[L]` is infinity.
3. During the same right-to-left scan, maintain the maximum hardness of all clams to the right of each rock. A rock is a possible final service rock exactly when this maximum is strictly smaller than its hardness. Store that condition for the final answer.
4. Scan the sorted objects from left to right with another monotonic stack of clams. When a rock of hardness `H_R` is encountered, pop clams with hardness smaller than `H_R`. The top after these pops is the nearest clam to the left with hardness at least `H_R`. Call its position `q`. If no such clam exists, set `q = 0`.
5. Process the rocks in increasing position order with dynamic programming. Let `dp[R]` be the minimum swimming distance needed to reach rock `R` after all clams before `R` have already been eaten.
6. If `q = 0`, the virtual starting point at position 0 can transition directly to `R`, because every clam before `R` is easier than `R`. This gives candidate cost `R`.
7. For a real previous rock `L` with `L >= q`, there is no clam in `(L,R)` whose hardness reaches `H_R`. Rock `R` can break every clam in that interval while Percy moves right. The transition is `dp[L] + R-L`, so the data structure stores `dp[L]-L`.
8. For a real previous rock `L < q`, the clam at `q` and every other clam between `L` and `R` must be handled by `L`, because `R` cannot break the clam at `q`. This transition is valid only while `R < bad[L]`. Its cost is `dp[L] + R + 2q - 3L`, so the data structure stores `dp[L]-3L`.
9. Query the minimum normal-transition value among previous rocks at positions at least `q`, and the minimum return-transition value among previous rocks at positions below `q`. Combine them with the current position and `q` to obtain `dp[R]`.
10. Insert the new rock into both data structures. Its normal-transition value is always available. Its return-transition value is inserted only if `bad[R]` is strictly greater than the current position, and it is removed once the sweep reaches `bad[R]`.
11. After all rocks have been processed, choose the last service rock `L`. If every clam to its right has hardness smaller than `H_L`, Percy can finish by moving to the rightmost clam and returning to `L`. This costs `2(Cmax-L)` when `L < Cmax`, and zero when the last clam is already at or to the left of `L`. Take the minimum over all valid final rocks.

### Why it works

The invariant is that after processing a rock `R`, `dp[R]` is the minimum cost among all normalized routes whose latest service rock is `R` and whose first visits have reached `R`. Between two consecutive service rocks `L<R`, every clam is handled either by `R` on the rightward movement or by `L` during one return excursion. If `R` handles everything, the cost is `R-L`. Otherwise `q` is the rightmost clam that `R` cannot handle, and `L` must handle the entire interval, giving the exact cost `R+2q-3L`. The condition `R<bad[L]` is precisely the condition that `L` is harder than every clam in the interval. Since every normalized optimal route can be represented as such increasing service rocks, the DP considers every optimal possibility and no invalid transition is accepted.

## Python Solution

```python
import sys
import heapq
from bisect import bisect_left

input = sys.stdin.readline

INF = 10**30

def solve():
    T = int(input())
    out = []

    for tc in range(1, T + 1):
        n = int(input())

        p1, p2, ap, bp, cp, dp_mod = map(int, input().split())
        h1, h2, ah, bh, ch, dh_mod = map(int, input().split())
        ops = input().strip()

        objects = [(p1, h1, ops[0] == 'C'),
                   (p2, h2, ops[1] == 'C')]

        pp, p = p1, p2
        hh, h = h1, h2

        for i in range(2, n):
            np = ((ap * pp + bp * p + cp) % dp_mod) + 1
            nh = ((ah * hh + bh * h + ch) % dh_mod) + 1
            objects.append((np, nh, ops[i] == 'C'))
            pp, p = p, np
            hh, h = h, nh

        objects.sort()

        # For every rock, compute:
        # bad = first clam to the right with hardness >= rock hardness
        # final_ok = every clam to the right is strictly easier
        rock_rev = []
        stack = []
        suffix_max_clam = -1

        for pos, hard, is_clam in reversed(objects):
            if is_clam:
                stack.append((pos, hard))
                if hard > suffix_max_clam:
                    suffix_max_clam = hard
            else:
                while stack and stack[-1][1] < hard:
                    stack.pop()

                bad = stack[-1][0] if stack else INF
                final_ok = suffix_max_clam < hard
                rock_rev.append((pos, hard, bad, final_ok))

        rock_rev.reverse()
        rocks = rock_rev
        m = len(rocks)

        if m == 0:
            out.append(f"Case #{tc}: -1")
            continue

        # q[i] = nearest clam to the left of rock i
        # whose hardness is >= hardness of rock i.
        q = []
        stack = []

        for pos, hard, is_clam in objects:
            if is_clam:
                stack.append((pos, hard))
            else:
                while stack and stack[-1][1] < hard:
                    stack.pop()
                q.append(stack[-1][0] if stack else 0)

        positions = [r[0] for r in rocks]
        max_clam_pos = -1

        for pos, hard, is_clam in objects:
            if is_clam:
                max_clam_pos = pos

        # Fenwick tree for minimum dp[L] - pos[L].
        # Indexes are reversed so a suffix in position order becomes
        # a prefix query in the Fenwick tree.
        bit = [INF] * (m + 1)

        def bit_update(idx, value):
            while idx <= m:
                if value < bit[idx]:
                    bit[idx] = value
                idx += idx & -idx

        def bit_query(k):
            res = INF
            while k > 0:
                if bit[k] < res:
                    res = bit[k]
                k -= k & -k
            return res

        # Segment tree for minimum dp[L] - 3*pos[L] among active
        # return-transition candidates.
        size = 1
        while size < m:
            size <<= 1

        seg = [INF] * (2 * size)

        def seg_set(idx, value):
            p = idx + size
            seg[p] = value
            p >>= 1
            while p:
                nv = seg[p << 1]
                rv = seg[p << 1 | 1]
                seg[p] = nv if nv < rv else rv
                p >>= 1

        def seg_query(k):
            # Minimum over indexes [0, k).
            if k <= 0:
                return INF

            left = size
            right = size + k
            res = INF

            while left < right:
                if left & 1:
                    if seg[left] < res:
                        res = seg[left]
                    left += 1
                if right & 1:
                    right -= 1
                    if seg[right] < res:
                        res = seg[right]
                left >>= 1
                right >>= 1

            return res

        # (expiry_position, rock_index)
        expiry = []

        dp_values = [INF] * m
        answer = INF

        for i in range(m):
            pos, hard, bad, final_ok = rocks[i]
            qi = q[i]

            # Return-transition candidates with bad <= pos are no longer valid.
            while expiry and expiry[0][0] <= pos:
                _, idx = heapq.heappop(expiry)
                seg_set(idx, INF)

            if qi == 0:
                best = pos
            else:
                k = bisect_left(positions, qi)
                best = pos + bit_query(m - k)

                # Previous rocks strictly to the left of q.
                left_best = seg_query(k)
                if left_best < INF:
                    candidate = pos + 2 * qi + left_best
                    if candidate < best:
                        best = candidate

            dp_values[i] = best

            # Insert current rock as a future previous service rock.
            rev_index = m - i
            bit_update(rev_index, best - pos)

            if bad > pos:
                seg_set(i, best - 3 * pos)
                heapq.heappush(expiry, (bad, i))

            # Can this rock be the last service rock?
            if final_ok:
                if pos >= max_clam_pos:
                    candidate = best
                else:
                    candidate = best + 2 * (max_clam_pos - pos)

                if candidate < answer:
                    answer = candidate

        if answer >= INF:
            answer = -1

        out.append(f"Case #{tc}: {answer}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The first part of the implementation constructs the generated arrays while keeping only the previous two recurrence values. Python's arbitrary precision integers handle the large intermediate products directly.

After sorting, the reverse scan computes `bad` and the condition for being a final service rock. The monotonic stack contains only clams. Popping while the stack top is too soft leaves the nearest clam whose hardness is large enough to defeat the current rock.

The forward scan performs the symmetric query for `q`. The two scans are separate because one asks for the nearest qualifying clam on the right and the other asks for the nearest qualifying clam on the left.

The Fenwick tree stores `dp[L] - P_L`. Its indexes are reversed, because the recurrence needs a suffix minimum over rocks with `P_L >= q`. The Fenwick tree only receives decreasing minimum updates, so no deletion is needed there.

The segment tree stores `dp[L] - 3P_L`. These candidates are temporary. Once the sweep reaches `bad[L]`, rock `L` can no longer handle every clam in a gap ending at the current rock, so the candidate is removed. The heap tells us exactly when each candidate expires.

The strict comparisons are deliberate. A rock of hardness `h` can break only clams with hardness strictly below `h`, so a clam with hardness equal to `h` belongs to the blocked set and causes a `bad` event.

The final calculation also uses strict inequality. A last service rock of hardness `h` is valid only if every remaining clam has hardness less than `h`.

## Worked Examples

### Sample 1

The objects are a clam at position 5 with hardness 30 and a rock at position 10 with hardness 31.

| Position | Type | Hardness | `q` | `dp` | Action |
| --- | --- | --- | --- | --- | --- |
| 5 | C | 30 |  |  | Pick up the clam |
| 10 | R | 31 | 0 | 10 | Rock handles the clam while moving right |

The rock at 10 has no qualifying clam to its left, because the clam hardness 30 is smaller than 31. The virtual starting point can transition directly to it, giving `dp = 10`. There are no clams after the rock, so it is also a valid final service rock. The answer is `10`.

### Sample 2

Now the rock is at position 5 with hardness 31 and the clam is at position 10 with hardness 30.

| Position | Type | Hardness | `q` | `dp` | Action |
| --- | --- | --- | --- | --- | --- |
| 5 | R | 31 | 0 | 5 | Reach the rock |
| 10 | C | 30 |  |  | Pick up the clam |
| 5 | R | 31 |  |  | Return and break the clam |

The rock at 5 becomes the final service rock. Its hardness exceeds the clam's hardness, so after reaching the clam at 10 Percy returns from 10 to 5. The additional final distance is `2(10-5) = 10`, giving `5 + 10 = 15`.

The trace demonstrates why the final service transition is different from an ordinary transition. Percy does not need to return again after the last service, so only one return trip is needed from the farthest remaining clam to the final rock.

### Sample 4

The objects are

| Position | Type | Hardness |
| --- | --- | --- |
| 10 | R | 50 |
| 11 | C | 49 |
| 50 | R | 10 |
| 52 | C | 8 |

For rock 10, there is no harder-or-equal clam to its right, because the clam at 11 has hardness 49. The first rock can be reached directly with cost 10.

For rock 50, the nearest clam on its left with hardness at least 10 is the clam at 11, so `q = 11`. The previous rock at 10 is to the left of `q`, and its hardness 50 exceeds every clam between positions 10 and 50. The return transition costs

`50 + 2*11 + (dp[10] - 3*10) = 50 + 22 + 10 - 30 = 52`.

This corresponds to

```
0 -> 11 -> 10 -> 50
```

with cost 52. The remaining clam at 52 has hardness 8, which the rock at 50 can break. Since this is the final service rock, Percy returns from 52 to 50, adding 4. The final answer is 56.

This example demonstrates why the DP needs both transition forms. A simple shortest path through the rocks would not capture the fact that the clam at 11 must be picked up before returning to rock 10.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | O(N log N) | Sorting costs O(N log N), while the monotonic stacks, Fenwick tree, segment tree, and expiry heap perform O(N log N) total work |
| Space | O(N) | The sorted objects, rock information, stacks, DP values, and data structures all use linear memory |

The dominant operation is sorting the generated objects by position. After that, every object enters and leaves each monotonic stack at most once, and every rock causes only a constant number of logarithmic data structure operations. With 800,000 objects, this is the appropriate scale for the given constraints, while the quadratic alternatives are far beyond the available operation budget.

## Edge Cases

For equal hardness, the monotonic stacks deliberately keep clams whose hardness is equal to the current rock. In the input

```
2
1 2 0 0 0 10
5 5 0 0 0 10
CR
```

the rock's hardness is not strictly greater than the clam's hardness. The rock cannot serve the clam, `final_ok` is false, and no other rock exists, so the answer is `-1`.

For a nearby left rock versus a distant right rock, consider

```
3
9 10 0 0 99 100
6 5 0 0 5 10
RCR
```

The generated positions are 9, 10, and 100. The rock at 9 has hardness 6 and the clam at 10 has hardness 5. The DP can use the virtual start to reach rock 9, then the final transition returns from the clam at 10 to rock 9. Its cost is `9 + 2(10-9) = 11`. The distant rock at 100 is irrelevant to the optimum.

For a rock visited before a later clam, the final transition explicitly accounts for the return. In the sample fourth case, rock 50 has already been reached before Percy picks up the clam at 52, so the clam cannot be considered eaten at that first visit. The final calculation adds `2(52-50)=4`, producing the total answer 56 after the earlier service at rock 10.

For a large generated value, the recurrence is evaluated with Python integers before applying the modulus. The code never converts intermediate products to 32 bit values. The sorting step then establishes the actual spatial order independently of the order in which the recurrence generated the objects.

For a rock with no sufficiently hard clam to its right, `bad` becomes infinity. Its return-transition candidate never expires, because it remains capable of handling every later interval. Conversely, if `bad[L]` is a real clam position, the candidate is removed as soon as the sweep reaches that position, matching the strict requirement that every clam in the interval must have hardness below `H_L`.

The final service rock is handled separately from ordinary transitions because Percy does not need to return to the right after the last clam has been eaten. If the final rock is at `L` and the farthest remaining clam is at `C`, the required distance is `2(C-L)`, not `2(C-L)+(C-L)`. This distinction is what gives the sample's final cost of 56 rather than a larger value.
