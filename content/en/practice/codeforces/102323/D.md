## Solution
## Problem Understanding

We have several trips to Fujiyama Sushi. On each trip there are `c` cars, and every car carries exactly four people, so there are `4c` family members in total. Each car has its own arrival time, measured from the beginning of the trip. Each person has an eating time. A person can start eating as soon as their car arrives, so if a person with eating time `t` rides in a car arriving at time `d`, that person finishes at time `d + t`.

The family wants to leave only after everyone has finished eating. We can freely assign people to cars, and the goal is to choose the assignment that minimizes the finishing time of the last person. The original problem allows up to 50 cars, with arrival times at most 45 minutes and eating times at most 75 minutes. There can be fewer than 100 trips in one input.

The useful constraint is the number of people, which is only `4c <= 200`. That is small enough that sorting is trivial, but it does not make arbitrary assignment feasible. If we tried every possible assignment of 200 people to 50 labeled cars while keeping exactly four people in each car, the number of assignments would be

`200! / (4!)^50`

which is roughly `7.7 × 10^305`. Even checking one assignment in linear time would be hopeless. The intended solution must exploit the ordering of arrival and eating times rather than enumerate assignments.

Three edge cases are particularly useful for catching incorrect implementations.

First, the input does not promise that cars are listed in arrival order. Consider

```
1
2
20 10
9 8 6 5 4 3 2 1
```

The correct output is

```
Trip #1: 24
```

The fastest car arrives at 10 and should receive the four slowest-to-finish? More precisely, it should receive the four largest eating times, `9, 8, 6, 5`, giving finishing times `19, 18, 16, 15`. The other car gets `4, 3, 2, 1`, giving a maximum of `24`. An implementation that simply pairs values in their input order can produce a larger answer.

Second, several values can be equal. For example,

```
1
2
5 5
7 7 7 7 7 7 7 7
```

has answer

```
Trip #1: 12
```

Every possible assignment is equivalent, so the algorithm must not depend on distinct values.

Third, every car receives exactly four people. With

```
1
2
1 45
75 73 72 71 4 3 2 1
```

the answer is

```
Trip #1: 76
```

The first car gets `75, 73, 72, 71`, producing a maximum of `76`, while the second car gets `4, 3, 2, 1`, producing `49`. An implementation that groups the sorted people incorrectly, especially around an index such as `4*i`, can assign the fifth person to the wrong car and get the wrong result.

## Approaches

A direct brute-force approach would try every valid way to partition the `4c` people into `c` groups of four, assign each group to a car, calculate all `arrival + eating` values, and keep the smallest maximum. This is correct because every possible assignment is explicitly considered. The problem is the number of assignments. At the maximum `c = 50`, there are exactly `200!/(4!)^50`, approximately `7.7 × 10^305`, possible assignments. The search becomes impossible long before the input reaches that size.

The brute force works because each person's finishing time depends only on the car they occupy and their own eating time. That same structure gives us the greedy solution. Suppose one car arrives earlier than another. Giving a slower eater to the earlier car is never worse than giving that slower eater to the later car while putting a faster eater in the earlier car. The earlier arrival time is the scarce resource, so the largest eating times should consume the earliest arrival slots.

There is one extra detail because each car holds four people. We cannot simply match one eating time to one arrival time. Instead, after sorting the cars by arrival time, the first car receives the four largest eating times, the second car receives the next four largest, and so on.

Equivalently, sort arrival times increasingly and eating times decreasingly. For the car at position `i`, its four assigned people are positions `4i` through `4i + 3` in the descending eating-time order. The answer is the largest value among `arrival[i] + eating_time`.

Why does this grouping work? Consider two cars where `a <= b`, and suppose a person with eating time `x` is on the earlier car while a person with eating time `y` is on the later car, with `x < y`. Swapping the two people changes their completion times from `a+x` and `b+y` to `a+y` and `b+x`. The larger eating time has moved to the earlier car. The maximum cannot increase because `a+y <= b+y`, while the other completion time becomes `b+x <= b+y`. Repeatedly applying this exchange removes every inversion, leaving the largest eating times on the earliest cars. Since each car needs exactly four people, the sorted order naturally forms groups of four.

The resulting approach needs only sorting, followed by a linear scan.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O((4c)!/(4!)^c × c) | O(c) | Too slow |
| Optimal | O(c log c) | O(c) | Accepted |

## Algorithm Walkthrough

1. Read the number of cars and the `c` arrival times. There are exactly `4c` eating times in the next line.
2. Sort the car arrival times in increasing order. The earliest-arriving car should receive the largest eating times because its early arrival gives those slow eaters the most time to finish.
3. Sort all `4c` eating times in decreasing order. The beginning of this array contains the people whose eating takes the longest.
4. Process the sorted people four at a time. For car `i`, use eating times at indices `4i`, `4i + 1`, `4i + 2`, and `4i + 3`. These are the four largest remaining eating times, so this car gets exactly its appropriate group.
5. For each of those four people, compute `arrival[i] + eating_time`. This is their actual finishing time because they begin eating when their car arrives.
6. Keep the maximum finishing time over all people. The family cannot leave before this value, and the greedy assignment minimizes it.

### Why it works

After sorting the cars as `a1 <= a2 <= ... <= ac`, the optimal assignment can be assumed to have every larger eating time assigned to an earlier car whenever possible. If a larger eating time is on a later car while a smaller eating time is on an earlier car, exchanging those two people cannot increase the maximum finishing time. Repeating this exchange eliminates all such inversions. Because every car has capacity exactly four, the resulting sorted arrangement puts the largest four eating times in the first car, the next four in the second, and so forth. The algorithm constructs precisely this inversion-free assignment, so its maximum finishing time is minimal.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    trips = int(input())
    out = []

    for case in range(1, trips + 1):
        c = int(input())
        cars = list(map(int, input().split()))
        people = list(map(int, input().split()))

        cars.sort()
        people.sort(reverse=True)

        best = 0

        for i in range(c):
            arrival = cars[i]
            start = 4 * i

            for j in range(start, start + 4):
                best = max(best, arrival + people[j])

        out.append(f"Trip #{case}: {best}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The outer loop processes one trip at a time. The input contains the number of trips first, so each iteration reads one car count, one array of arrival times, and one array containing exactly four times as many eating times.

The two `sort` calls implement the greedy ordering. `cars.sort()` gives increasing arrival times, while `people.sort(reverse=True)` puts the slowest eaters first.

For car `i`, the first assigned person has index `4 * i`. The next three indices are `4 * i + 1`, `4 * i + 2`, and `4 * i + 3`. Using `start + 4` as the exclusive boundary makes each group contain exactly four people and prevents an off-by-one error at the boundary between cars.

The expression `arrival + people[j]` is the completion time for that person. We only need the maximum because the family leaves when the last person finishes.

Python integers have arbitrary precision, although the given limits make every result tiny anyway. No special overflow handling is needed.

The output format includes the trip number followed by the minimum finishing time, matching the required `Trip #d: value` format.
