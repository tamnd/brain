## Solution
## Problem Understanding

The problem gives a polynomial in factored form

[
P(X)=(X+a_1)(X+a_2)\cdots(X+a_n),
]

where (1\le n\le 9) and every (a_i) is an integer from (-10) to (10). We need to expand it and print the resulting polynomial in the required compact notation. The official problem is Codeforces 100F, “Polynom”, a special implementation problem with a 2 second limit and 64 MB of memory.

For example,

[
(X-1)(X+1)=X^2-1,
]

so the output is `X^2-1`. If

[
(X+1)(X+1)=X^2+2X+1,
]

the compact output is `X^2+2*X+1`. The statement describes every term conceptually as `C*X^K`, but unnecessary parts are omitted. Thus coefficient (1) is not printed, exponent (1) is not printed, and a constant term does not contain `*X^0`. Zero terms are omitted entirely.

The small bound (n\le9) means even a fairly direct implementation is fast enough. The coefficients themselves are also tiny enough for ordinary Python integers, although Python would handle much larger integers safely anyway. Since the degree is at most 9, we never need sophisticated polynomial algorithms. The useful target is simply (O(n^2)), which is effectively constant for these constraints.

There are several formatting cases where an otherwise correct polynomial expansion can produce the wrong answer. For input

```
1
0
```

the polynomial is (X), so the correct output is `X`, not `1*X^1`. The latter represents the same mathematical value but is not the required shortest representation.

For

```
1
-5
```

the polynomial is (X-5), so the output is `X-5`. A formatter that treats every coefficient uniformly might incorrectly produce `X+-5`.

For

```
2
0
0
```

the polynomial is (X^2), so the output is `X^2`. Both lower-degree coefficients are zero and must disappear. A careless implementation might print `X^2+0*X+0`.

Finally, for

```
2
-1
1
```

the middle coefficient is zero, giving `X^2-1`. This catches the common mistake of printing a plus sign before a negative coefficient or retaining the zero middle term. The official samples include this exact case.

## Approaches

A brute-force way to obtain each coefficient is to use the definition of polynomial multiplication directly. For every subset of the (n) factors, choose either the (X) part or the (a_i) part. A subset of size (k) contributes to the coefficient of (X^{n-k}), with value equal to the product of the selected (a_i)'s. Enumerating all (2^n) subsets and processing up to (n) elements per subset costs (O(n2^n)). At the maximum stated (n=9), this is only (9\cdot512=4608) elementary selections, so it is actually fast enough for the original constraints. The problem is that the method scales exponentially, becoming about (30\cdot2^{30}), more than 32 billion operations, at (n=30).

The better observation is that polynomial multiplication already gives exactly the information we need without considering every subset separately. Start with the polynomial (1). When processing a factor (X+a_i), multiply the current polynomial by this linear polynomial. If the current coefficient array is (c), then the new coefficient at degree (j) receives two contributions: (c_j) from choosing (X), and (a_i c_{j-1}) from choosing (a_i). Each multiplication takes (O(k)) when the current degree is (k), so processing all (n) factors costs (O(n^2)).

The brute force works because every coefficient is ultimately a sum of products obtained by choosing one term from every factor, but it repeatedly reconstructs combinations that ordinary polynomial multiplication aggregates immediately. The observation that each new factor has only two terms lets us update all coefficients in one pass.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | (O(n2^n)) | (O(n)) | Accepted for (n\le9), poor scalability |
| Optimal | (O(n^2)) | (O(n)) | Accepted |

## Algorithm Walkthrough

1. Read (n) and the (n) values (a_i). Represent the current polynomial by an array `coef`, where `coef[j]` is the coefficient of (X^j). Initially the polynomial is (1), so `coef = [1]`.
2. Process every factor (X+a_i). Suppose the current polynomial has degree (k). Create a new array of length (k+2), because multiplication by a linear factor increases the degree by one.
3. For every existing coefficient `coef[j]`, add it to `new[j + 1]`. This corresponds to taking the (X) part of (X+a_i), which increases the degree by one.
4. For the same coefficient, add `coef[j] * a_i` to `new[j]`. This corresponds to taking the constant part (a_i), which leaves the degree unchanged.
5. Replace the current coefficient array by the newly computed one. After processing all factors, the array contains the coefficients of the complete polynomial, from the constant term at index zero to the leading coefficient at index (n).
6. Traverse the coefficients from degree (n) down to zero. Skip every coefficient equal to zero because its term contributes nothing to the polynomial.
7. For each nonzero coefficient, construct its shortest representation. For degree zero, print only the coefficient. For degree one, print `X` when the absolute coefficient is one, otherwise print `C*X`. For higher degrees, print `X^K` when the absolute coefficient is one, otherwise print `C*X^K`.
8. Add `+` before a positive non-leading term and `-` before a negative non-leading term. For a coefficient whose absolute value is one, do not print the numeric coefficient itself.

The key invariant is that after processing the first (i) factors, `coef[j]` is exactly the coefficient of (X^j) in

[
\prod_{k=1}^{i}(X+a_k).
]

Multiplying this polynomial by (X+a_{i+1}) creates exactly two contributions for every existing term, one shifted by one degree and one multiplied by (a_{i+1}). The update therefore computes precisely the coefficients of the polynomial with one additional factor. By induction, after the final factor every coefficient is correct.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    a = [int(input()) for _ in range(n)]

    # coef[j] is the coefficient of X^j.
    coef = [1]

    for value in a:
        new = [0] * (len(coef) + 1)

        for j, c in enumerate(coef):
            # Take X from (X + value).
            new[j + 1] += c

            # Take value from (X + value).
            new[j] += c * value

        coef = new

    terms = []

    for power in range(n, -1, -1):
        c = coef[power]

        if c == 0:
            continue

        if power == 0:
            body = str(abs(c))
        elif power == 1:
            if abs(c) == 1:
                body = "X"
            else:
                body = f"{abs(c)}*X"
        else:
            if abs(c) == 1:
                body = f"X^{power}"
            else:
                body = f"{abs(c)}*X^{power}"

        if not terms:
            if c < 0:
                terms.append("-" + body)
            else:
                terms.append(body)
        else:
            if c < 0:
                terms.append("-" + body)
            else:
                terms.append("+" + body)

    print("".join(terms))

if __name__ == "__main__":
    solve()
```

The coefficient array is initialized with `[1]` because the neutral element for polynomial multiplication is the constant polynomial (1). For each input value, `new[j + 1] += c` handles the (X) contribution and `new[j] += c * value` handles the constant contribution.

The representation is stored in increasing degree order, which makes the multiplication update especially simple. The final traversal goes in the opposite direction because standard polynomial notation prints the highest degree first.

The formatting code deliberately uses `abs(c)` for the body of a term. The sign is handled separately, which prevents outputs such as `X+-5`. The first term is also handled separately because it does not receive an explicit `+` sign.

Python integers have arbitrary precision, so there is no overflow issue. With (n\le9) and (|a_i|\le10), the coefficients are in fact very small anyway.

## Worked Examples

For Sample 1, the input is

```
2
-1
1
```

The factors are ((X-1)(X+1)).

| Factor processed | `coef` after multiplication |
| --- | --- |
| Initial | `[1]` |
| (X-1) | `[-1, 1]` |
| (X+1) | `[-1, 0, 1]` |

The final array means

[
-1+0X+X^2.
]

The zero middle coefficient is skipped, and the result is `X^2-1`. This demonstrates why zero terms must be removed during formatting.

For Sample 2, the input is

```
2
1
1
```

The factors are ((X+1)(X+1)).

| Factor processed | `coef` after multiplication |
| --- | --- |
| Initial | `[1]` |
| (X+1) | `[1, 1]` |
| (X+1) | `[1, 2, 1]` |

The coefficients represent

[
1+2X+X^2.
]

Traversing from degree two to zero gives `X^2+2*X+1`. This example exercises the normal positive-coefficient formatting and confirms that the coefficient of (X) is retained when it is nonzero.

| Space | (O(n)) | Only the current and next coefficient arrays are stored. |

The original constraint (n\le9) is tiny, so the quadratic algorithm uses only a few dozen arithmetic operations per test case. The 64 MB memory limit is nowhere near restrictive for an array of at most ten coefficients. The original Codeforces statement gives a 2 second time limit and 64 MB memory limit.

## Edge Cases

For the minimum-size input

```
1
0
```

the algorithm starts with `[1]`. Multiplying by (X+0) produces `[0, 1]`. The degree-one coefficient is one, so the formatter emits `X` rather than `1*X`. The constant coefficient is zero and disappears.

For

```
1
-10
```

the coefficient array becomes `[-10, 1]`. The degree-one term is the leading `X`, while the constant term is negative. Since it is the second term, the formatter adds `-` and then prints its absolute value, producing `X-10`.

For

```
2
0
0
```

the first multiplication gives `[0, 1]`, and the second gives `[0, 0, 1]`. Both lower-degree coefficients are zero, so the only surviving term is `X^2`. A formatter that prints every degree would incorrectly produce `X^2+0*X+0`.

For

```
2
-10
10
```

the first factor produces `[-10, 1]`. Multiplying by (X+10) gives `[−100, 0, 1]`. The middle coefficient cancels exactly, so the output is `X^2-100`. This catches both zero-term handling and sign handling.

The most subtle formatting case is a coefficient equal to (1) or (-1). For example,

```
2
-1
-1
```

gives

[
(X-1)^2=X^2-2X+1.
]

The degree-two coefficient is `1`, so it becomes `X^2`; the degree-one coefficient is `-2`, so it becomes `-2*X`; and the constant coefficient is `1`, so it becomes `+1`. The final output is `X^2-2*X+1`, with no unnecessary coefficient or exponent notation.
