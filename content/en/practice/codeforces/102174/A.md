## Solution
## Problem Understanding

这道题要求把简谱中的每个音符转换成 24 孔口琴对应的吹奏方式。输入给出音符数量 `n`，随后给出 `n` 个音符。每个音符由数字 `1` 到 `7` 表示基本音阶，数字后面的 `+` 表示升高一个八度，`-` 表示降低一个八度，连续出现两个符号则表示变化两个八度。特殊的 `0` 表示休止。

我们真正需要判断的不是音符处于哪个八度，而是它对应的口琴孔位属于吸气还是吹气。对于这张 24 孔口琴的音阶排列，同一个基本音阶在不同八度上的吹奏方式保持一致。因此，`5`、`5-` 和 `5--` 都属于同一种吹奏方式。程序只需要根据数字部分确定方式，遇到 `0` 则输出 `X`。

24 孔口琴的音阶排列在每个八度中具有固定规律。七个基本音阶对应的吹奏方式是 `1`、`3`、`5` 为吹气，`2`、`4`、`6`、`7` 为吸气。换成题目要求的字符，就是 `1 -> E`，`2 -> I`，`3 -> E`，`4 -> I`，`5 -> E`，`6 -> I`，`7 -> I`。

`n` 最大只有 100，因此即使采用非常直接的处理方式也远远不会触及 1 秒的时间限制。我们只需要对每个输入字符串做常数次字符判断，整个算法的工作量是几百次基本操作级别。这里不存在需要排序、搜索大量状态或者进行动态规划的问题，`O(n)` 已经足够，而且实际上也是读取输入所必须付出的数量级。

容易出错的地方主要集中在八度符号和休止符的处理上。第一个边界情况是八度变化不能改变吹奏方式。例如输入 `3 3+ 3-` 时，三个音符都是音阶 3，对应的输出应该是 `EEE`。如果程序把 `+` 或 `-` 当成不同音符重新建立映射，就可能得到错误结果。

```
3
3 3+ 3-
```

正确输出为：

```
EEE
```

第二个边界情况是休止符 `0` 不是数字音阶，因此不能按照普通数字映射。输入只有一个休止符时：

```
1
0
```

正确输出为：

```
X
```

如果程序直接使用类似 `mapping[token[0]]` 的逻辑，却没有为 `0` 单独处理，就会产生错误。

第三个容易忽略的情况是低八度可以连续出现多个 `-`。例如：

```
3
5-- 7+ 1
```

正确输出为：

```
EIE
```

这里 `5--` 仍然按照音阶 5 判断，`7+` 仍然按照音阶 7 判断。八度信息决定音高，但不影响题目要求的吸气或吹气。

## Approaches

最直接的暴力做法是把 24 个孔逐个检查。对于每一个输入音符，先根据数字和八度符号确定它实际对应的音高，然后在线性扫描的 24 个孔位中寻找这个音高所在的位置，最后根据该孔位属于吹气还是吸气来输出字符。这种方法是正确的，因为 24 孔口琴的完整音阶图本身就是一个有限的映射，逐孔查找最终一定能找到对应位置。

不过，即使把这种方法称为暴力搜索，它在本题中也不会真的超时。最坏情况下 `n = 100`，每个音符最多检查 24 个孔，因此最多只有 `100 × 24 = 2400` 次孔位比较。这远小于 1 秒能够处理的操作数量。

真正适合本题的做法来自一个更简单的观察。我们并不需要知道具体是哪一个孔，只需要知道这个音阶是吹气还是吸气。而且同一个基本音阶在不同八度下的吹奏方式相同，所以 `+` 和 `-` 完全不影响最终答案。这样，每个输入字符串实际上只需要检查第一个字符即可。

对于 `1` 到 `7`，可以直接建立固定映射。`1`、`3`、`5` 是吹气，输出 `E`；`2`、`4`、`6`、`7` 是吸气，输出 `I`。如果第一个字符是 `0`，输出 `X`。每个音符只做常数次操作，因此整个过程是线性的。

暴力方法的价值在于帮助理解题目中的口琴音阶图确实可以直接查找，但它多做了大量没有必要的工作。关键观察把“在 24 个孔中寻找音高”降低成了“查看音符的基本音阶”，从而得到最简洁的实现。

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(24n) = O(n) | O(1) | Accepted, but unnecessary |
| Optimal | O(n) | O(n) for the output string | Accepted |

## Algorithm Walkthrough

1. 读取音符数量 `n`，再读取接下来的 `n` 个音符字符串。每个字符串可能是普通数字、带 `+` 的音符、带 `-` 的音符，或者 `0`。
2. 逐个处理每个音符。只检查字符串的第一个字符，因为八度变化符号只改变音高，不改变这个基本音阶在口琴上的吹吸方式。
3. 如果当前音符是 `0`，把 `X` 加入答案。`0` 表示休止，而不是一个需要在口琴孔位中寻找的音阶。
4. 如果当前音符属于 `1`、`3`、`5`，把 `E` 加入答案。这三个基本音阶在对应的 24 孔口琴音阶排列中使用吹气。
5. 如果当前音符属于 `2`、`4`、`6`、`7`，把 `I` 加入答案。这些音阶使用吸气。
6. 所有音符处理完成后，将得到的字符依次连接并输出。输出中的第 `i` 个字符只由第 `i` 个输入音符决定，所以不需要维护前后音符之间的状态。

### Why it works

算法的核心不变量是：处理到第 `i` 个音符后，答案字符串的前 `i` 个字符恰好描述前 `i` 个输入音符的吹奏方式。对于任意一个非休止音符，它的第一个字符就是基本音阶 `1` 到 `7`，而 `+`、`-` 只表示八度变化，不改变该基本音阶的吹吸方式，因此固定映射能够得到唯一正确的字符。对于 `0`，算法直接输出 `X`，与休止的定义一致。每个音符独立处理，所以这个性质可以从第一个音符一直保持到最后一个音符，最终输出必然正确。

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    notes = input().split()

    mapping = {
        '1': 'E',
        '2': 'I',
        '3': 'E',
        '4': 'I',
        '5': 'E',
        '6': 'I',
        '7': 'I',
        '0': 'X'
    }

    ans = []
    for note in notes:
        ans.append(mapping[note[0]])

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```

程序首先建立 `mapping`，把基本音阶和输出字符一一对应。把 `0` 也放进同一个映射后，处理逻辑就统一了，不需要在循环中额外写一个特殊分支。

循环中的 `note[0]` 是关键实现细节。例如 `5--` 的第一个字符是 `5`，`7+` 的第一个字符是 `7`，因此八度符号会自然地被忽略。由于输入保证每个音符都是合法格式，所以这里不需要检查字符串是否为空。

最后使用 `''.join(ans)` 将所有字符合并成一个字符串。不能在循环中频繁使用字符串拼接来构造答案，虽然本题的 `n` 只有 100，不会产生实际性能问题，但列表收集后统一连接是更稳定的字符串构造方式。

题目中的 `n` 与第二行的音符数量是一一对应的。代码直接使用 `split()` 读取整行，因此多个空格也能被正常处理，而且不会受到 `+`、`-` 等符号的影响。

## Edge Cases

对于八度符号，输入 `3`、`3+` 和 `3-` 的区别只在音高，而题目要求的是吹气还是吸气。因此输入：

```
3
3 3+ 3-
```

程序分别取出三个字符串的第一个字符，得到三个 `3`，再通过映射得到 `E E E`，最终输出 `EEE`。如果错误地把完整字符串作为字典键，却只建立了 `3` 的映射，就会在 `3+` 或 `3-` 上查找失败。

对于休止符，输入：

```
1
0
```

字符串的第一个字符是 `0`，而映射表专门将 `0` 设置为 `X`，所以输出为 `X`。这个处理不能把 `0` 当成普通音阶，因为 `0` 没有对应的吹气或吸气动作。

对于多个八度符号，输入：

```
3
5-- 7+ 1
```

第一项取第一个字符得到 `5`，映射为 `E`；第二项得到 `7`，映射为 `I`；第三项得到 `1`，映射为 `E`。最终输出 `EIE`。这里不需要统计 `+` 或 `-` 的数量，因为无论升降一个还是两个八度，都不会改变吹吸类型。

对于边界音阶 `1` 和 `7`，输入：

```
2
1 7
```

程序分别得到 `E` 和 `I`，输出：

```
EI
```

这两个音阶分别位于基本音阶映射的两端，能够检查是否误把范围写成 `2` 到 `6`，或者错误地认为所有奇数音阶都吹气。实际规律是 `1`、`3`、`5` 吹气，而 `7` 也属于吸气，因此完整映射必须单独覆盖七个音阶。
