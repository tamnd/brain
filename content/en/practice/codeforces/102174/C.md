## Solution
## Problem Understanding

森克需要依次击败 (n) 只怪兽。第 (i) 只怪兽有 (d_i) 点生命值和 (x_i) 点攻击力，森克平时的攻击力为 (k)。每一回合森克先攻击，如果怪兽没有被这一击杀死，怪兽才会反击一次，所以森克真正承受伤害的次数，就是这场战斗中怪兽存活到下一回合的次数。

森克有 (c) 份力量炖水果。每吃一份，当前回合的攻击力增加 (k)，也就是说，如果这一回合吃了 (t) 份水果，森克这一击造成 ((t+1)k) 点伤害。水果的效果只持续当前回合，吃掉的水果也不能再次使用。

我们需要决定水果如何分配，使所有怪兽被击败后森克承受的总伤害最小。输出这个最小值。

对于第 (i) 只怪兽，如果完全不使用水果，它需要

[
q_i=\left\lceil\frac{d_i}{k}\right\rceil
]

次攻击才能死亡。由于森克始终先手，其中最后一次攻击不会受到反击，所以这只怪兽造成的伤害为

[
(q_i-1)x_i.
]

关键在于理解一份水果究竟能带来多少收益。如果在某场战斗中额外获得一份水果，相当于额外增加一次基础攻击单位 (k)。假设原本需要 (q_i) 次攻击，现在为这只怪兽投入 (f) 份水果，那么总共拥有 (q_i+f) 个单位的攻击力，可以把这些攻击力分配到若干回合中。只要最终需要的回合数为 (q_i-f)，就可以把水果带来的攻击力全部用于提前结束战斗。因此每投入一份水果，最多可以让这只怪兽少反击一次，也正好减少 (x_i) 点伤害。

一只怪兽最多只能从 (q_i) 个回合缩短到一个回合，所以它最多能使用

[
q_i-1
]

份水果。于是问题已经从模拟战斗变成了一个资源分配问题：每只怪兽提供 (q_i-1) 个位置，每个位置使用一份水果可以获得 (x_i) 的收益，总共只有 (c) 份水果。

由于 (n) 可以达到 (10^5)，而 (k,c,d_i,x_i) 最大可以达到 (10^6)，任何涉及所有水果状态和所有怪兽状态的二维动态规划都无法通过。比如 (O(nc)) 会达到 (10^{11}) 级别的状态，1 秒的限制下完全不可行。我们需要利用每一份水果带来的收益实际上只取决于它被分配给哪只怪兽这一性质。

还需要注意几个容易出错的边界情况。

第一种情况是怪兽只需要一回合。例如输入

```
1 10 100
7 5
```

输出应该是 `0`。因为基础攻击力已经足以一击击杀怪兽，怪兽根本没有机会反击。若代码直接把 (q_i x_i) 当作伤害，就会错误得到 5。

第二种情况是生命值恰好是攻击力的整数倍。例如输入

```
1 3 1
6 7
```

输出应该是 `0`。没有水果时需要两次攻击，但只用一份水果，第一回合攻击力变成 6，可以直接击杀。若把回合数写成 `d // k + 1`，就会出现典型的整除边界错误。

第三种情况是水果数量超过所有可以产生收益的位置。例如输入

```
2 10 100
1 4
1 9
```

输出仍然是 `0`。两只怪兽都只需要一回合，多出来的水果没有任何价值。若代码简单地把所有 (c) 份水果都当成有效收益，就会产生负数。

第四种情况是水果应该优先给攻击力更高的怪兽。例如

```
2 3 1
3 3
4 5
```

第一只怪兽只需要一回合，本身没有可以缩短的反击次数。第二只怪兽需要两回合，一份水果可以让它直接在第一回合死亡，因此答案为 `0`。如果按怪兽生命值大小分配水果，而不是按每份水果实际减少的伤害排序，就可能得到错误策略。

## Approaches

最直接的做法是把每只怪兽看成一个资源消耗对象。先计算每只怪兽不使用水果时需要的回合数 (q_i)，然后考虑给前若干只怪兽分别分配多少水果。可以做一个动态规划，令状态表示处理到某只怪兽时使用了多少份水果，转移时枚举当前怪兽使用的水果数量。这个思路完全忠实于原问题，因为我们显式尝试了水果在怪兽之间的所有分配。

即使进一步优化转移，这类方法仍然需要至少处理 (n) 和 (c) 的二维状态。最坏情况下状态数量达到

[
n c=10^5\times10^6=10^{11},
]

这已经远远超过可接受范围。若真的枚举每只怪兽可以使用的水果数量，复杂度还会更高。

真正的突破来自一个更简单的观察。对第 (i) 只怪兽而言，它本来需要 (q_i) 次攻击，也就是会反击 (q_i-1) 次。每额外使用一份水果，就相当于增加一次基础攻击单位，因此可以让所需攻击次数减少一次。一次少反击就少承受 (x_i) 点伤害，所以这只怪兽的每一份有效水果都具有完全相同的收益 (x_i)。

于是第 (i) 只怪兽实际上贡献了 (q_i-1) 个价值为 (x_i) 的物品。所有物品的重量都是 1，而背包容量是 (c)。这样的背包不需要动态规划，直接选择价值最大的物品即可。

因为同一只怪兽产生的所有物品价值都相同，我们甚至不需要真的建立这些物品。把所有怪兽按照 (x_i) 从大到小排序，然后尽可能把水果交给攻击力最高的怪兽即可。每只怪兽最多拿 (q_i-1) 份，拿满后再处理下一只怪兽。

初始答案是所有怪兽在没有水果时造成的伤害：

[
\sum_i(q_i-1)x_i.
]

每使用一份水果，就从答案中减去当前怪兽的 (x_i)。所以只需要按 (x_i) 降序贪心扣除收益。

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force DP | (O(nc)) 或更高 | (O(c)) | Too slow |
| Sort and Greedy | (O(n\log n)) | (O(n)) | Accepted |

## Algorithm Walkthrough

1. 对每只怪兽计算它在没有水果时需要的攻击次数

[
q_i=\left\lceil\frac{d_i}{k}\right\rceil
=\frac{d_i+k-1}{k}.
]

因为最后一次攻击不会遭到反击，所以它初始造成的伤害为 ((q_i-1)x_i)。
2. 将第 (i) 只怪兽的可用水果数量记为

[
cap_i=q_i-1.
]

每使用一份水果，最多可以让这只怪兽少进行一次会导致反击的回合，因此每份水果可以减少 (x_i) 点伤害。一个怪兽最多只能缩短到一回合，所以不能使用超过 (q_i-1) 份水果。
3. 把所有怪兽按照攻击力 (x_i) 从大到小排序。

这样排列后，前面的怪兽意味着一份水果能够节省更多生命值。由于所有水果的消耗都是 1，而每份水果只关心它带来的伤害减少量，优先使用收益最大的水果一定不会劣于把它放到收益更小的位置。
4. 依次处理排序后的怪兽。设当前还剩 (c) 份水果，那么最多可以给当前怪兽使用

[
\min(c,cap_i)
]

份。将这些水果带来的收益从答案中扣除，然后减少剩余水果数量。
5. 当水果用完，或者所有怪兽都已经没有可缩短的回合时结束。得到的答案就是最小总伤害。

### Why it works

把每只怪兽拆成 (q_i-1) 个虚拟物品，每个物品消耗一份水果并提供 (x_i) 的收益。任何一份水果对某只怪兽的作用，都可以独立地看成选择其中一个这样的虚拟物品，因为每减少一次怪兽的反击，就恰好少受到一次 (x_i) 点伤害。于是原问题等价于从这些单位重量的物品中选最多 (c) 个，使价值总和最大。

对于单位重量物品，最优方案显然选择价值最大的物品。这里每个物品的价值就是对应怪兽的攻击力 (x_i)，所以按 (x_i) 从大到小选择，并且每只怪兽最多选择 (q_i-1) 个，就是全局最优方案。初始伤害减去最大可获得的收益后，得到的正是最小伤害。

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n, k, c = map(int, input().split())

    monsters = []
    answer = 0

    for _ in range(n):
        d, x = map(int, input().split())

        rounds = (d + k - 1) // k
        useful = rounds - 1

        answer += useful * x

        if useful > 0:
            monsters.append((x, useful))

    monsters.sort(reverse=True)

    remaining = c

    for x, useful in monsters:
        if remaining == 0:
            break

        use = min(remaining, useful)
        answer -= use * x
        remaining -= use

    print(answer)

if __name__ == "__main__":
    solve()
```

代码首先计算 `rounds = (d + k - 1) // k`，这是整数形式的向上取整。这里不能写成 `d // k + 1`，因为当 (d) 恰好被 (k) 整除时，两者不同。

`useful = rounds - 1` 表示这只怪兽最多有多少次反击可以被水果消除。若 `useful` 为 0，这只怪兽已经一击死亡，没有必要把它加入排序数组。

变量 `answer` 先保存完全不吃水果时的总伤害。对于每个怪兽，这个值就是 `(rounds - 1) * x`。

随后按照 `x` 降序排序。Python 的元组排序会先比较第一个元素，因此 `monsters.sort(reverse=True)` 正好按照攻击力从大到小排列。第二个元素只是容量，不影响我们需要的主要排序顺序。

处理一个怪兽时，实际使用的水果数量为 `min(remaining, useful)`。这样既不会超过剩余水果，也不会让同一只怪兽被缩短到零回合。每份水果都减少 `x` 点最终伤害，所以直接执行 `answer -= use * x`。

所有数值都需要使用整数计算。最大总伤害可以达到约 (10^5\times10^6\times10^6=10^{17}) 的量级，Python 的整数没有固定 64 位限制，因此不会发生溢出。在 C++ 中则应使用 `long long`。

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | (O(n\log n)) | 计算所有怪兽信息需要 (O(n))，按照攻击力排序需要 (O(n\log n))，最后扫描一次需要 (O(n)) |
| Space | (O(n)) | 最多保存 (n) 只存在可优化回合的怪兽 |

## Edge Cases

当怪兽本身一回合就能被杀死时，(q_i=1)，所以 `useful = 0`。例如

```
1 10 100
7 5
```

计算得到 (q=1)，初始伤害就是 ((1-1)\times5=0)。算法不会给它分配水果，因为它没有任何有效位置，最终输出 `0`。

当 (d_i) 恰好是 (k) 的倍数时，向上取整必须得到准确的整数商。例如

```
1 3 1
6 7
```

有 (q=6/3=2)，所以没有水果时受到一次反击，伤害为 7。一份水果可以让第一回合攻击力变成 6，直接击杀怪兽，收益为 7，最终答案为 `0`。使用 `(d + k - 1) // k` 可以正确处理这个边界。

当水果数量超过总有效位置时，算法只会使用真正能够减少反击次数的水果。例如

```
2 10 100
1 4
1 9
```

两只怪兽都有 (q_i=1)，所以所有 `useful` 都是 0。排序数组为空，答案从一开始就是 0。剩余的水果没有任何用途，也不会被错误地算成负伤害。

当不同怪兽的攻击力不同，而水果数量有限时，排序是决定正确性的核心。例如

```
2 3 1
3 3
4 5
```

第一只怪兽没有有效位置，第二只怪兽有一个价值为 5 的位置。唯一水果交给第二只怪兽可以减少 5 点伤害，正好把它从两回合战斗变成一回合战斗，因此答案为 0。算法按照攻击力排序后自然得到这个选择。

最后，当 (c) 非常大时，不能写成循环执行 (c) 次并每次寻找最优怪兽。(c) 可以达到 (10^6)，虽然单独看并不算巨大，但结合 (n=10^5) 会让错误的 (O(nc)) 方法达到 (10^{11}) 级别。当前算法对每只怪兽一次性计算 `use = min(remaining, useful)`，所以无论 (c) 多大，处理水果的循环仍然只有 (O(n)) 次。
