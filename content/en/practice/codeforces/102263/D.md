## Solution
## Problem Understanding

We have a first array `a` whose elements we are allowed to modify, and a second array `b` containing the permitted step sizes. In one operation, we choose one element of `a` and either add or subtract any value from `b`. We may repeat this operation any number of times, and the goal is to make every element of `a` equal.

The key question is not which common value we should reach. The real question is whether the allowed operations can change the difference between two elements of `a` by exactly the amount needed to make that difference zero.

Suppose the greatest common divisor of all values in `b` is `g`. Every operation changes an element by a multiple of `g`, because every `b[j]` is divisible by `g`. Conversely, Bézout's identity tells us that every integer multiple of `g` can be constructed by adding and subtracting elements of `b`. Thus, from any starting value `x`, the set of values reachable from it is exactly the set of integers congruent to `x` modulo `g`.

Consequently, all elements of `a` can become equal exactly when they already have the same remainder modulo `g`.

The constraints allow both array lengths to reach `10^6`. An algorithm with quadratic complexity would require around `10^12` operations in the worst case, which is far beyond what a competitive programming time limit can handle. Even an `O(nm)` approach is ruled out immediately. We need to process each input value only a constant number of times, giving an `O(n + m)` solution.

There are several edge cases that can make an implementation based on intuition fail. If `m = 1`, the only permitted step is some value `b`, so values such as `1` and `3` can be equalized when `b = 2`, because both have the same remainder modulo `2`. A careless solution might incorrectly require their difference itself to appear in `b`.

For example:

```
2 1
1 3
2
```

The correct output is `Yes`. We can change `1` to `3` by adding `2`.

Another subtle case is when the values in `b` have a common divisor larger than one even though no single `b[j]` is the required difference.

```
2 2
1 7
6 10
```

The correct output is `Yes`, because `gcd(6, 10) = 2` and both first-array values are odd. The difference `6` is itself available, so one can directly transform `1` into `7`, but the example also illustrates that the relevant structure is generated by the common gcd, not by individual step values.

The opposite case is equally important:

```
2 2
1 8
6 10
```

Here the correct output is `No`, because `1` is odd while `8` is even. Every operation changes a number by an even amount, so its parity can never change.

Finally, when the first array contains only one element, it is already possible to make all its elements equal because there is nothing to change.

```
1 3
100
6 10 15
```

The correct output is `Yes`. An implementation that always compares pairs of elements must handle this case explicitly or naturally allow the empty comparison set.

## Approaches

A direct brute-force approach would try to simulate the allowed operations. Starting from one value, it could repeatedly add or subtract values from `b` and search for a value reachable from every other element. The approach is conceptually correct because every legal operation is represented in the search, but the state space is unbounded. We can keep applying operations forever, and the same values can be reached through many different sequences.

A more restrained brute-force approach might examine every pair of elements in `a` and try to determine whether their difference can be represented as a combination of values from `b`. If it uses every value of `b` while processing every pair, the worst case is `O(n^2m)`, which can reach roughly `10^18` elementary checks for `n,m = 10^6`. Even reducing this to a pairwise `O(n^2)` check still gives about `10^12` operations.

The brute-force works because the operations form an additive system, but it fails when we try to enumerate that system explicitly. The observation that unlocks the problem is that the additive system generated by several integers is completely described by their gcd.

Let

```
g = gcd(b[0], b[1], ..., b[m-1]).
```

Every allowed step is divisible by `g`, so the remainder modulo `g` never changes. This gives a necessary condition immediately: every `a[i]` must have the same remainder modulo `g`.

The same condition is also sufficient. Since `g` is the gcd of the elements of `b`, there exist integers `c1, c2, ..., cm` such that

```
c1*b[0] + c2*b[1] + ... + cm*b[m-1] = g.
```

Each coefficient can be interpreted as repeated addition or subtraction, so we can construct `g`, and consequently any multiple of `g`. If two values of `a` have the same remainder modulo `g`, their difference is divisible by `g`, so that difference can be generated using the permitted operations. We can transform every element to the same target residue class representative.

This reduces the entire problem to one gcd computation and one pass over the first array.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(n²m) in a direct operation search | O(n) or more | Too slow |
| Optimal | O(n + m) | O(n) | Accepted |

## Algorithm Walkthrough

1. Read the two arrays. We need the values in `b` to determine which congruence classes are preserved, and the values in `a` to check whether all elements belong to one such class.
2. Compute the gcd of every value in `b`. Start with `g = 0`, then repeatedly update `g = gcd(g, b[i])`. Starting from zero works because `gcd(0, x) = x`, so after processing the entire second array, `g` is exactly the gcd of all permitted step sizes.
3. Store the remainder of the first element of `a` modulo `g`. This remainder represents the only congruence class that all elements are allowed to occupy if a solution exists.
4. Scan every remaining element `a[i]`. If `a[i] % g` differs from the first remainder, print `No` immediately. Its residue cannot be changed by any sequence of legal operations, so it can never become equal to the other elements.
5. If every element has the same remainder modulo `g`, print `Yes`. Any difference between two elements is divisible by `g`, and every multiple of `g` can be generated from the values in `b`, so all elements can be transformed to a common value.

### Why it works

The invariant is the remainder of each first-array element modulo `g`. Since every permitted operation adds or subtracts a number divisible by `g`, this remainder never changes. If two elements have different remainders, they can never meet, which proves the rejection condition.

If all elements have the same remainder, the difference between any two elements is divisible by `g`. The gcd of the allowed steps generates exactly all integer multiples of `g`, so that difference can be eliminated by a sequence of legal additions and subtractions. Hence all elements belong to the same reachable equivalence class, and the answer is `Yes`.

## Python Solution

```python
import sys
from math import gcd

input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    a = list(map(int, input().split()))
    b = list(map(int, input().split()))

    g = 0
    for x in b:
        g = gcd(g, x)

    r = a[0] % g

    for x in a[1:]:
        if x % g != r:
            print("No")
            return

    print("Yes")

if __name__ == "__main__":
    solve()
```

The first loop computes the gcd of all allowed step sizes. Python's `math.gcd` handles the Euclidean algorithm efficiently, and starting from zero avoids needing a special case for the first element of `b`.

The second part uses `a[0]` as the reference residue. Every other value must have exactly the same remainder modulo `g`. The check can terminate as soon as a mismatch appears because one mismatching element is enough to make the answer impossible.

There is no integer overflow concern in Python. In languages with fixed-width integers, the input values themselves fit comfortably in 32-bit signed integers, and the gcd calculation never needs values larger than the original operands.

The case `n = 1` is handled naturally. The loop over `a[1:]` is empty, so the algorithm prints `Yes`.

The case `m = 1` is also handled naturally. The gcd becomes the only value in `b`, giving exactly the expected condition that all first-array values must be congruent modulo that step size.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | O(n + m) | Every value in `b` participates in one gcd computation, and every value in `a` is checked once. |
| Space | O(n + m) | The implementation stores both input arrays. |

With array lengths up to `10^6`, linear processing is the appropriate scale. The algorithm performs only a constant amount of work per input value and avoids pairwise comparisons or state-space exploration. The memory usage is also linear, dominated by storing the two input arrays.

## Edge Cases

When there is only one element in the first array, there is no equality constraint between different elements. For

```
1 1
100
7
```

the gcd is `7`, the reference residue is `100 % 7 = 2`, and there are no remaining elements to contradict it. The algorithm prints `Yes`.

When all values are already equal, no operation is required. For

```
5 3
42 42 42 42 42
6 10 14
```

the gcd is `2`, and every value has remainder `0`. The scan finds no mismatch and prints `Yes`. The algorithm does not unnecessarily require an available operation to perform.

When several allowed step sizes share a nontrivial gcd, the individual step values are not the real invariant. For

```
4 3
1 7 13 19
6 10 14
```

the gcd is `2`, and all four first-array values have remainder `1`. Even though the difference between arbitrary values such as `1` and `13` need not be one of the entries in `b`, it is divisible by `2`, so it can be generated from combinations of `6`, `10`, and `14`. The algorithm correctly prints `Yes`.

When two values have different residues modulo the gcd, no sequence of operations can make them equal. For

```
3 3
1 7 8
6 10 14
```

the gcd is `2`. The first two values are odd, while `8` is even. The scan reaches `8`, computes `8 % 2 = 0`, compares it with the reference residue `1`, and immediately prints `No`.

The maximum input size does not introduce a mathematical boundary case, but it exposes inefficient implementations. With `n = 100000` or larger, comparing every pair would already require billions of checks. The presented algorithm instead performs one gcd pass and one residue pass, so increasing the input size scales linearly.
