## Solution
## Problem Understanding

The input describes the results of a collection of football matches. Each match contains two team names and a result character. A `W` means the first team won, while `T` means the teams drew. A win gives the first team 3 points and the losing team 0, while a draw gives both teams 1 point. The task is to calculate every team's total points and print all teams from highest score to lowest score. Teams with equal scores are ordered alphabetically. The official statement gives the same scoring rules and ordering requirement.

A team can be identified simply by its name, so a dictionary is the natural data structure for storing its current score. Every match affects exactly two entries, and a team only needs to be created when it first appears in a match. After all matches have been processed, there are at most `2n` distinct team appearances, so the number of distinct teams is also at most `2n`.

The statement does not publish an explicit upper bound for `n` on the current Codeforces page. The time limit is 1 second and the memory limit is 256 MB. That makes an algorithm linear in the number of matches, followed by one sort of the distinct teams, the appropriate target. An approach that scans all matches separately for every team can require quadratic work, which becomes problematic as the number of games grows.

The first edge case is a single match. For

```
1
A B W
```

the correct output is

```
A 3
B 0
```

A careless implementation that only records teams after awarding points can forget `B`, because the losing team receives zero points but still has to appear in the output.

The second edge case is a draw:

```
1
A B T
```

The correct output is

```
A 1
B 1
```

A solution that treats `T` as a win for the first team would incorrectly give `A` three points and `B` zero.

The third edge case is a tie in the final standings. For

```
2
Bob Alice T
Charlie Alice T
```

the scores are `Alice = 2`, `Bob = 1`, and `Charlie = 1`, so the output is

```
Alice 2
Bob 1
Charlie 1
```

The equal-score teams must be alphabetized, rather than kept in input order. A sorting key that uses only the score would fail on this case.

## Approaches

A direct brute-force solution can first collect the team names and then, for every team, scan every game to determine how many points that team earned. This is correct because every match is examined when computing each team's total, so no result can be missed. If there are `m` distinct teams and `n` games, however, this performs `m * n` game checks. Since `m` can be as large as `2n`, the worst case is about `2n²` checks. After that, the teams still have to be sorted.

The brute force works because the scoring rule for one team can be determined independently by inspecting every match. The problem is that the same match gets inspected again and again for different teams. The key observation is that each match already tells us exactly how the scores of its two participants change. There is no reason to postpone those updates and scan the match later.

We can process each game exactly once. When the result is `W`, add 3 to the first team's score and leave the second team's score unchanged. When the result is `T`, add 1 to both teams. At the end, sorting the dictionary entries by descending score and then ascending team name produces exactly the required ranking.

The only non-linear part is the final sorting. If `m` teams appear, that costs `O(m log m)`, while processing all games costs `O(n)`. Since `m <= 2n`, the total is `O(n log n)`.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(mn + m log m), worst case O(n²) | O(m) | Too slow for large input |
| Optimal | O(n + m log m), hence O(n log n) | O(m) | Accepted |

## Algorithm Walkthrough

1. Create an empty dictionary `score`. Its key is a team name and its value is that team's current number of points. A team must be inserted even when its first result is a loss, because every team appearing in the match belongs in the final standings.
2. Read each match as `team1`, `team2`, and `result`. Initialize both teams in the dictionary with score zero if they have not appeared before.
3. If the result is `W`, add 3 points to `team1`. The second team gets no points, but its dictionary entry remains present.
4. If the result is `T`, add 1 point to both teams. There is no other possible result according to the input specification.
5. Convert the dictionary into pairs of `(team, score)` and sort them using the key `(-score, team)`. Negating the score gives descending numerical order, while the team name remains in normal alphabetical order.
6. Print every sorted pair as `team score`. The number of output lines is exactly the number of distinct teams that appeared in the games.

### Why it works

After processing any prefix of the input, the dictionary invariant is that every team stored in it has exactly the points earned in the matches processed so far. A `W` updates the winner by exactly the 3 points prescribed by the rules, and a `T` updates both participants by exactly 1 point. Since every match is processed once, after the final match every dictionary value is the team's complete tournament score. The final sorting key orders these complete scores from largest to smallest and breaks equal scores alphabetically, so every printed line satisfies the required ranking.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    score = {}

    for _ in range(n):
        team1, team2, result = input().split()

        if team1 not in score:
            score[team1] = 0
        if team2 not in score:
            score[team2] = 0

        if result == "W":
            score[team1] += 3
        else:
            score[team1] += 1
            score[team2] += 1

    teams = sorted(score.items(), key=lambda item: (-item[1], item[0]))

    sys.stdout.write(
        "\n".join(f"{team} {points}" for team, points in teams)
    )

if __name__ == "__main__":
    solve()
```

The dictionary is the central part of the implementation. `score[team]` always contains the points accumulated by that team so far, matching the invariant from the algorithm walkthrough.

Both teams are initialized before examining the result. This is necessary for losses, because a losing team receives zero points but still has to be printed. Initializing both sides also makes the draw case straightforward.

For `W`, only `team1` receives points because the statement guarantees that the first listed team is the winner. For `T`, both teams receive one point. There is no need for an `L` branch because `L` cannot occur in the input.

The sorting expression uses `(-item[1], item[0])`. If two teams have scores 7 and 4, their keys begin with `-7` and `-4`, so 7 comes first. If two teams both have 4, their first key components are equal and Python compares the second components, which are the team names, alphabetically.

Python integers do not overflow, so even a large number of games does not require special handling for the score value. The output is built with `join`, avoiding an unnecessary flush or write operation for every individual team.

## Worked Examples

The official sample contains four teams and six matches.

```
6
Germany Portugal W
UnitedStates Ghana W
Germany Ghana T
UnitedStates Portugal T
Germany UnitedStates W
Portugal Ghana W
```

The processing state is:

| Match | Result | Germany | Portugal | UnitedStates | Ghana |
| --- | --- | --- | --- | --- | --- |
| Germany Portugal | W | 3 | 0 | 0 | 0 |
| UnitedStates Ghana | W | 3 | 0 | 3 | 0 |
| Germany Ghana | T | 4 | 0 | 3 | 1 |
| UnitedStates Portugal | T | 4 | 1 | 4 | 1 |
| Germany UnitedStates | W | 7 | 1 | 4 | 1 |
| Portugal Ghana | W | 7 | 4 | 4 | 1 |

The final scores are Germany 7, Portugal 4, UnitedStates 4, and Ghana 1. Portugal and UnitedStates have equal scores, so the secondary alphabetical comparison puts `Portugal` before `UnitedStates`.

The output is:

```
Germany 7
Portugal 4
UnitedStates 4
Ghana 1
```

For a second example, consider a group where every match is a draw:

```
3
Beta Alpha T
Gamma Alpha T
Gamma Beta T
```

The state becomes:

| Match | Result | Alpha | Beta | Gamma |
| --- | --- | --- | --- | --- |
| Beta Alpha | T | 1 | 1 | 0 |
| Gamma Alpha | T | 2 | 1 | 1 |
| Gamma Beta | T | 2 | 2 | 2 |

All three teams finish with 2 points. Since their scores are equal, the names determine the order:

```
Alpha 2
Beta 2
Gamma 2
```

This trace demonstrates why the sorting key needs both score and name. It also confirms that every team is retained even when no team wins a game.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | O(n + m log m) | Each of the `n` games is processed once, then `m` distinct teams are sorted |
| Space | O(m) | The dictionary and sorted team list store one entry per distinct team |

Here `m` is the number of distinct teams, and `m <= 2n` because every game contains two teams. Thus the total time is `O(n log n)` in terms of the number of games, with linear memory. This is comfortably preferable to repeatedly scanning all games for every team under the 1 second limit.

## Edge Cases

For the single-match case

```
1
A B W
```

both teams are inserted before the result is processed. The score becomes `A = 3` and `B = 0`. Sorting places `A` first, giving

```
A 3
B 0
```

The critical detail is that `B` is created even though its score never increases.

For a draw

```
1
A B T
```

the dictionary starts as `{A: 0, B: 0}`. The `T` branch increments both entries, producing `{A: 1, B: 1}`. The output is

```
A 1
B 1
```

There is no special case required for draws beyond updating both participants.

For equal final scores,

```
2
Bob Alice T
Charlie Alice T
```

the first match gives `Bob = 1` and `Alice = 1`. The second gives `Charlie = 1` and `Alice = 2`. The final values are `Alice = 2`, `Bob = 1`, and `Charlie = 1`. The sorting keys for Bob and Charlie are `(-1, "Bob")` and `(-1, "Charlie")`, so the result is

```
Alice 2
Bob 1
Charlie 1
```

The input order does not influence the final ordering among teams with equal scores.

For repeated games,

```
4
Zed Amy T
Amy Bob W
Bob Zed T
Zed Amy W
```

the scores evolve as `Zed = 1, Amy = 1`, then `Amy = 4, Bob = 0`, then `Bob = 1, Zed = 2`, and finally `Zed = 5, Amy = 4`. The output is consequently

```
Zed 5
Amy 4
Bob 1
```

Every occurrence of a team contributes to the same dictionary entry, so there is no assumption that two teams meet at most once.

Finally, a team that loses every match must not disappear. In

```
2
A B W
C B W
```

the updates produce `A = 3`, `C = 3`, and `B = 0`. Since `B` was inserted when the first match was read, it remains in the dictionary and is printed last:

```
A 3
C 3
B 0
```

This is the main implementation detail that separates a complete standings solution from one that only tracks teams that receive points.
