## Solution
## Problem Understanding

We are given an 8 by 8 chessboard containing several knights. Every cell is either empty, represented by `.`, or contains a knight, represented by `K`. A knight attacks exactly the cells reachable by changing one coordinate by 2 and the other by 1. We must mark every empty cell that is reachable by at least one knight in exactly one move with `*`. Existing knights remain `K`, and every other empty cell remains `.`. The resulting 8 by 8 board is printed.

The board dimensions are fixed at 8 by 8, so there are only 64 cells. Even a solution that performs a few hundred or a few thousand operations is comfortably fast. There is no need for a sophisticated graph algorithm or breadth-first search because we only care about one knight move, not about paths involving several moves. In particular, the largest possible number of knights is 64, and each knight has only 8 possible move offsets, giving at most 512 candidate destinations to inspect.

The main edge cases come from board boundaries and overlapping moves. A knight in a corner has only two legal moves. For example, with

```
K.......
........
........
........
........
........
........
........
```

the correct output is

```
........
..*.....
.*......
........
........
........
........
........
```

A careless implementation that assumes all eight moves stay inside the board would index outside the array or mark an invalid position.

Another subtle case occurs when several knights can reach the same empty cell. The cell should still contain only one `*`, because the output describes whether the cell is reachable, not how many knights reach it. For example,

```
........
..K.....
........
.K......
........
........
........
........
```

can have cells reached by both knights. Assigning `*` rather than incrementing a counter naturally handles this case.

A third case is a destination that already contains a knight. The output must preserve `K` rather than replace it with `*`. For example,

```
K.......
........
..K.....
........
........
........
........
........
```

has a knight at `(0, 0)` that can reach `(2, 1)`, but that destination is already occupied by another knight, so it remains `K`. A careless implementation that marks every reachable cell unconditionally would destroy the original board information.

## Approaches

A straightforward brute-force solution can inspect every board cell and ask whether at least one knight can move to it. For each destination, we can inspect every cell as a possible knight and test the eight knight offsets. With 64 possible destinations, 64 possible source cells, and 8 offsets, the worst case performs `64 * 64 * 8 = 32,768` move checks. That is tiny for this particular board, so this approach is actually fast enough.

The more direct approach starts from the knights instead. Whenever we encounter a `K`, we try all eight possible knight moves. If a destination is inside the 8 by 8 board and currently contains `.`, we change it to `*`. Each knight contributes at most eight checks, so with 64 knights there are at most `64 * 8 = 512` candidate moves.

The key observation is that the problem asks for cells reachable in one move. We do not need to search through intermediate positions. A knight's complete set of possible one-step destinations is known in advance, so each knight can be processed independently. This reduces the work from checking every source-destination pair to checking only the eight geometrically possible destinations of each actual knight.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(64² × 8) | O(64) | Accepted, but unnecessary work |
| Optimal | O(64 × 8) | O(64) | Accepted |

Since 64 is a constant, both approaches are technically O(1) with respect to input size. The second approach is still preferable because it directly expresses the structure of the problem and avoids examining cells that are not knights.

## Algorithm Walkthrough

1. Read the eight board rows into a mutable 8 by 8 character grid. Keeping the grid mutable lets us write `*` directly into reachable empty cells.
2. Scan every row and every column. When the current cell contains `K`, treat it as a source position for one knight move.
3. For that knight, try the eight displacement pairs `(2,1)`, `(2,-1)`, `(-2,1)`, `(-2,-1)`, `(1,2)`, `(1,-2)`, `(-1,2)`, and `(-1,-2)`. These are exactly the legal ways to move two cells in one direction and one cell perpendicular to it.
4. For each destination, first check that its row and column are between `0` and `7`. A move outside this range leaves the chessboard and must be ignored.
5. If the destination is inside the board and contains `.`, replace it with `*`. We deliberately do not replace `K`, because knights must remain visible in the output. Repeatedly reaching the same cell is harmless because assigning `*` again does not change the result.
6. After every knight has been processed, print the eight resulting rows. Every marked cell is reachable by at least one knight, while every unmarked empty cell was not reached by any legal move.

### Why it works

The invariant is that after processing any prefix of the knights, every `*` on the board is reachable in one legal move from at least one processed knight, and every legal destination of every processed knight has been marked unless it was occupied by a knight. When a new knight is processed, all eight and only eight possible knight destinations are examined, so the invariant is extended to that knight without introducing an invalid destination. After all knights are processed, every possible one-move destination has been considered, which means the final board contains exactly the required reachable empty cells.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    board = [list(input().strip()) for _ in range(8)]

    moves = [
        (2, 1), (2, -1),
        (-2, 1), (-2, -1),
        (1, 2), (1, -2),
        (-1, 2), (-1, -2)
    ]

    for r in range(8):
        for c in range(8):
            if board[r][c] != 'K':
                continue

            for dr, dc in moves:
                nr = r + dr
                nc = c + dc

                if 0 <= nr < 8 and 0 <= nc < 8:
                    if board[nr][nc] == '.':
                        board[nr][nc] = '*'

    for row in board:
        print(''.join(row))

if __name__ == "__main__":
    solve()
```

The board is stored as lists rather than strings because individual cells need to change from `.` to `*`. The `moves` array contains all eight legal knight displacements, so there is no need for separate special cases for horizontal and vertical moves.

The boundary check uses `0 <= nr < 8` and `0 <= nc < 8`. Python uses zero-based indexing, so valid row and column indices are exactly `0` through `7`. Checking the destination before accessing `board[nr][nc]` prevents an invalid array access.

The condition `board[nr][nc] == '.'` is also deliberate. A destination containing `K` must remain a knight. A destination already containing `*` does not need special handling, because assigning `*` again would have exactly the same effect.

There is no integer overflow issue because the algorithm stores only characters and coordinates. Fast I/O is not actually necessary for such a small input, but `sys.stdin.readline` follows the standard competitive-programming input pattern.

The board is fixed at 64 cells, so the solution is far below any practical time or memory limit. Even the brute-force alternative would perform only 32,768 move checks, but the direct solution is simpler and scales naturally if the board dimensions are later generalized.

## Edge Cases

A knight in the upper-left corner has only two legal destinations. With

```
K.......
........
........
........
........
........
........
........
```

the algorithm tries all eight offsets. Six produce negative row or column indices and are rejected by the boundary condition. The two valid destinations are `(1,2)` and `(2,1)`, so the output is

```
K.......
..*.....
.*......
........
........
........
........
........
```

Multiple knights may reach the same cell. Suppose two knights produce the same destination during their respective move loops. The first knight changes `.` to `*`; when the second knight reaches the same position, the cell is already `*`. The condition only acts on `.`, so the result remains a single `*`. This represents reachability rather than the number of attacking knights.

A knight can also target another knight. Consider

```
K.......
........
..K.....
........
........
........
........
........
```

The knight at `(0,0)` can reach `(2,1)`, but that cell contains `K`. The implementation checks for `.` before writing `*`, so the second knight remains unchanged. This preserves the required distinction between an occupied cell and an empty reachable cell.

Finally, a board containing no knights should remain completely unchanged. Since the outer scan never enters the move loop when `board[r][c] != 'K'`, no cell can accidentally become `*`. Conversely, if every cell contains a knight, every possible destination is occupied, so the board also remains unchanged. These cases fall out naturally from the same two checks rather than requiring special-case code.
