## Problem Understanding

The task is a small numerical algebra problem built around the Steinhart-Hart equation. We have three calibration measurements. Each measurement pairs a resistance (R_i) with a temperature (T_i), and the model says

[
\frac{1}{T}=A+B\ln R+C(\ln R)^3.
]

The three measurements determine the three unknown constants (A), (B), and (C). We only need to print (A). The input contains (T_1,T_2,T_3,R_1,R_2,R_3), each as a floating-point value on its own line. The official statement explicitly gives a sequence of intermediate formulas for computing the constants, so the programming task is mainly about evaluating those formulas in the correct order.

There is no large (n), array, graph, or repeated test case here. The input size is always six floating-point numbers, and the time limit is one second with 256 MB of memory. Consequently, asymptotic optimization is not the issue. Any solution performing a fixed number of arithmetic operations is effectively instantaneous. The real concerns are using the natural logarithm, preserving floating-point precision, and evaluating the divisions in the intended order.

The calibration points must be suitable for the supplied formulas. In particular, the logarithms require positive resistances, and the denominators (L_2-L_1), (L_3-L_1), (L_3-L_2), and (L_1+L_2+L_3) must not vanish for the formulas to be defined.

A useful boundary case is a resistance of exactly (1). For example,

```
1
1
1
1
2
4
```

has (L_1=\ln 1=0). If the three temperatures are all (1), then every (Y_i) is (1), so both slopes are zero, giving (C=0), (B=0), and finally (A=1). The correct output is (1). A careless implementation that assumes logarithms are always nonzero could incorrectly treat this as a special case or introduce an unnecessary division by (L_1).

Another edge case is when all three temperatures are equal while the resistances are different. For

```
1
1
1
1
2
4
```

the same calculation gives (A=1), (B=0), (C=0). A method that assumes different temperatures are necessary would reject a perfectly valid mathematical case.

A more dangerous case is repeated resistance. For example,

```
1
1
1
2
2
4
```

makes (L_2-L_1=0), so (\gamma_2) is undefined. The supplied formulas cannot determine the calibration constants from such data. A careless implementation would attempt the division and produce an exception or an invalid floating-point result. Valid test data must avoid this singular situation.

## Approaches

A generic way to think about the problem is to treat the three measurements as three equations in the three unknowns (A,B,C). After writing

[
Y_i=\frac1{T_i},\qquad L_i=\ln R_i,
]

each measurement becomes

[
Y_i=A+B L_i+C L_i^3.
]

A naive algebraic implementation could build this as a (3\times3) linear system and perform Gaussian elimination. That approach is completely feasible because the matrix always has exactly three rows and three columns. It performs only a constant number of arithmetic operations, so unlike the usual large-input brute force, there is no input size at which it becomes asymptotically too slow. The worst case is still just a fixed-size elimination, well below a few hundred arithmetic operations.

The more natural solution comes from observing that the problem already provides an elimination sequence specialized to this exact system. Taking differences between equations removes (A). Dividing those differences by the corresponding differences in (L) gives two secant slopes, (\gamma_2) and (\gamma_3). Their difference isolates the cubic coefficient (C), after which (B) follows immediately. Finally, substituting the first calibration point recovers (A).

This is preferable to generic Gaussian elimination because the algebra has already exploited the special structure of the basis functions (1,L,L^3). There is no matrix construction, pivoting, or general-purpose elimination to implement. The entire computation is a fixed sequence of logarithms, additions, multiplications, and divisions.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Generic 3x3 Gaussian elimination | (O(1)) | (O(1)) | Accepted |
| Direct Steinhart-Hart formulas | (O(1)) | (O(1)) | Accepted, simpler |

## Algorithm Walkthrough

1. Read the six floating-point values in their input order. The statement gives the order as (T_1,T_2,T_3,R_1,R_2,R_3), so the first three values must be interpreted as temperatures rather than resistances.
2. Compute (L_1=\ln R_1), (L_2=\ln R_2), and (L_3=\ln R_3). These are the independent-variable values used by the Steinhart-Hart equation.
3. Compute (Y_1=1/T_1), (Y_2=1/T_2), and (Y_3=1/T_3). The original equation is expressed in terms of (1/T), so these values convert the measurements into the form needed by the algebra.
4. Compute

[
\gamma_2=\frac{Y_2-Y_1}{L_2-L_1}
]

and

[
\gamma_3=\frac{Y_3-Y_1}{L_3-L_1}.
]

These quantities represent slopes between the first calibration point and the other two points after transforming the data.

1. Compute

[
C=
\frac{\gamma_3-\gamma_2}{L_3-L_2}
\cdot
\frac{1}{L_1+L_2+L_3}.
]

The difference between the two slopes removes the contribution that behaves linearly in (L), leaving enough information to determine the cubic coefficient.

1. Compute

[
B=\gamma_2-C(L_1^2+L_1L_2+L_2^2).
]

This subtracts the cubic contribution from the first secant slope, leaving the coefficient of (L).

1. Recover (A) using the first calibration point:

[
A=Y_1-L_1(B+L_1^2C).
]

This is simply the original equation rearranged to isolate (A).

1. Print (A) as a floating-point value. The judge uses a tolerance, so exact decimal reproduction is unnecessary. The official statement also explicitly says not to worry about exact rounding.

The invariant throughout the calculation is that (L_i) and (Y_i) always represent the transformed coordinates of the original calibration measurements, while (C), then (B), and finally (A) are recovered in an order where every newly computed coefficient depends only on values already known. Since the formulas are algebraically derived from the three original equations, the resulting (A) is the coefficient belonging to the same model that generated the calibration data.

## Python Solution

```python
import sys
import math

input = sys.stdin.readline

def solve(values):
    T1, T2, T3, R1, R2, R3 = values

    L1 = math.log(R1)
    L2 = math.log(R2)
    L3 = math.log(R3)

    Y1 = 1.0 / T1
    Y2 = 1.0 / T2
    Y3 = 1.0 / T3

    gamma2 = (Y2 - Y1) / (L2 - L1)
    gamma3 = (Y3 - Y1) / (L3 - L1)

    C = ((gamma3 - gamma2) / (L3 - L2)) / (L1 + L2 + L3)

    B = gamma2 - C * (L1 * L1 + L1 * L2 + L2 * L2)

    A = Y1 - L1 * (B + L1 * L1 * C)

    return A

def main():
    values = [float(input()) for _ in range(6)]
    print(solve(values))

if __name__ == "__main__":
    main()
```

The `solve` function mirrors the mathematical derivation directly. Keeping (L_i) and (Y_i) as separate variables makes the dependency order explicit and prevents accidentally mixing a temperature with its reciprocal.

`math.log` computes the natural logarithm required by the Steinhart-Hart equation. Python's `float` is sufficient because the judge accepts answers within a numerical tolerance.

The expression for (C) is written as two divisions rather than using an explicit negative exponent. Both forms are mathematically equivalent, and the chosen version makes the denominator structure easier to inspect. The expression for (B) uses (L_1^2), (L_1L_2), and (L_2^2) exactly as given by the derivation.

There is no integer overflow issue because all calculations use Python floating-point values. There is also no need for special formatting such as a fixed number of decimal places. Printing the full Python floating-point representation gives more than enough precision for the stated tolerance.

## Edge Cases

When (R_1=1), we get (L_1=0). For

```
1
1
1
1
2
4
```

the transformed values are (L=(0,\ln2,\ln4)) and (Y=(1,1,1)). Both gamma values are zero, so (C=0), then (B=0), and the final calculation gives (A=1). No special branch is needed because the formula naturally handles (L_1=0).

When all temperatures are equal, the three (Y_i) values are equal. For the same input, the two secant slopes are both zero. Consequently (C=0) and (B=0), leaving (A=Y_1). This demonstrates why equal temperatures alone are not a problem. What matters is whether the transformed calibration points make the required denominators zero.

Repeated resistances are different. For

```
1
1
1
2
2
4
```

we have (L_1=L_2), so the expression for (\gamma_2) contains a zero denominator. There is no valid result from the supplied calibration formulas for this data. The implementation intentionally does not hide this condition with arbitrary epsilon adjustments, because changing a zero denominator into an approximate one would invent calibration data that the problem did not provide.

Finally, very large resistances such as (10^{100}), (10^{200}), and (10^{300}) are still within Python's floating-point range. `math.log` operates on these values directly and produces finite logarithms. The algorithm itself does not depend on the resistance being small, only on it being positive and on the resulting calibration equations being nonsingular.
