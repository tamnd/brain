## Solution
## Problem Understanding

We are given an upper bound `m`, with `m < 10^6`, and need to construct the best RSA public key `(n, e)` under that bound. The modulus `n` must be a semiprime, meaning it has exactly two prime factors when multiplicity is counted. Thus `4 = 2 × 2`, `6 = 2 × 3`, and `25 = 5 × 5` are valid, while `12 = 2 × 2 × 3` is not. The exponent `e` must satisfy `1 < e < n`, `e <= m`, and `gcd(n, e) = 1`. Among all valid keys, we first maximize `n`, then minimize `e`. The original problem specifies only that `m` is positive, but a valid key first exists at `m = 4`, so the intended test data necessarily has a sufficiently large `m`.

The bound below one million is the central algorithmic clue. A direct factorization of every candidate would be too expensive in the worst case. Testing one number by trial division takes up to about `sqrt(m)` divisor checks, and doing that for a large range of candidates gives roughly `O(m sqrt(m))` work. At `m = 10^6`, that is on the order of hundreds of millions of trial divisions, which is not suitable for a one-second limit. The problem has only one input value, so we can afford preprocessing over the entire range instead. The official limits are one second and 256 MB.

There are several small cases that can fool a solution based only on parity. For example, with input `4`, the answer is `4 3`. The number `4` is `2 × 2`, but `e = 2` is not relatively prime to it, so the first valid exponent is `3`. With input `6`, the answer is `6 5`. Here both `2` and `3` divide `6`, so neither can be used as `e`; `5` is the first valid choice. A careless implementation that always uses `3` for even `n` would incorrectly output `6 3`.

Another edge case is a square of a prime. For input `25`, the answer is `25 2`, because `25 = 5 × 5` has exactly two prime factors and `2` is coprime with it. A factor-counting routine that requires two distinct prime factors would incorrectly reject `25`. The definition explicitly allows the two prime factors to be equal.

The samples also show why the largest semiprime must be found before choosing `e`. For input `197`, the largest valid `n` is `194 = 2 × 97`, giving `e = 3`. Choosing a smaller odd semiprime merely because it has the convenient exponent `2` would violate the primary optimization criterion.

## Approaches

The straightforward solution is to start from `m` and move downward. For each candidate `n`, we can test whether it is semiprime by repeatedly trying divisors up to `sqrt(n)` and counting prime factors. The first semiprime encountered is necessarily the largest possible `n`, because every larger value has already been rejected. Once `n` is fixed, we can test `e = 2, 3, 4, ...` until finding one with `gcd(n, e) = 1`. This is correct because both choices are made in exactly the required priority order.

The problem is the repeated factorization. In the worst case, testing every candidate near `10^6` requires up to `sqrt(10^6) = 1000` trial divisors each. Summed over a range of size `m`, the work is approximately

`1 + sqrt(2) + ... + sqrt(m) = O(m sqrt(m))`,

which is about `6.7 × 10^8` divisor checks when `m = 10^6`, ignoring additional loop and arithmetic overhead. That is far beyond what a one-second Python solution should attempt.

The key observation is that we do not need to factor any individual large number from scratch. The only question we ask about every candidate is how many prime factors it has, counting multiplicity. Since all candidates are at most one million, we can compute that information for the entire range with a sieve.

A particularly convenient way to represent the information is `Omega(n)`, the total number of prime factors of `n` with multiplicity. For example, `Omega(12) = 3` because `12 = 2 × 2 × 3`, while `Omega(25) = 2` because `25 = 5 × 5`. Exactly the numbers with `Omega(n) = 2` are semiprimes.

We can first use the Sieve of Eratosthenes to identify every prime. For each prime `p`, every multiple of `p` contains at least one factor `p`, so we add one to `Omega` for all multiples of `p`. To count repeated copies of `p`, we repeat the same operation for `p^2`, `p^3`, and so on. Thus a number divisible by `p^k` receives one contribution from each of `p`, `p^2`, ..., `p^k`, exactly matching the exponent of `p` in its factorization.

After that preprocessing, scanning downward from `m` until `Omega[n] == 2` immediately gives the largest valid modulus.

There is also a useful structural shortcut for `e`. If `n` is odd, then `2` is automatically coprime to `n`, so the smallest possible exponent is `2`. If `n` is even, a semiprime must be `2p`. Usually `3` is coprime to `n`, so `e = 3`. The only exception is `n = 6`, where both `2` and `3` divide `n`, so `e = 5`. This also handles `n = 4`, where `3` is valid. Since a semiprime cannot have more than two prime factors, there are no other cases.

The brute-force works because it directly checks the definition, but fails when the same expensive factorization is repeated for many candidates. The observation that the upper bound is only `10^6` lets us sieve factor counts for the entire range once, turning the search for `n` into a linear scan.

| --- | --- | --- | --- |
| Brute Force | `O(m sqrt(m))` | `O(1)` | Too slow |
| Optimal | `O(m log log m)` | `O(m)` | Accepted |

## Algorithm Walkthrough

1. Read `m` and allocate a prime sieve and a byte array `omega` for the number of prime factors counted with multiplicity.
2. Run the Sieve of Eratosthenes up to `m`. A number remaining marked as prime after the sieve is exactly a prime that can contribute factors to later numbers.
3. For every prime `p`, visit all multiples of `p` and add one to their factor counts. Then visit multiples of `p^2`, `p^3`, and higher powers while they are at most `m`, adding another one at each power. This counts every occurrence of `p` in a factorization rather than merely counting distinct prime divisors.
4. Starting at `n = m`, move downward until `omega[n] == 2`. This is the first semiprime encountered from the top, so it is necessarily the maximum allowed `n`.
5. Choose `e` from the structure of this semiprime. If `n` is odd, use `e = 2`. If `n` is even and divisible by `3`, then the only possible semiprime in this situation is `n = 6`, so use `e = 5`. Otherwise use `e = 3`.
6. Print `n` and `e`. The selected exponent is smaller than `n`, is at least `2`, and is coprime to `n`.

Why it works: `omega[x]` is exactly the number of prime factors of `x`, counting repeated factors. Hence `omega[x] == 2` if and only if `x` is a semiprime under the problem's definition. The downward scan consequently returns the largest valid modulus. For an odd semiprime, `2` cannot share a prime factor with it. For an even semiprime, `n = 2p`; if `p != 3`, then `3` is coprime to `n`, while `n = 6` requires `5`. These are the smallest possible valid exponents in every case, so the resulting pair satisfies both optimization criteria.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    m = int(input())

    # Sieve of Eratosthenes.
    is_prime = bytearray(b'\x01') * (m + 1)
    if m >= 0:
        is_prime[0] = 0
    if m >= 1:
        is_prime[1] = 0

    p = 2
    while p * p <= m:
        if is_prime[p]:
            start = p * p
            count = (m - start) // p + 1
            is_prime[start:m + 1:p] = b'\x00' * count
        p += 1

    # omega[x] = total number of prime factors of x,
    # counting multiplicity.
    omega = bytearray(m + 1)

    for p in range(2, m + 1):
        if not is_prime[p]:
            continue

        power = p
        while power <= m:
            for x in range(power, m + 1, power):
                omega[x] += 1

            if power > m // p:
                break
            power *= p

    # Find the largest semiprime.
    n = m
    while n >= 4 and omega[n] != 2:
        n -= 1

    # Find the smallest valid e.
    if n & 1:
        e = 2
    elif n % 3 == 0:
        # The only even semiprime divisible by 3 is 6.
        e = 5
    else:
        e = 3

    print(n, e)

if __name__ == "__main__":
    solve()
```

The first part builds the primality sieve. The slice assignment marks all multiples of a discovered prime starting at `p * p`, which is the standard optimization because smaller multiples already have a smaller prime factor.

The `omega` array uses `bytearray` because a number below one million cannot have many prime factors. The largest possible value is achieved by repeatedly multiplying by `2`, so it is below `20`. A byte is more than sufficient and keeps memory usage very small.

For each prime `p`, the loop over `power = p, p^2, p^3, ...` is what distinguishes this from a sieve for the number of distinct prime factors. For example, when `p = 2`, the number `12` is visited at `2`, `4`, and not `8`, so it receives two contributions from the prime `2`. The prime `3` contributes once, giving `omega[12] = 3`.

The downward search starts at exactly `m`, because the primary objective is to maximize `n`. The condition `omega[n] == 2` directly encodes the semiprime definition, including squares such as `25`.

The exponent selection avoids a general-purpose GCD loop. For odd `n`, `e = 2` is always valid. For even `n`, a semiprime has the form `2p`. If it is divisible by `3`, then `p = 3` and `n = 6`, making `5` the first valid exponent. Otherwise `3` is coprime to `n`. In every case the chosen `e` is strictly smaller than `n`.

## Worked Examples

For Sample 1, the input is `197`. The largest semiprime at or below `197` is `194 = 2 × 97`. Since it is even but not divisible by `3`, the smallest valid exponent is `3`.

| `n` | `omega[n]` | Action |
| --- | --- | --- |
| 197 | 1 | Prime, reject |
| 196 | 4 | `2 × 2 × 7 × 7`, reject |
| 195 | 3 | `3 × 5 × 13`, reject |
| 194 | 2 | `2 × 97`, accept |

After finding `n = 194`, the exponent candidates begin with `2`, but `gcd(194, 2) != 1`. The next candidate is `3`, and `gcd(194, 3) = 1`, so the output is `194 3`.

This trace demonstrates that maximizing `n` has priority over minimizing `e`. Even though many smaller odd semiprimes could use `e = 2`, none can replace `194`.

For Sample 2, the input is `259`. The number itself is `7 × 37`, so it is already a semiprime.

| `n` | `omega[n]` | Action |
| --- | --- | --- |
| 259 | 2 | `7 × 37`, accept |

Because `259` is odd, `2` is automatically coprime to it, giving the output `259 2`.

This trace demonstrates the most direct case: when `m` is already a semiprime, the scan does not need to move at all, and an odd modulus immediately gets the smallest possible exponent.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | `O(m log log m)` | The prime sieve and prime-power factor counting require near-linear sieve work, followed by a linear downward scan. |
| Space | `O(m)` | The primality and `omega` arrays each contain `m + 1` entries. |

With `m < 10^6`, the preprocessing range is small enough for a sieve-based solution. The use of `bytearray` keeps the actual memory footprint far below the 256 MB limit, and the algorithm avoids the hundreds of millions of trial divisions required by repeated factorization. The one-second limit is consistent with a near-linear sieve, while a per-number square-root factorization is not.

## Edge Cases

For `m = 4`, the input is already the smallest possible case with a valid key. The factor count is `omega[4] = 2`, because `4 = 2 × 2`, so the scan stops immediately. Since `4` is even and not divisible by `3`, the algorithm chooses `e = 3`. The output is `4 3`. A solution that requires two distinct prime factors would incorrectly reject this modulus.

For `m = 6`, the scan again stops immediately because `6 = 2 × 3` and `omega[6] = 2`. The usual even-number rule cannot choose `3`, because `gcd(6, 3) = 3`, and `2` is also invalid. The special case detects that `6 % 3 == 0` and chooses `e = 5`. The output is `6 5`. This is the only semiprime where the generic even rule needs an additional exception.

For `m = 25`, the algorithm finds `25 = 5 × 5`, so the repeated-factor counting correctly gives `omega[25] = 2`. Because `25` is odd, `2` is coprime to it and is the smallest possible exponent. The output is `25 2`. This confirms that the sieve counts multiplicity rather than only distinct primes.

For `m = 197`, the values `197`, `196`, and `195` are rejected because their factor counts are `1`, `4`, and `3`, respectively. At `194`, the count becomes `2`, since `194 = 2 × 97`. The algorithm stops there, proving that no larger valid modulus was skipped. Since `194` is even and not divisible by `3`, `e = 3` is selected, giving `194 3`, exactly as required by the sample.
