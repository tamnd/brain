## Solution
## Problem Understanding

We are given an array of integers and need to compute four standard statistics from it: the arithmetic mean, the median, the mode, and the range. The required output consists of those four values in exactly that order, one per line. The original problem statement gives the array size and then all array values on the next line.

The mean is the sum of all values divided by the number of values. The median requires the values to be considered in sorted order. When the array length is odd, the median is the single middle value. When the length is even, it is the average of the two middle values. The mode is the value occurring most frequently, while the range is the difference between the largest and smallest values.

The published statement does not specify a numerical upper bound for (n), so we should not rely on a tiny input size. The time limit is one second and the memory limit is 256 MB. A solution that repeatedly scans the entire array for every element takes (O(n^2)) time and becomes unsuitable as (n) grows. Sorting gives us the median and the extrema in (O(n \log n)), while a frequency dictionary gives the mode in expected (O(n)). This comfortably leaves the dominant work at (O(n \log n)).

There are several small cases where careless implementations can produce the wrong result. For an array containing one value, such as `1` followed by `7`, the correct output is `7.0`, `7.0`, `7`, `0`. An implementation that assumes there are two distinct middle positions can mishandle the median.

An even-sized array is another common boundary case. For `4` followed by `1 2 3 4`, the correct output is `2.5`, `2.5`, `1`, `3`. The median is not one of the array elements here, so using `a[n // 2]` unconditionally would give `3` instead of `2.5`.

Repeated values are necessary for a meaningful mode. For `5` followed by `2 2 8 1 5`, the correct mode is `2`, because it appears twice while every other value appears once. This is also the supplied sample.

Negative values must also be handled correctly. For `3` followed by `-5 -5 -2`, the correct output is `-4.0`, `-5.0`, `-5`, `3`. Computing the range as `max - min` handles negative numbers naturally, whereas taking absolute values of individual elements would be incorrect.

The statement asks for a single mode but does not define a tie-breaking rule for multiple equally frequent values. The implementation below keeps the first value encountered among tied modes. The sample has a unique mode, and this is the natural behavior of a frequency scan that only replaces the current mode when a strictly larger frequency is found.

## Approaches

A direct brute-force solution can calculate the mean and range with one scan, sort the array to obtain the median, and then find the mode by checking every value against every other value. For each of the (n) array elements, we scan all (n) positions and count equal values. The mode computation alone performs exactly (n^2) equality checks in the worst case. The approach is correct because every possible value is examined and its complete frequency is counted, so the largest frequency must be found. Its weakness is the quadratic running time.

The brute-force works because every statistic has a simple definition, but the repeated frequency scans do unnecessary work. If the same value occurs many times, the algorithm counts that value again and again. A frequency dictionary fixes this by storing the count associated with each distinct value as we scan the array. Each occurrence then contributes to exactly one counter, so the entire mode computation becomes expected (O(n)).

The median creates the remaining non-linear part. Once the array is sorted, both the median and the range become direct indexing operations. Sorting also gives the minimum and maximum immediately. Thus one sort gives us all the order information we need, while the frequency dictionary handles repetition independently.

We can calculate the sum before sorting, because the sum does not depend on order. We can also build the frequency dictionary during the same initial scan. After that, sorting is the only (O(n \log n)) operation.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(n²) | O(n) | Too slow for large n |
| Optimal | O(n log n) | O(n) | Accepted |

## Algorithm Walkthrough

1. Read (n) and the (n) integers. We keep the array because the median requires its elements in sorted order.
2. Compute the sum while reading the values and build a frequency dictionary. The sum gives the mean directly, while the dictionary lets us determine the mode without repeatedly scanning the array.
3. Sort the array in nondecreasing order. After sorting, the smallest value is at index `0`, the largest is at index `n - 1`, and the middle positions are known.
4. Compute the mean as `sum / n`. Python's `/` operator produces a floating-point result, which also gives the desired form for cases such as an odd-sized array containing an integer mean.
5. Compute the median from the middle position when `n` is odd. When `n` is even, average the two central elements at indices `n // 2 - 1` and `n // 2`. The distinction is necessary because an even number of observations has two central values.
6. Find the mode by examining the frequency dictionary and retaining the value with the largest frequency. When frequencies tie, keep the first encountered value rather than replacing the current answer on an equal frequency.
7. Compute the range as `a[-1] - a[0]`. Sorting has already put the minimum and maximum at the two ends of the array, so no additional scan is necessary.
8. Print the mean, median, mode, and range on separate lines in the required order.

### Why it works

After sorting, the array is in exactly the order used by the definition of the median, so the selected middle value or pair of middle values is correct. The frequency dictionary contains the exact number of occurrences of every distinct value, so the value retained as the mode has maximum frequency. The first and last sorted elements are respectively the minimum and maximum, making their difference the range. The sum contains every input value exactly once, so dividing it by (n) gives the mean. Each statistic is consequently computed from the defining property of that statistic.

## Python Solution

```python
import sys
from collections import Counter

input = sys.stdin.readline

def solve():
    n = int(input())
    a = list(map(int, input().split()))

    total = sum(a)
    freq = Counter(a)

    a.sort()

    mean = total / n

    if n % 2 == 1:
        median = float(a[n // 2])
    else:
        median = (a[n // 2 - 1] + a[n // 2]) / 2.0

    mode = a[0]
    best_count = 0

    for value, count in freq.items():
        if count > best_count:
            best_count = count
            mode = value

    value_range = a[-1] - a[0]

    print(mean)
    print(median)
    print(mode)
    print(value_range)

if __name__ == "__main__":
    solve()
```

The first scan builds `total` and `freq`. Keeping these values before sorting avoids any need to recover frequencies from the sorted array later.

The call to `a.sort()` is the main (O(n \log n)) operation. Python sorts integers in ascending order, so `a[0]` and `a[-1]` can be used directly for the range.

The odd-sized median uses `a[n // 2]`. For example, when `n = 5`, this is index `2`, the third element. For an even size such as `n = 6`, the middle positions are indices `2` and `3`, which are exactly `n // 2 - 1` and `n // 2`.

The explicit `float` conversion in the odd median makes its type consistent with the even case. Thus an input whose median is an integer can still produce output such as `2.0`, matching the sample's representation.

The mode scan uses `>` rather than `>=`. This means a tied frequency does not overwrite the current mode. Python dictionaries preserve insertion order, so the selected tied mode is the first one whose frequency reaches the maximum during the scan.

Python integers have arbitrary precision, so there is no integer overflow issue when computing the sum or the difference between the endpoints.

## Worked Examples

### Sample 1

The supplied sample is:

```
5
2 2 8 1 5
```

The initial sum is `18`, and the frequency dictionary is `{2: 2, 8: 1, 1: 1, 5: 1}`. Sorting produces `[1, 2, 2, 5, 8]`.

| Step | Sorted array | Sum | Middle values | Mode | Range |
| --- | --- | --- | --- | --- | --- |
| Read values | `[2, 2, 8, 1, 5]` | 18 | not computed | not computed | not computed |
| Sort | `[1, 2, 2, 5, 8]` | 18 | `2` | `2` | `7` |
| Compute statistics | `[1, 2, 2, 5, 8]` | 18 | `2` | `2` | `7` |

The mean is `18 / 5 = 3.6`. Since the length is odd, index `5 // 2 = 2` gives the median `2`. The value `2` has the highest frequency, and the range is `8 - 1 = 7`. The resulting output is exactly the supplied sample output.

### Sample 2

For an even-sized example:

```
4
1 2 3 4
```

The frequency of every value is one, so the first value remains the mode under the tie behavior described above. Sorting does not change the array.

| Step | Sorted array | Sum | Middle values | Mode | Range |
| --- | --- | --- | --- | --- | --- |
| Read values | `[1, 2, 3, 4]` | 10 | not computed | not computed | not computed |
| Sort | `[1, 2, 3, 4]` | 10 | `2, 3` | `1` | `3` |
| Compute statistics | `[1, 2, 3, 4]` | 10 | `2.5` | `1` | `3` |

The mean is `10 / 4 = 2.5`. Because there are four elements, the median is `(2 + 3) / 2 = 2.5`. Every value occurs once, so the first encountered value, `1`, remains the selected mode. The range is `4 - 1 = 3`.

## Edge Cases

For a single-element array, the exact input is:

```
1
7
```

The sorted array is `[7]`. The sum is `7`, so the mean is `7.0`. Since the length is odd, index `1 // 2 = 0` gives median `7.0`. The only value has frequency one and is the mode, while the range is `7 - 7 = 0`. The output is `7.0`, `7.0`, `7`, `0`, so there is no attempt to access a nonexistent second middle element.

For an even-sized array, consider:

```
4
1 2 3 4
```

After sorting, the two middle values are at indices `4 // 2 - 1 = 1` and `4 // 2 = 2`, giving `2` and `3`. Their average is `2.5`. Using only the right middle position would incorrectly report `3`, which is why the parity check is necessary.

For repeated values, consider the supplied sample:

```
5
2 2 8 1 5
```

The frequency dictionary records two occurrences for `2` and one for every other value. The mode scan starts with the first encountered value, `2`, whose count is two, and no later count is larger. The result is consequently `2`. Sorting separately produces `[1, 2, 2, 5, 8]`, so the median remains `2` and the range is `7`.

For negative values, consider:

```
3
-5 -5 -2
```

The sum is `-12`, giving a mean of `-4.0`. The sorted array is `[-5, -5, -2]`, so the median is `-5.0`. The mode is `-5`, and the range is `-2 - (-5) = 3`. The subtraction of the two endpoints handles the signs directly and does not require any special case for negative numbers.

For tied frequencies, consider:

```
4
1 1 2 2
```

Both `1` and `2` occur twice. The problem statement asks for a singular mode but does not specify how such a tie should be resolved. The implementation uses the first encountered maximum, so it returns `1`. The remaining statistics are unaffected: the mean is `1.5`, the median is `1.5`, and the range is `1`. This behavior is deterministic and follows directly from the strict `>` comparison in the mode scan.
