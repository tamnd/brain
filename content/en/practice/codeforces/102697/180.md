## Solution
## Problem Understanding

A string is called boring when every character in it is either `a` or `b`. Given one non-empty string, we have to decide whether it satisfies that rule. The output is `YES` if no other character occurs, and `NO` as soon as at least one character outside `a` and `b` appears. The original problem has a 1 second time limit and 256 MB memory limit.

The key observation about the constraints is that the task only asks us to inspect the characters of one string. Even if the string is very long, an algorithm that processes every character once is linear in its length and is comfortably appropriate for a 1 second limit. There is no reason to build auxiliary structures or compare every pair of positions. A quadratic algorithm would perform roughly (n^2/2) character checks in the worst case, which quickly becomes impractical as the string grows.

There are a few small cases that commonly cause mistakes. For example, the input

```
a
```

must produce

```
YES
```

because the only character is allowed. A solution that accidentally requires both `a` and `b` to occur would incorrectly reject it.

The input

```
baaaaabba
```

must produce

```
YES
```

because repeated characters and any ordering of `a` and `b` are allowed. The condition is about which characters occur, not about their arrangement. This is also one of the official examples.

The input

```
baaaaabad
```

must produce

```
NO
```

because the final `d` is forbidden, even though every earlier character is valid. A careless implementation that only checks the beginning of the string could miss this violation.

Finally,

```
ccabbabbdd
```

must produce

```
NO
```

because both `c` and `d` are outside the allowed alphabet. We only need one invalid character to reject the entire string.

## Approaches

A straightforward brute-force interpretation is to repeatedly verify larger prefixes. Start with the first character, check whether that prefix contains only `a` and `b`, then check the first two characters, then the first three, and so on until the entire string has been checked. This is correct because the complete string is boring exactly when every one of its prefixes is boring. However, checking a prefix from scratch repeats almost all previous work. For a string of length (n), the total number of character inspections is

[
1 + 2 + 3 + \dots + n = \frac{n(n+1)}2,
]

which is (O(n^2)). For (n=10^5), that is about (5\times10^9) character inspections, far beyond what a 1 second limit can support.

The observation that removes this repetition is much simpler: the property is local to each character. We do not need to reconsider the characters that have already been checked. While scanning from left to right, if the current character is `a` or `b`, it cannot make the string invalid, so we continue. If it is anything else, the answer is already known to be `NO`, and the scan can stop immediately.

This turns the repeated prefix validation into one linear pass. The brute-force approach works because it eventually examines every character, but fails because it examines the same character many times. The single-pass approach keeps exactly the information that matters, whether every character seen so far belongs to the allowed set `{a, b}`.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(n²) | O(1) | Too slow for large n |
| Optimal | O(n) | O(1) | Accepted |

## Algorithm Walkthrough

1. Read the string and remove the trailing newline using `strip()`. The input contains no spaces, so this gives exactly the string that must be checked.
2. Scan the characters from left to right. For every character, test whether it is either `a` or `b`. This is sufficient because the definition places no restriction on position, frequency, or transitions between the two allowed characters.
3. If a character is different from both `a` and `b`, immediately print `NO` and stop. Once an invalid character exists, adding or inspecting other characters cannot make the existing string valid.
4. If the scan reaches the end without finding an invalid character, print `YES`. Every character has then been verified to belong to the allowed alphabet, which is exactly the definition of a boring string.

### Why it works

The invariant during the scan is that every character examined so far belongs to `{a, b}`. If the current character is also `a` or `b`, the invariant remains true. If the current character is anything else, the string contains a forbidden character and cannot be boring, so returning `NO` is correct. If the loop finishes, the invariant covers the entire string, proving that every character is allowed and the correct answer is `YES`.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    s = input().strip()

    for ch in s:
        if ch != 'a' and ch != 'b':
            print("NO")
            return

    print("YES")

solve()
```

The input is read once, and `strip()` removes the newline produced by `readline()`. Since the string is specified to contain no spaces, there is no ambiguity from using `strip()` here.

The loop directly implements the second and third steps of the algorithm. The condition uses two comparisons rather than relying on a larger character range, because only the exact characters `a` and `b` are valid. A character such as `c`, `A`, or `1` must all be rejected.

The `return` after printing `NO` is also deliberate. Once a forbidden character has been found, continuing the scan cannot change the answer. If no early return occurs, the loop has examined every character, so printing `YES` is justified.

There are no integer calculations, so integer overflow is irrelevant. The implementation also does not allocate any structure proportional to the input length beyond the string itself.

## Edge Cases

The single-character input `a` is handled by the loop inspecting one character, finding it valid, and reaching the end, which produces `YES`. The same reasoning gives `YES` for `b`. There is no requirement for both characters to appear.

For the input

```
baaaaabba
```

the algorithm examines `b`, then a sequence of `a` characters and `b` characters, and every character passes the allowed-character test. The loop finishes and prints `YES`. The ordering and repetition do not matter because the property depends only on membership in `{a, b}`.

For the input

```
baaaaabad
```

the algorithm accepts the initial `b` and all following `a` characters. When it reaches `d`, the condition `ch != 'a' and ch != 'b'` becomes true, so it immediately prints `NO`. The invalid character is near the end, but a left-to-right scan still catches it correctly.

For the input

```
ccabbabbdd
```

the first character, `c`, is already forbidden. The algorithm therefore prints `NO` after one iteration. It does not need to inspect the later `a` and `b` characters, because a string containing even one forbidden character cannot satisfy the definition.

For the boundary case

```
aaac
```

the first three characters preserve the invariant, while the fourth character violates it. The algorithm checks that final position rather than stopping at index `n - 2`, so it correctly prints `NO`. The corresponding valid case `aaab` reaches the end and prints `YES`.
