## Solution
## Problem Understanding

We are given three integer side lengths, `a`, `b`, and `c`. The task is to decide whether these three segments can be the sides of a non-degenerate triangle. The required output is `VALID` when they can form such a triangle and `INVALID` otherwise. The official problem uses a single test case, with no test-case count.

For three positive side lengths, the triangle inequality says that every side must be strictly shorter than the sum of the other two:

`a + b > c`, `a + c > b`, and `b + c > a`.

The input is tiny: there are exactly three numbers, so even a constant number of arithmetic operations is enough. There is no large `n` that would make quadratic or cubic algorithms relevant. The one-second time limit and 256 MB memory limit are consequently far more generous than necessary.

A careless implementation can fail at equality. For example, with

```
1 2 3
```

the answer is

```
INVALID
```

because `1 + 2 = 3`. These three segments can only form a straight line, not a non-degenerate triangle. Using `>=` instead of `>` in the wrong direction can accidentally accept this case.

Another edge case is an obviously dominant side:

```
1 5 1
```

The answer is

```
INVALID
```

because `1 + 1 < 5`. The two short sides cannot reach far enough to close the shape. This is the first official sample.

Equal sides are completely valid when their lengths are positive. For example,

```
5 5 5
```

produces

```
VALID
```

because every pair sums to `10`, which is strictly greater than the remaining side. A solution that assumes all three lengths must be different would be incorrect.

## Approaches

The most direct approach is to check the definition literally. We evaluate all three triangle inequalities, `a + b > c`, `a + c > b`, and `b + c > a`, and accept exactly when all three are true. This is correct because the triangle inequality is both necessary and sufficient for three positive lengths to form a non-degenerate triangle. The worst case performs exactly three additions and three comparisons, followed by a constant amount of boolean logic.

We can simplify the same reasoning further by observing that only the largest side needs to be checked. Suppose the three lengths are sorted as `x <= y <= z`. Since `z` is the largest side, the potentially difficult inequality is `x + y > z`. The other two inequalities are automatically true because `z >= y` and `z >= x`, while all side lengths are positive. Thus the problem reduces to finding the largest side and checking whether the other two sides have a sum strictly larger than it.

Because there are only three values, sorting takes constant time as well. In Python, sorting three integers is effectively constant work, and the resulting code is compact and resistant to ordering mistakes.

The brute-force and optimal approaches have the following costs.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(1) | O(1) | Accepted |
| Optimal | O(1) | O(1) | Accepted |

The distinction is not about asymptotic complexity here. Both approaches are easily fast enough. The optimized formulation is preferable because it exposes the mathematical structure of the triangle inequality and reduces three separate conditions to one.

## Algorithm Walkthrough

1. Read the three side lengths `a`, `b`, and `c`. There is only one test case, so no outer test-case loop is needed.
2. Find the largest of the three lengths and call it `z`. The remaining two lengths are `x` and `y`.
3. Check whether `x + y > z`. This is the only triangle inequality that can possibly fail once the sides are ordered, because `z` is the side most difficult to satisfy.
4. Print `VALID` if the inequality is true. Otherwise print `INVALID`. The comparison must be strict, since equality creates a degenerate straight line rather than a triangle.

### Why it works

After ordering the sides as `x <= y <= z`, consider the two inequalities involving the smaller sides. Since `x` and `y` are positive, `y + z > x` is automatically true because `z >= x` and adding the positive `y` makes the left side strictly larger. Similarly, `x + z > y` is automatically true because `z >= y` and `x` is positive. The only inequality that contains the largest side on the right is `x + y > z`. Hence checking this single condition is equivalent to checking all three triangle inequalities.

## Python Solution

```python
import sys
input = sys.stdin.readline

a, b, c = map(int, input().split())

x, y, z = sorted((a, b, c))

if x + y > z:
    print("VALID")
else:
    print("INVALID")
```

The input line is read with `input`, following the required fast-I/O pattern even though the input is only three integers. `map(int, ...)` converts the three tokens directly into integers.

Sorting produces `x <= y <= z`, which makes `z` the largest side. The only non-trivial condition is then `x + y > z`.

The strict `>` comparison is essential. With `1 2 3`, the expression becomes `1 + 2 > 3`, which is false, correctly producing `INVALID`. Using `>=` would incorrectly accept a degenerate triangle.

Python integers do not overflow, so the addition `x + y` remains safe even for very large integer inputs.

## Edge Cases

The equality case `1 2 3` is handled by sorting the values into `1, 2, 3` and testing `1 + 2 > 3`. The comparison is false because the two sides merely equal the third side. The program prints `INVALID`, correctly rejecting the degenerate shape.

The dominant-side case `1 5 1` becomes `1, 1, 5`. The algorithm computes `1 + 1 = 2`, so `2 > 5` is false and prints `INVALID`. No separate check is needed for the other two inequalities because the largest side is already known.

For the all-equal case `5 5 5`, sorting changes nothing. The algorithm checks `5 + 5 > 5`, which is true, so the answer is `VALID`. Equal lengths are not a special failure condition.

The input `4 5 6` demonstrates the valid case. After sorting, `4 + 5 = 9`, and `9 > 6` holds. The algorithm prints `VALID`, and the remaining inequalities are guaranteed by the fact that `6` is the largest positive side.

Finally, the large input with sides `10^18`, `10^18`, and `1999999999999999999` gives a useful boundary check. The sum of the smaller sides is exactly `2000000000000000000`, which is greater than the largest side by `1`, so the output is `VALID`. Python's arbitrary-precision integers make the calculation safe without any special overflow handling.
