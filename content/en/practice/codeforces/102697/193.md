## Solution
## Problem Understanding

We are given three positive integers (a), (b), and (c), describing the quadratic polynomial

[
y=ax^2+bx+c.
]

We must find every way to write this polynomial as a product of two binomials with positive integer coefficients:

[
(ax^2+bx+c)=(px+q)(rx+s),
]

where (p,q,r,s) are all positive integers. Each factorization must be printed in the form `(px + q)(rx + s)`, with coefficient (1) omitted, and the complete set of factorizations must be sorted in ASCII order. If no such factorization exists, we print `-1`. These are the requirements given by the current Codeforces Gym statement.

Expanding the two binomials gives

[
(px+q)(rx+s)=prx^2+(ps+qr)x+qs.
]

Consequently, every valid factorization must satisfy

[
pr=a,\qquad ps+qr=b,\qquad qs=c.
]

The statement does not publish numeric upper bounds for (a,b,c), so the useful way to reason about the constraints is through the arithmetic work performed by the algorithm. A direct search over all possible coefficients can require work proportional to the values themselves, which becomes unsuitable as the coefficients grow. The optimal method reduces the search to finding divisors of one integer, requiring only (O(\sqrt a)) divisor checks in the implementation below.

There are several edge cases that can silently break a straightforward implementation. First, the two factors are ordered in the output, so both `(2x + 2)(x + 3)` and `(x + 3)(2x + 2)` are different required outputs. For input `2 8 6`, both occur, and removing one as a duplicate would produce an incomplete answer.

Second, a coefficient equal to (1) must be printed as `x`, not `1x`. For input `1 17 60`, the correct output contains `(x + 12)(x + 5)` rather than `(1x + 12)(x + 5)`. A careless formatter can produce mathematically equivalent text that does not match the required output.

Third, a repeated factorization must not be printed twice when the two roots of the auxiliary quadratic coincide. For example, if the relevant value is (t) and the discriminant is zero, the two possible values of (t) are identical. Treating both as separate cases would duplicate every resulting factorization.

Finally, a quadratic can have integer roots but still fail the positive-coefficient requirement. The condition here is not merely that the polynomial has rational or integer roots. Every coefficient inside both binomials must be positive. For input `3 7 11`, the required output is `-1`, because no positive integers (p,q,r,s) satisfy all three coefficient equations.

## Approaches

The most direct approach is to choose the four coefficients of the two factors and test whether their product equals the original polynomial. Since (pr=a), we could try every positive divisor (p) of (a), derive (r=a/p), then try possible values for the constant coefficients and check the middle coefficient. A still simpler brute-force implementation could try every (p) from (1) through (a), every (q) from (1) through (c), and test the resulting factorization. That takes (O(ac)) operations in the worst case, which is already too large for coefficients that are even moderately big. Searching all four coefficients independently would be even worse.

The structure of the three coefficient equations gives a much stronger observation. Define

[
t=ps.
]

The other contribution to the middle coefficient is (qr), so

[
qr=b-t.
]

Now multiply these two quantities:

[
(ps)(qr)=pqrs.
]

Because (pr=a) and (qs=c),

[
pqrs=(pr)(qs)=ac.
]

Hence (t) must satisfy

[
t(b-t)=ac.
]

Rearranging gives a quadratic equation involving only (t):

[
t^2-bt+ac=0.
]

Its discriminant is

[
D=b^2-4ac.
]

This is the key reduction. Instead of searching over four unknown coefficients, we first determine the only possible values of (t=ps). They are

[
t=\frac{b\pm\sqrt D}{2}.
]

If (D<0), there are no real values of (t), so no factorization exists. If (D) is not a perfect square, (t) cannot be an integer, so again no positive-integer factorization exists. If the parity of (b+\sqrt D) is odd, the candidate (t) is not an integer either.

Once a valid (t) is known, we need to split it into (p) and (s), while simultaneously respecting (p\mid a) and (s\mid c). We can enumerate divisors (p) of (t). For every such (p), set

[
r=\frac ap,\qquad s=\frac tp.
]

The candidate is valid exactly when (r) is an integer and (s) divides (c), in which case (q=c/s). The resulting factorization is

[
(px+q)(rx+s).
]

There is no need to separately check the middle coefficient. Since (ps=t) and (qr=ac/t=b-t), the middle coefficient is automatically (b).

We only need to find divisors of (t), and every divisor can be found by checking integers up to (\sqrt t). Since (t\le ac), using (\sqrt a) as the divisor search bound after working with divisors of (a) gives a particularly convenient implementation. For each candidate (t), we enumerate divisors of (a) up to (\sqrt a), and for each divisor (p), check whether (p\mid t) and (t/p\mid c). Every valid ordered factorization appears exactly once.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | (O(ac)) | (O(1)) apart from output | Too slow |
| Optimal | (O(\sqrt a)) | (O(k)), where (k) is the number of answers | Accepted |

## Algorithm Walkthrough

1. Read (a), (b), and (c). We want to find all positive integers (p,q,r,s) satisfying (pr=a), (qs=c), and (ps+qr=b).
2. Compute the discriminant (D=b^2-4ac). If (D<0), there cannot be any integer value of (t=ps), so the answer is `-1`.
3. Compute the integer square root (d=\lfloor\sqrt D\rfloor). If (d^2\ne D), the discriminant is not a perfect square, so the possible values of (t) are not integers and there is no valid factorization.
4. Check the parity of (b+d). If it is odd, neither ((b+d)/2) nor ((b-d)/2) is an integer, so there is no valid factorization.
5. Construct the two possible values

[
t_1=\frac{b+d}{2},\qquad t_2=\frac{b-d}{2}.
]

Keep only positive values. If (D=0), these two candidates are equal, so keep only one copy.

1. For every candidate (t), enumerate divisors (p) of (a). We only need to inspect (p) up to (\sqrt a), because every divisor larger than the square root appears paired with a smaller divisor. Whenever (p\mid a), also consider (a/p) as a divisor.
2. For each divisor (p), require (p\mid t). Then set

[
s=\frac tp.
]

We need (s\mid c), because (s) is one of the two positive factors whose product is (c).

1. If both divisibility conditions hold, compute

[
r=\frac ap,\qquad q=\frac cs.
]

The four coefficients now satisfy (pr=a) and (qs=c). Since (t) was constructed as a root of (t(b-t)=ac), the remaining cross term also satisfies (ps+qr=b).

1. Add both divisor orientations when they are different. If (p) is a divisor found through the square-root enumeration, its paired divisor (a/p) represents a separate possible leading coefficient and must also be tested. This is what allows the algorithm to produce both `(2x + 2)(x + 3)` and `(x + 3)(2x + 2)`.
2. Convert every valid factorization into its required string representation, omitting coefficient `1` before `x`, and sort all strings lexicographically. Python's string ordering matches ASCII ordering for the characters used here.
3. Print the sorted strings. If no candidate was generated, print `-1`.

### Why it works

Every valid factorization ((px+q)(rx+s)) defines (t=ps). Its middle coefficient gives (ps+qr=b), while multiplying the two cross terms gives ((ps)(qr)=ac). Thus (t) must satisfy (t^2-bt+ac=0), so the discriminant test cannot discard a valid factorization.

Conversely, suppose a positive integer (t) satisfies (t(b-t)=ac). If we choose a divisor (p) such that (p\mid a), (p\mid t), and (t/p\mid c), then setting (r=a/p), (s=t/p), and (q=c/s) gives positive integers with (pr=a) and (qs=c). Furthermore,

[
qr=\frac ac\cdot s
]

can be expressed more directly as

[
qr=\frac{ac}{ps}=\frac{ac}{t}=b-t,
]

because (t(b-t)=ac). Hence (ps+qr=b), so the constructed factors multiply to the original polynomial. Every valid factorization has exactly such a (t) and such a divisor (p), so the enumeration is complete.

## Python Solution

```python
import sys
import math

input = sys.stdin.readline

def format_factor(coef_x, const):
    if coef_x == 1:
        return f"(x + {const})"
    return f"({coef_x}x + {const})"

def solve():
    a, b, c = map(int, input().split())

    disc = b * b - 4 * a * c

    if disc < 0:
        print(-1)
        return

    root = math.isqrt(disc)

    if root * root != disc:
        print(-1)
        return

    if (b + root) & 1:
        print(-1)
        return

    t1 = (b + root) // 2
    t2 = (b - root) // 2

    candidates = [t1]
    if t2 != t1:
        candidates.append(t2)

    answers = set()

    limit = math.isqrt(a)

    for t in candidates:
        if t <= 0:
            continue

        for d in range(1, limit + 1):
            if a % d != 0:
                continue

            p1 = d
            p2 = a // d

            for p in (p1, p2):
                if t % p != 0:
                    continue

                s = t // p

                if c % s != 0:
                    continue

                r = a // p
                q = c // s

                left = format_factor(p, q)
                right = format_factor(r, s)

                answers.add(left + right)

    if not answers:
        print(-1)
        return

    print("\n".join(sorted(answers)))

if __name__ == "__main__":
    solve()
```

The discriminant calculation implements the central reduction from the four factor coefficients to the single quantity (t=ps). Python integers have arbitrary precision, so expressions such as `b * b` and `4 * a * c` do not overflow even when the input coefficients are large.

`math.isqrt` is used instead of floating-point `sqrt`. A floating-point square root can round a large integer slightly above or below its true value, which could incorrectly classify a discriminant as a perfect square. `isqrt` gives the exact integer square root, so checking `root * root == disc` is reliable.

The parity check is necessary because the quadratic formula divides by (2). A perfect-square discriminant alone does not guarantee that (t) is an integer. For example, (b=5) and (d=2) would give ((5+2)/2=3.5).

The divisor loop only runs through `isqrt(a)`. Whenever `d` divides `a`, both `d` and `a // d` are tested. This avoids an easy completeness bug where only small divisors are considered. The same factorization can be represented with either binomial first, so both orientations have to remain available.

The `answers` set removes accidental duplicates. This is useful when the same factorization can be reached through two divisor enumeration paths. We sort only after all candidates have been generated, because the required ordering is textual ASCII order rather than numerical order of coefficients.

## Worked Examples

### Sample 1

For input `2 8 6`, the polynomial is

[
2x^2+8x+6.
]

The discriminant is

[
8^2-4(2)(6)=16,
]

so (d=4). The two possible values of (t) are (6) and (2).

For (t=6), the valid divisor choices produce the factorization `(2x + 2)(x + 3)` and its reversed ordering. For (t=2), they produce the other ordering pair.

| (t) | (p) | (s=t/p) | (r=a/p) | (q=c/s) | Factorization |
| --- | --- | --- | --- | --- | --- |
| 6 | 2 | 3 | 1 | 2 | `(2x + 2)(x + 3)` |
| 6 | 1 | 6 | 2 | 1 | `(x + 1)(2x + 6)` |
| 2 | 2 | 1 | 1 | 6 | `(2x + 6)(x + 1)` |
| 2 | 1 | 2 | 2 | 3 | `(x + 3)(2x + 2)` |

After ASCII sorting, the output is

```
(2x + 2)(x + 3)
(2x + 6)(x + 1)
(x + 1)(2x + 6)
(x + 3)(2x + 2)
```

The trace demonstrates why both roots of the auxiliary quadratic matter. Each root represents one possible value of the cross term (ps), and together they recover every valid orientation.

### Sample 2

For input `1 17 60`, the discriminant is

[
17^2-4(1)(60)=49,
]

so (d=7). The two values of (t) are (12) and (5).

| (t) | (p) | (s=t/p) | (r=a/p) | (q=c/s) | Factorization |
| --- | --- | --- | --- | --- | --- |
| 12 | 1 | 12 | 1 | 5 | `(x + 5)(x + 12)` |
| 5 | 1 | 5 | 1 | 12 | `(x + 12)(x + 5)` |

The leading coefficient is (1), so both factors have `x` rather than `1x`. Sorting gives

```
(x + 12)(x + 5)
(x + 5)(x + 12)
```

This example also shows why a factorization and its reversal are separate outputs even when both factors have the same leading coefficient.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | (O(\sqrt a + k\log k)) | We inspect divisors of (a) up to (\sqrt a), and sort (k) generated factorizations |
| Space | (O(k)) | The answer set stores the factorizations before sorting |

The divisor search is the expensive arithmetic part, and it is independent of (b) and (c) except for constant-time divisibility checks. The output itself can contain multiple factorizations, so storing and sorting those strings is unavoidable when the required order is lexicographic. Since the published statement does not provide explicit coefficient bounds, the complexity is best understood directly as (O(\sqrt a)) arithmetic search plus the cost of producing the required output.

## Edge Cases

A zero discriminant is handled by constructing only one candidate \(t\). For input `4 4 1`, we have

\[
D=4^2-4(4)(1)=0,
\]

so \(t=2\). The only valid split is \(p=2,s=1\), giving \(r=2,q=1\). The result is `(2x + 1)(2x + 1)`. If both quadratic-formula branches were processed without deduplication, the same answer would be generated twice.

For input `1 2 1`, the discriminant is \(0\) and \(t=1\). The only possible coefficients are \(p=r=q=s=1\), giving

\[
(x+1)(x+1)=x^2+2x+1.
\]

The formatter prints `x` instead of `1x`, which matches the required representation.

For input `3 7 11`, the discriminant is

\[
7^2-4(3)(11)=-83.
\]

The algorithm stops immediately because a negative discriminant cannot produce an integer \(t\). The output is `-1`.

For input `5 5 5`, the values are all equal, but the discriminant is

\[
25-100=-75.
\]

Again there is no possible positive-integer factorization, so the answer is `-1`. This catches the common mistake of assuming that similar or equal coefficients imply a factorization.

For input `2 8 6`, the algorithm deliberately considers both divisors in each divisor pair. Choosing \(p=2,s=3\) gives `(2x + 2)(x + 3)`, while choosing \(p=1,s=6\) gives `(x + 1)(2x + 6)`. Reversing the factor roles gives the other two required strings. The final sort puts these four strings into exactly the required ASCII order.
