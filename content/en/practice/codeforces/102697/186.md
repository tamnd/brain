## Solution
## Problem Understanding

The input is one line containing a noisy transcription of a radio message. Ordinary characters belong to the original message. Every piece of radio static is enclosed by an underscore, so a substring of the form `_static_` must be removed completely, including both underscores. The characters outside such regions form the answer.

For example, in `hello_***_hello`, the middle `***` is static, so the recovered message is `hellohello`. In `code ram_^_s^^^`, the substring `^` between the two underscores is static, while the spaces and letters around it are part of the message.

The statement does not give a separate numeric bound for the length of the line, so the useful constraint is simply that the input may be long enough that we should process each character only a constant number of times. An O(L) algorithm, where L is the line length, is optimal because even reading the input already costs O(L). An O(L²) solution can become too slow as the transcription grows.

There are a few boundary cases where implementations commonly go wrong. A line can begin with static, as in `_abc_code`, whose correct output is `code`. A careless solution that assumes the first character is always part of the message would incorrectly keep `abc`. A line can end immediately after static, as in `code_abc_`, whose output is `code`; an implementation that waits for another ordinary character before closing the static region can mishandle the final underscore. Multiple static regions can also be adjacent, as in `a_x__y_b`, where the two underscores between the static sections are separate delimiters and the result is `ab`. Finally, a line can contain spaces that are genuine message characters, as in `_noise_hello world_noise_`, whose output is `hello world`. Splitting on whitespace would destroy those spaces.

## Approaches

A direct but inefficient approach is to repeatedly search for the first underscore, search for the next underscore, and physically remove the whole static region from the current string. This is logically correct because every static region is precisely the text between a pair of underscores. The problem is the repeated string modification. If the input has length L and contains Θ(L) small static regions, each deletion can copy Θ(L) characters, giving Θ(L²) character operations in the worst case. For example, a line containing many alternating ordinary characters and one-character static regions can force the implementation to repeatedly rebuild almost the entire remaining string.

The structure of the input gives us a much simpler observation. While scanning from left to right, an underscore tells us whether we are entering or leaving static. Outside static, every character belongs to the answer. Inside static, every character should be ignored. Since the state changes only when an underscore is encountered, one boolean variable is enough to describe everything we need to know.

The brute-force approach works because it identifies exactly the same underscore-delimited regions, but it repeatedly modifies already processed data. The observation that static is represented by a simple alternating state lets us process the transcription once, append only characters seen outside static, and finish in linear time.

| Approach | Time Complexity | Space Complexity | Verdict |
|---|---|---|---|
| Brute Force | O(L²) | O(L) | Too slow |
| Optimal | O(L) | O(L) | Accepted |

## Algorithm Walkthrough

1. Read the entire line without removing spaces from the middle. The input represents a message, not a whitespace-separated list of tokens, so `input()` rather than `split()` is the appropriate operation.

2. Start with `inside_static = False`. Before seeing any underscore, characters belong to the original message.

3. Scan every character from left to right. If the character is an underscore, toggle `inside_static`. An underscore is a delimiter, so it is never copied to the answer.

4. If the character is not an underscore and `inside_static` is false, append it to the result. Such a character is outside static and is part of the recovered message.

5. If the character is not an underscore and `inside_static` is true, discard it. Every character inside a static region is noise.

6. After the scan, print the accumulated result. The delimiter structure guarantees that every static section has been skipped exactly between its opening and closing underscore.

The key invariant is that immediately before processing each character, `inside_static` is true exactly when the current position lies inside a static region. An underscore changes that state because it is precisely a boundary between message and static. Consequently, every non-underscore character is appended exactly when it belongs to the original message, and every static character is discarded exactly when it should be discarded.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    s = input().rstrip('\n')

    inside_static = False
    ans = []

    for ch in s:
        if ch == '_':
            inside_static = not inside_static
        elif not inside_static:
            ans.append(ch)

    print(''.join(ans))

if __name__ == "__main__":
    solve()
```

The call to `rstrip('\n')` removes only the line terminator. It deliberately does not use `strip()`, because leading or trailing spaces can be meaningful message characters.

The `inside_static` flag corresponds directly to the state in the algorithm walkthrough. Each underscore toggles it, so the first underscore enters static and the next one leaves static. This also handles an input beginning or ending with static without requiring special cases.

The result is stored in a list rather than repeatedly concatenating strings. Python strings are immutable, so repeated `ans += ch` can introduce unnecessary copying. Appending characters to a list is constant-amortized time, and `''.join(ans)` constructs the final string once.

There is no integer arithmetic, so overflow is irrelevant. The loop processes every input character once, and the only boundary condition is the underscore toggle, which avoids index calculations entirely.

## Complexity Analysis

| Measure | Complexity | Explanation |
|---|---|---|
| Time | O(L) | Every character is examined exactly once, and the final `join` is linear in the output size. |
| Space | O(L) | The result list stores at most one entry for every non-static character. |

Since reading an L-character input already requires O(L) work, the linear scan is asymptotically optimal. The algorithm also avoids repeatedly copying the remaining transcription, so its running time grows proportionally with the actual input size.

## Edge Cases

When the input begins with static, the state machine handles the boundary immediately. For `_abc_code`, the first underscore changes `inside_static` from false to true, `abc` is discarded, and the second underscore changes the state back to false. The characters `code` are then appended, giving `code`. No special case for the beginning of the string is required.

When the input ends after static, the closing underscore still toggles the state before the scan finishes. For `code_abc_`, `code` is appended, `abc` is ignored, and the final underscore returns the state to false. The answer is exactly `code`. There is no need to inspect a character after the closing delimiter, so an implementation based on adjacent indices is avoided.

For consecutive static regions, consider `a_x__y_b`. The first underscore enters static, the next leaves it, the following underscore immediately enters static again, and the final relevant underscore leaves it. The characters `x` and `y` are both discarded, while `a` and `b` are preserved. The result is `ab`. The toggle model naturally handles an empty message segment between two delimiters.

Spaces must be treated as ordinary characters unless they are inside static. In `_noise_hello world_noise_`, the first noisy region is discarded, both words and their separating space are appended, and the final noisy region is discarded. The output is `hello world`. This is why the program reads the whole line instead of splitting it into whitespace-separated tokens.

The same method also handles an input containing no underscores at all. For `hello world`, the state remains false throughout the scan, so every character is copied and the output is identical to the input. This is the simplest case of the invariant, with the scanner never entering static.
