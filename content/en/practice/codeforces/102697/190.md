## Solution
## Problem Understanding

We have a town containing (n) people. For every person, the input gives their name and the name of the person who infected them. Exactly one person has `OTHER` as their source, meaning their infection came from outside the town.

A person is called a superspreader if they directly infected at least three other people. The task is to print every superspreader in the same order in which the people appeared in the input. If nobody infected three or more people, we print `NONE`.

The key detail is that the problem asks about **direct** infections. If Alice infected Bob and Bob infected Cheryl, Alice is not credited with infecting Cheryl. We only count how many input records name a particular person as their immediate source.

The only explicit numerical constraint in the statement is that (n) is a positive integer. There is no upper bound stated on (n), so an algorithm should avoid anything that grows quadratically with the number of people. A single pass through the (n) records is the natural target. With (n) records, an (O(n^2)) approach can require about (n^2) name comparisons, while an (O(n)) approach only processes each record a constant number of times.

There are several small cases that can make a careless implementation fail.

Consider a town containing only the person who was infected from outside:

```
1
Alice OTHER
```

The correct output is:

```
NONE
```

There are no infection records naming Alice, so Alice infected nobody. An implementation that accidentally counts the `OTHER` record as an infection caused by Alice would produce the wrong result.

Consider three people infected by the same person:

```
4
Alice OTHER
Bob Alice
Cheryl Alice
Darryl Alice
```

The correct output is:

```
Alice
```

Alice has exactly three direct victims, so the threshold is inclusive. Testing `count > 3` instead of `count >= 3` would incorrectly reject her.

Finally, consider a chain:

```
4
Alice OTHER
Bob Alice
Cheryl Bob
Darryl Cheryl
```

The correct output is:

```
NONE
```

Every person infected exactly one other person. A solution that tries to count everyone reachable downstream from a person would incorrectly classify Alice, even though the definition only counts direct transmissions.

## Approaches

The most direct brute-force solution is to examine every person and scan all (n) infection records to count how many times that person's name appears as a source. This is correct because every direct infection appears exactly once as an input record, so the number of matching source names is exactly that person's number of direct transmissions. However, doing a full scan for every person requires (O(n^2)) comparisons. For (n) records, the worst case is on the order of (n^2) operations, which quickly becomes impractical as the input grows.

The structure of the input gives us a much simpler way to count. Each record has the form `victim source`, and the only information relevant to superspreaders is the source field. Whenever a source name appears, we can immediately increase that person's infection count. A dictionary gives constant expected time for this update, so the entire input can be processed in one pass.

The output order needs separate attention. Dictionary iteration order should not be used as the mechanism for deciding the required order. Instead, we keep the original input order of the people and perform the final filtering in that order. This directly matches the statement and also works regardless of how the dictionary is implemented.

The brute-force approach works because it repeatedly reconstructs each person's number of victims from the complete input. It fails because it repeats almost the same work for every person. The observation that every infection contributes to exactly one source count lets us aggregate all those repeated scans into a single pass.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | (O(n^2)) | (O(n)) | Too slow for large (n) |
| Optimal | (O(n)) expected | (O(n)) | Accepted |

## Algorithm Walkthrough

1. Read (n), then process the (n) infection records one by one. Store each person's name in the original input order because the final answer must preserve this order.
2. For every record `person source`, increment the count associated with `source`, except when `source` is `OTHER`. `OTHER` represents a source outside the town, so it is not a person who can be reported as a local superspreader.
3. After all records have been processed, scan the people in their original input order. A person is a superspreader exactly when their accumulated count is at least three, so append their name whenever the count reaches that threshold.
4. If the resulting list is empty, print `NONE`. Otherwise, print every stored superspreader on its own line.

The reason for separating counting from output is that a person's count is not necessarily complete when their own input record is read. Someone can appear as a source later in the input, so deciding whether a person qualifies before reading all records could produce an incorrect result.

### Why it works

After processing any prefix of the input, the dictionary count for a name equals the number of processed infection records whose source is that name. Each record represents exactly one direct infection, so every direct victim contributes exactly one increment to the correct source. After all (n) records have been processed, the count for every person is exactly their total number of direct victims. Filtering those counts with the condition `>= 3` therefore selects exactly the superspreaders. Since the final scan follows the original input order, the output order is also correct.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    people = []
    infected_by = {}

    for _ in range(n):
        person, source = input().split()
        people.append(person)

        if source != "OTHER":
            infected_by[source] = infected_by.get(source, 0) + 1

    answer = []

    for person in people:
        if infected_by.get(person, 0) >= 3:
            answer.append(person)

    if answer:
        sys.stdout.write("\n".join(answer) + "\n")
    else:
        sys.stdout.write("NONE\n")

if __name__ == "__main__":
    solve()
```

The `people` list preserves exactly the order in which names occur in the input. We need this because the statement specifies input order rather than alphabetical order or any other ordering.

The `infected_by` dictionary stores the direct infection count for each source. `get(source, 0)` handles both cases cleanly: a source seen for the first time starts at zero, while an existing source receives one more victim.

The `OTHER` check must happen before updating the dictionary. `OTHER` is not a town resident, so it cannot be a superspreader in this problem.

The final loop uses `infected_by.get(person, 0)` because many people may never appear as a source. Treating a missing name as count zero is exactly what we need.

There is no integer overflow concern in Python. The largest possible count is (n), and Python integers handle it directly. The implementation also avoids nested loops, which is the main performance issue in the brute-force solution.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | (O(n)) expected | Each record causes one dictionary update, followed by one scan of the (n) people. |
| Space | (O(n)) | The input order and dictionary can each contain up to (n) names. |

The algorithm performs only a constant amount of expected-time dictionary work per input record and one additional linear scan. Since the statement gives no upper bound beyond (n > 0), linear time is the appropriate target and avoids the quadratic behavior of repeatedly scanning the entire input.

## Edge Cases

The first edge case is a town with only the external infection source:

```
1
Alice OTHER
```

The algorithm stores Alice in `people`, but skips the `OTHER` source when updating `infected_by`. Alice consequently has an implicit count of zero. The final check fails the `>= 3` condition, so the output is `NONE`.

The second edge case is the exact threshold:

```
4
Alice OTHER
Bob Alice
Cheryl Alice
Darryl Alice
```

The three records with source Alice increment her count from zero to one, then two, then three. The final scan sees `infected_by["Alice"] == 3`, so Alice is printed. This catches the common mistake of using a strict `> 3` comparison.

The third edge case is a transmission chain:

```
4
Alice OTHER
Bob Alice
Cheryl Bob
Darryl Cheryl
```

The dictionary ends as `{Alice: 1, Bob: 1, Cheryl: 1}`. Alice has two people downstream from her, but only Bob was directly infected by Alice. Since every count is one, the output is `NONE`. This confirms that the algorithm matches the direct-infection definition rather than computing graph reachability.

The final edge case concerns output ordering:

```
8
Zoe OTHER
Amy Zoe
Bob Zoe
Cara Zoe
Dan Amy
Eve Amy
Fox Amy
Gus Bob
```

Zoe receives three direct infections, and Amy also receives three. Both qualify. Their names appear in that order in the input, so the final scan produces:

```
Zoe
Amy
```

Sorting the names would happen to give a different order, which is why preserving the original input sequence explicitly is safer than relying on alphabetical or dictionary order.
