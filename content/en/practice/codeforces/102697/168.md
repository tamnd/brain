## Solution
## Problem Understanding

The task is to print the first `n` rows of Pascal's Triangle. Row `i` contains exactly `i` integers. The first and last value of every row are `1`, while every interior value is obtained by adding the two values directly above it in the previous row. For example, after the first four rows have been constructed, the next row is `1 4 6 4 1`.

The input consists of one positive integer `n`, and the output must contain exactly `n` lines, with row `i` containing the `i` values belonging to that row of the triangle. This is the complete specification given by the problem. The official statement does not provide an upper bound for `n`, so the natural constraint comes from the output itself: printing `n` rows requires printing `1 + 2 + ... + n = n(n+1)/2` integers. Any accepted solution must spend at least Ω(n²) time simply producing those integers.

That output lower bound immediately rules out algorithms whose work is cubic or exponential in `n` once `n` becomes moderately large. A quadratic algorithm is the right target because it matches the amount of data that has to be printed. Memory can also be kept linear if rows are generated one at a time instead of storing the entire triangle.

There are a few boundary cases that are easy to mishandle. For `n = 1`, the output is just one line containing `1`. A solution that starts by constructing a "previous row" and then only prints newly generated rows could accidentally print nothing.

For example, the input

```
1
```

must produce

```
1
```

because the first row consists of a single `1`.

The first two rows also expose an indexing mistake:

```
2
```

must produce

```
1
1 1
```

There are no interior elements in either row. A loop that assumes every row has an interior section can accidentally omit the second row's values or access nonexistent elements.

Another common mistake is forgetting that the last value is always `1`. For

```
5
```

the fifth row is

```
1 4 6 4 1
```

not `1 4 6 4`. The recurrence only computes interior positions, so both boundaries must be added explicitly.

## Approaches

A straightforward brute-force solution can calculate every value independently as a binomial coefficient. The value in row `r`, using zero-based indexing, is `C(r, k)`. One way to calculate it without relying on a precomputed triangle is to evaluate the multiplicative formula for every coefficient separately. Even if symmetry is used so that only `k <= r/2` is calculated, the coefficient at position `k` requires Θ(k) arithmetic steps. Across all rows this gives

`Σ(r=0..n-1) Σ(k=1..floor(r/2)) Θ(k) = Θ(n³)`,

so the amount of arithmetic grows cubically while the required output contains only Θ(n²) values. The approach is mathematically correct, but it repeats work that neighboring coefficients could share.

The useful structure is that Pascal's Triangle is already defined by a local recurrence. Once row `r - 1` is known, every interior value of row `r` is obtained from two adjacent values in that previous row. There is no reason to recompute those values from scratch.

We can keep the current row in an array. The next row starts and ends with `1`, and every position between them is the sum of two adjacent elements of the current row. After printing the new row, it becomes the current row for the next iteration. Each row requires work proportional to its length, so constructing all rows takes Θ(n²), exactly matching the number of values that must be printed.

The brute-force works because each position really is a binomial coefficient, but it fails by rediscovering the same information repeatedly. The observation that adjacent rows are connected by a simple two-value recurrence reduces the work to the unavoidable output size.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(n³) | O(n) | Too slow for large `n` |
| Optimal | O(n²) | O(n) | Accepted |

## Algorithm Walkthrough

1. Read `n`, the number of rows that must be printed. We will generate exactly one row per iteration, so the loop naturally corresponds to the required output lines.
2. Start with an empty previous row. Before generating the first row there are no values above it.
3. For row length `length` from `1` through `n`, create a new row whose first and last values are `1`. These are always the boundary values of Pascal's Triangle, regardless of how many rows have already been constructed.
4. For every interior position, add the two neighboring values from the previous row. If the previous row is `[1, 3, 3, 1]`, for example, the next row's interior becomes `1 + 3`, `3 + 3`, and `3 + 1`, giving `[1, 4, 6, 4, 1]`.
5. Print the newly constructed row and replace the previous row with it. Only the immediately preceding row is needed to construct the next one, so retaining older rows would waste memory.

### Why it works

The invariant is that immediately before constructing row `i`, `previous` contains exactly row `i - 1` of Pascal's Triangle. The new row places `1` at both boundaries, which agrees with the definition of the triangle. Every interior position is computed as the sum of the two values directly above it, so each interior value also agrees with the definition. Thus the newly constructed row is exactly row `i`, and assigning it to `previous` restores the invariant for the next iteration. Since the algorithm starts with the first row and repeats this argument through row `n`, every printed row is correct.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    previous = []

    for length in range(1, n + 1):
        if length == 1:
            current = [1]
        else:
            current = [1] * length

            for j in range(1, length - 1):
                current[j] = previous[j - 1] + previous[j]

        sys.stdout.write(" ".join(map(str, current)) + "\n")
        previous = current

if __name__ == "__main__":
    solve()
```

The `previous` array stores exactly one completed row. For the first row, the special case `length == 1` creates `[1]`. For every later row, initializing the whole array with `1` handles both boundaries immediately.

The loop over `j` starts at `1` and stops before `length - 1`, because those are precisely the interior positions. For position `j`, the two values above it are `previous[j - 1]` and `previous[j]`. This indexing is the central off-by-one detail in the implementation.

After printing, `previous = current` makes the new row available for the next iteration. No earlier row is needed, so the algorithm never constructs a two-dimensional triangle.

Python integers do not overflow at a fixed machine width, which avoids the integer-overflow concerns that would arise in languages using fixed-width integer types. The values themselves become large as `n` grows, and their size is naturally reflected in the amount of work required to print them.

Using `sys.stdout.write` avoids repeatedly calling the higher-overhead `print` function for every row. The input contains only one integer, so the standard fast-input pattern is sufficient even though input processing is not the bottleneck.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | O(n²) | Row `i` requires O(i) work, and there are `n` rows. Printing itself also requires Θ(n²) values. |
| Space | O(n) | Only the current and previous rows are retained, and each contains at most `n` values. |

The quadratic running time is optimal in terms of the number of output elements because the required output itself contains `n(n+1)/2` integers. The linear auxiliary space is also sufficient because the recurrence only depends on the immediately preceding row. The official problem gives a 1 second time limit and 256 MB memory limit, so avoiding any cubic recomputation is the key performance requirement.

## Edge Cases

For `n = 1`, the algorithm enters the `length == 1` branch and constructs `[1]`. It immediately prints that row and finishes. There is no attempt to access `previous[j]`, so the empty previous row cannot cause an indexing error. The exact output is `1`.

For `n = 2`, the first iteration produces `[1]`. The second iteration initializes `[1, 1]` and the interior loop has no iterations because there is no interior position. The output is consequently

```
1
1 1
```

This handles the boundary where a row has exactly two elements.

For `n = 3`, the third row starts as `[1, 1, 1]`. Its only interior position is index `1`, which is replaced by `previous[0] + previous[1] = 1 + 1 = 2`. The final row becomes `[1, 2, 1]`, confirming that the interior loop's bounds include every interior element exactly once.

For the sample `n = 5`, the fifth iteration receives `[1, 3, 3, 1]` as `previous`. It calculates the three interior values as `1 + 3 = 4`, `3 + 3 = 6`, and `3 + 1 = 4`, while the two boundary values remain `1`. The result is exactly `1 4 6 4 1`.

For a large input such as `n = 1000`, the algorithm still stores only the previous row and the current row. The number of generated values is Θ(n²), which is unavoidable because all of them must be printed. The implementation does not recursively recompute coefficients or retain the entire triangle, so its work and auxiliary memory follow the intended quadratic and linear bounds.
