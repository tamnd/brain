## Problem Understanding

The problem describes several clients arriving for a haircut. For each client, we know the current hair length and the length they want after the haircut. We need to calculate how many inches of hair must be removed to change the current length into the requested length.

For a client with current length `a` and desired length `b`, cutting `x` inches leaves `a - x` inches. We want

`a - x = b`.

Solving for `x` gives

`x = a - b`.

So each test case is completely independent, and there is no interaction between clients. The official input contains `n` test cases, followed by one pair of integers for each client. The official statement does not give explicit upper bounds for the integer values, but since every test case requires only one subtraction, the size of the values does not affect the algorithmic complexity. Python integers also avoid fixed-width overflow.

The main edge case is when the client already has exactly the requested length. For example,

```
1
10 10
```

requires output

```
0
```

A careless solution that assumes every client needs a positive amount cut could incorrectly produce `1` or otherwise fail to handle the zero case.

Another boundary case is when only one test case is present. For example,

```
1
1 0
```

requires output

```
1
```

There is no special initialization needed for multiple cases, so the same subtraction handles this correctly.

The statement does not explicitly state what happens if the requested length is greater than the current length. Such a situation cannot be achieved by cutting hair, since cutting can only decrease the length. The mathematical quantity `current - desired` would then be negative. The intended problem context is that the requested final length is reachable by cutting, so the solution directly computes the required difference.

The original problem has a one-second time limit and a memory limit of 256 MB. Since each test case needs only constant work, even a very large number of test cases is handled in linear time with respect to the number of input pairs. There is no reason to use sorting, dynamic programming, graph algorithms, or any data structure.

## Approaches

A brute-force approach might try to simulate the haircut one inch at a time. For example, if a client's hair is 1,000,000 inches long and the desired length is 1 inch, such a simulation would perform 999,999 individual cutting operations. More generally, if the amount to remove is `d`, the simulation performs `d` operations, so its running time depends on the numerical values rather than on the number of test cases. With large input values, this can become unnecessarily slow.

The brute-force works because every simulated cut decreases the current length by exactly one until the desired length is reached. The problem does not actually require us to simulate those intermediate states, though. We only need the total amount removed.

The key observation is that the amount removed is exactly the difference between the initial and final lengths. If the initial length is `a` and the final length is `b`, then removing `a - b` inches changes the length directly from `a` to `b`. Thus the entire process can be replaced by one subtraction.

The brute-force works because it eventually computes the same difference, but fails when the difference is large. The observation that only the initial and final lengths matter lets us reduce each test case to constant-time arithmetic.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(a - b) per case | O(1) | Too slow when lengths are large |
| Optimal | O(1) per case | O(1) | Accepted |

## Algorithm Walkthrough

1. Read the number `n` of clients. We process each client independently because the haircut of one client has no effect on any other client.
2. For every client, read the current length `a` and requested final length `b`. These are the only two values needed to determine the answer.
3. Compute `a - b`. This is the amount that must be removed because the equation `a - removed = b` has the unique solution `removed = a - b`.
4. Print the computed difference immediately. There is no need to store previous test cases or maintain any global state.

### Why it works

For every client, let `x` be the amount of hair cut. After cutting, the hair length is `a - x`, and the required final length is `b`. Thus a valid haircut must satisfy `a - x = b`. Rearranging gives `x = a - b`, so the algorithm outputs exactly the required amount for every test case. Since the cases are independent, processing them one by one produces all required answers.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    ans = []

    for _ in range(n):
        current, desired = map(int, input().split())
        ans.append(str(current - desired))

    sys.stdout.write("\n".join(ans))

if __name__ == "__main__":
    solve()
```

The first line is read as the number of independent clients. The loop then executes exactly once for every input pair.

Inside the loop, `current - desired` directly implements the equation derived in the algorithm walkthrough. The answers are converted to strings and collected so that the program can write them all at once.

There is no off-by-one issue because the problem asks for the amount of hair removed, not the number of intermediate lengths visited. For example, going from 14 to 8 requires exactly `14 - 8 = 6` inches, not 5 or 7.

Python's integer representation also means there is no integer-overflow concern. The program uses only a few variables at a time, so its auxiliary memory remains constant apart from the output list.
