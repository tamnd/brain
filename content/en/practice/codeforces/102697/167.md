## Solution
## Problem Understanding

The task is a small arithmetic problem disguised as a Blackjack decision. We receive the two cards currently in the player's hand and must determine which card value would make the total exactly 21 on the next draw. A numeric card contributes its printed value, while 10, J, Q, and K all contribute 10. An ace normally contributes 11, but it can be reduced to 1 if counting it as 11 would make the hand exceed 21. If the existing two-card hand is already worth 21, the required output is `BLACKJACK`. If the missing value is 10, every ten-valued card is valid, so the required output is `FACE CARD/10`.

The input contains exactly two space-separated card representations. The statement guarantees that their total is at least 10, so the answer never requires a value larger than 11. There is no large input parameter here, so the usual concerns about an (O(n^2)) or even (O(n \log n)) algorithm do not arise. A direct constant-time calculation is more than sufficient, and even a small exhaustive search over all possible card types would still be constant time.

The only subtle part is handling aces consistently. Treating every ace as 11 without allowing the value to drop to 1 can produce an impossible total. For example, the input

```
A A
```

has an initial sum of 22 if both aces are blindly counted as 11, but the correct Blackjack value is 12 because one ace must become 1. The correct output is `9`. A careless implementation that simply computes `11 + 11` would instead calculate a negative required value.

Another boundary case is an existing total of exactly 21. For

```
A 10
```

the answer is `BLACKJACK`, not `0`, because the problem asks for the special output when the two-card hand is already 21. A program that always computes `21 - total` and prints that number would produce the wrong format.

The value 10 also has a special representation. For

```
3 8
```

the total is 11, so the missing value is 10. The correct output is `FACE CARD/10`, rather than `10`, because the required card can be a 10, Jack, Queen, or King.

Finally, when exactly one point is missing, the answer must be `A`. For

```
6 4
```

the total is 10 and the required value is 11, which is represented by an ace. Printing `11` would describe the numerical value but not the required card representation.

## Approaches

A natural brute-force approach is to try every possible card type as the next card. We could consider `A`, the cards `2` through `9`, `10`, `J`, `Q`, and `K`, compute the resulting hand value for each, and report a card whose value makes the total 21. There are only 13 card types, so this takes at most 13 candidate checks. It is completely correct because every possible next card is explicitly considered.

For this particular problem, that brute force does not actually become too slow. The input contains only two cards, and the number of possible card types is fixed. Its worst-case operation count is bounded by 13 candidate evaluations, so it is still (O(1)). A claim that this approach would time out would not be accurate for the given problem.

The simpler observation is that we do not need to enumerate anything. Once the current hand value is known, there is exactly one numerical value that reaches 21:

[
\text{needed} = 21 - \text{current}.
]

The only remaining work is translating that number back into the required card representation. A value of 1 means `A`, values from 2 through 9 are printed directly, and 10 is represented by `FACE CARD/10`. Since the current hand contains only two cards, calculating its value is also constant time.

The brute-force and direct approaches have the following complexity.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(1), at most 13 candidates | O(1) | Accepted |
| Optimal | O(1) | O(1) | Accepted |

The direct approach is preferable because it expresses the mathematical structure of the problem directly instead of checking possibilities that can be derived immediately.

## Algorithm Walkthrough

1. Read the two card strings and convert each one into its Blackjack value. A numeric card uses its integer value, `10`, `J`, and `Q` and `K` all become 10, and `A` initially contributes 11.
2. Keep track of how many aces were read while computing the initial total. This matters because an ace is the only card whose value can change after the total has been computed.
3. If the total exceeds 21 and there is an ace, subtract 10 from the total for one ace. With only two cards, at most one such adjustment is necessary for a valid non-busted hand. This changes one ace from 11 to 1.
4. If the resulting total is 21, print `BLACKJACK` and finish. The problem gives this two-card situation its own output.
5. Otherwise compute `needed = 21 - total`. The current total is at least 10, so the required value is small and falls into the supported card-value range.
6. If `needed` is 1, print `A`, because an ace can provide the required 11-point value when it does not cause the hand to exceed 21.
7. If `needed` is 10, print `FACE CARD/10`, because all four types `10`, `J`, `Q`, and `K` have the same value.
8. For every other required value, print the integer itself. Values from 2 through 9 correspond directly to their numbered cards.

The key invariant is that after the ace adjustment, `total` is the actual highest valid Blackjack value of the two-card hand. Every possible next card has a fixed contribution of 2 through 10, except that an ace can contribute 11 when the resulting hand remains at most 21. Since `needed` is exactly `21 - total`, the selected representation reaches 21 whenever such a card exists. The special outputs only change the representation of values 1, 10, and an already complete total of 21.

## Python Solution

```python
import sys
input = sys.stdin.readline

def card_value(card):
    if card == 'A':
        return 11
    if card in ('J', 'Q', 'K', '10'):
        return 10
    return int(card)

def solve():
    cards = input().split()

    total = 0
    aces = 0

    for card in cards:
        total += card_value(card)
        if card == 'A':
            aces += 1

    if total > 21 and aces:
        total -= 10

    if total == 21:
        print("BLACKJACK")
        return

    needed = 21 - total

    if needed == 1:
        print("A")
    elif needed == 10:
        print("FACE CARD/10")
    else:
        print(needed)

if __name__ == "__main__":
    solve()
```

The `card_value` function isolates the card parsing rules. Keeping the representation conversion in one place prevents the main algorithm from having to distinguish between all four ten-valued cards.

The loop computes the initial hand value and counts aces at the same time. The ace correction subtracts exactly 10, changing one ace from 11 to 1. Because the input has only two cards, there cannot be a situation requiring more than one such correction while keeping the hand at or below 21.

The `total == 21` check must happen before calculating the missing value. Otherwise the program would compute zero and print an invalid card representation instead of the required `BLACKJACK`.

The output cases correspond directly to the three non-numeric representations. An ace is printed for a required value of 1, the shared string is printed for 10, and ordinary values are printed as integers.

Python integers do not overflow, and the entire program uses only a constant amount of memory.

## Edge Cases

The ace case is the most significant edge condition. For

```
A A
```

the algorithm first calculates (11 + 11 = 22). Since that exceeds 21 and there is an ace, it subtracts 10, giving the valid Blackjack value 12. It then computes (21 - 12 = 9), so the output is `9`. The adjustment preserves the invariant that the stored total is a valid hand value rather than the sum obtained by blindly treating aces as fixed 11-point cards.

The already-complete hand is another special case. For

```
A 10
```

the total is 21, so the algorithm prints `BLACKJACK` before calculating `needed`. The same result occurs for `10 A`, and a ten-valued face card such as `K A` also gives 21.

The value 10 has several card representations. For

```
3 8
```

the total is 11, leaving exactly 10 points. The algorithm prints `FACE CARD/10`, covering all of `10`, `J`, `Q`, and `K` without having to choose one particular rank.

The ace output is triggered when the current total is 20. For

```
9 J
```

the total is (9 + 10 = 19), so the required value is 2 and the output is `2`. For

```
10 10
```

the total is 20, so the required value is 1 and the output is `A`. The implementation deliberately prints `A` rather than `11`, because the output describes a card, not merely its numerical contribution.

The lower input boundary is also handled naturally. Since the given total is guaranteed to be at least 10, the required value is never greater than 11. The direct subtraction consequently maps every valid answer into one of the supported representations without needing a separate case for an impossible large card value.
