## Solution
## Problem Statement

An engineering project has a target height `n` and a tolerance `k`. A project is accepted whenever its actual height lies within `k` units of the target, including both endpoints.

The task is simply to determine the smallest acceptable height and the largest acceptable height.

## Input

The input contains two positive integers. The first is the target height `n`, and the second is the allowed tolerance `k`. They are given on separate lines.

## Output

Print the lower acceptable height on the first line and the upper acceptable height on the second line.

## Problem Understanding

The acceptable interval is centered at `n`. Moving downward by the full tolerance gives the smallest allowed height, while moving upward by the same amount gives the largest allowed height. Consequently, the two values we need are simply `n - k` and `n + k`.

The official statement gives no upper bound for `n` or `k`, only that they are positive integers. The time limit is 1 second and the memory limit is 256 MB. Since the solution requires only two arithmetic operations and two outputs, its running time is constant regardless of how large the input values are. There is no reason to use loops, arrays, graph algorithms, or any other data structure.

The first edge case is when the tolerance is zero. For example,

```
5
0
```

produces

```
5
5
```

A careless solution that assumes the lower and upper limits must differ would be wrong, because zero tolerance means that only the target height is acceptable.

The second edge case is when the tolerance is larger than the target. For example,

```
2
5
```

produces

```
-3
7
```

The lower endpoint can be negative because the statement asks for `n - k` directly and does not impose a restriction that the computed lower limit must be positive. An implementation that clamps the answer to zero would silently change the required interval.

The third edge case is when `n` and `k` are equal. For example,

```
8
8
```

produces

```
0
16
```

The lower endpoint is exactly zero, so an implementation using a strict inequality instead of an inclusive interval would mishandle this boundary.

## Approaches

A brute-force approach could generate every acceptable height from `n - k` through `n + k`, then remember the first and last generated values. This is correct because the acceptable heights form one continuous inclusive interval. However, it performs exactly `2k + 1` iterations. If `k` is very large, that means an unnecessary amount of work even though the requested endpoints can be obtained immediately.

The brute-force works because the acceptable set is an interval, but it fails to exploit the fact that only its two endpoints are needed. The key observation is that the lower endpoint is exactly `k` below `n`, and the upper endpoint is exactly `k` above `n`. No intermediate height has to be examined.

This reduces the entire problem to two arithmetic expressions, `n - k` and `n + k`, followed by printing them.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(k) | O(1) | Unnecessary and potentially too slow |
| Optimal | O(1) | O(1) | Accepted |

## Algorithm Walkthrough

1. Read the target height `n` and tolerance `k`. Keeping the two values separate makes the endpoint formulas direct.
2. Compute the lower limit as `n - k`. This is the farthest acceptable height below the target.
3. Compute the upper limit as `n + k`. This is the farthest acceptable height above the target.
4. Print the lower limit followed by the upper limit, each on its own line, matching the required output order.

### Why it works

The definition of the tolerance says that every acceptable height is between `n - k` and `n + k`, inclusively. The smallest number in this interval is exactly `n - k`, and the largest number is exactly `n + k`. Since the algorithm outputs those two values directly, both required endpoints are correct.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())
    k = int(input())

    print(n - k)
    print(n + k)

if __name__ == "__main__":
    solve()
```

The first two lines read the target height and tolerance from their separate input lines. Python integers are suitable here because the statement does not impose a fixed upper bound on the values.

The two arithmetic expressions implement the endpoint calculations from steps 2 and 3 directly. There is no loop because no intermediate acceptable height affects the answer.

The two `print` calls deliberately preserve the required order. The lower endpoint must appear first, followed by the upper endpoint. There are no indexing or boundary issues because the interval endpoints are obtained directly rather than through an iteration.

## Edge Cases

When `k = 0`, the exact input is

```
5
0
```

The algorithm computes `5 - 0 = 5` and `5 + 0 = 5`, so the output is

```
5
5
```

The invariant that the two stored values are the exact endpoints of the tolerance interval still holds even when the interval contains only one integer.

When the tolerance is larger than the target, the exact input is

```
2
5
```

The algorithm first computes `2 - 5 = -3`, then `2 + 5 = 7`, producing

```
-3
7
```

Nothing in the endpoint definition requires the lower result to remain positive. The arithmetic must be performed without an artificial `max(0, ...)`.

When the target equals the tolerance, the exact input is

```
8
8
```

The lower endpoint is `8 - 8 = 0`, while the upper endpoint is `8 + 8 = 16`. The output is

```
0
16
```

This exercises the exact boundary between negative and nonnegative results and confirms that the subtraction is performed without an off-by-one adjustment.

When the input values are very large, the algorithm still performs exactly the same two operations. For example,

```

```

gives

```

1999999999999999999
```

Python's integer type handles these values without fixed-width overflow, and the algorithm does not allocate memory proportional to either number.
