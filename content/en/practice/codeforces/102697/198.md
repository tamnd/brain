## Solution
## Problem Understanding

We have a single-elimination tournament with a power-of-two number of teams. Each team has a seed, and the seeds determine the fixed bracket. In the first round, seed (s) plays seed (n-s+1). Winners then advance into the positions determined by the bracket, so an upset does not change the bracket itself, it only changes which team occupies a particular position. The input also gives the probability, in percent, that every team beats every other team.

The task is to calculate the probability that every team eventually wins the entire tournament, then print the teams in decreasing order of those probabilities. The probabilities must be sorted using their full precision and only rounded to the nearest integer when printing. The problem statement specifies that (n) is a positive power of two, but the published statement does not give a numeric upper bound for (n). Since the input already contains an (n \times n) probability matrix, reading the input costs (O(n^2)), so an algorithm substantially above quadratic quickly becomes impractical. The intended dynamic programming approach uses (O(n^2 \log n)) arithmetic operations, which is easily manageable for tournament-sized inputs.

The first non-obvious case is a tournament containing only one team. For example,

```
1
Solo
50
```

has the correct output

```
Solo 100
```

The self-match probability of 50 is not actually used. A team in a one-team tournament wins automatically, so treating the diagonal probability as a real match would give the wrong answer.

Another common edge case is a completely symmetric tournament. For example,

```
4
A B C D
50 50 50 50
50 50 50 50
50 50 50 50
50 50 50 50
```

has the correct output probability of 25 for every team. A careless implementation that uses the diagonal entry as an opponent, or that rounds probabilities before sorting, can disturb this symmetry.

A third edge case comes from the bracket layout itself. With four teams, the first-round games are seed 1 versus seed 4 and seed 2 versus seed 3. The second round is then the winner of those two games. The corresponding leaf order is therefore (1,4,2,3), not (1,2,3,4). With eight teams the order becomes (1,8,4,5,2,7,3,6). Using seed order directly would calculate the probabilities for a different tournament.

Finally, an answer can be exactly on a rounding boundary. If a team has probability (12.5%), the required printed value is 13. The sorting must happen before this rounding, because two close probabilities can round to the same integer even though their true ordering is different.

## Approaches

A direct brute-force solution can enumerate every possible tournament outcome. There are (n-1) games in a single-elimination tournament, and every game has two possible winners, so there are (2^{n-1}) possible complete outcome patterns. For each pattern, we can simulate the tournament, multiply the probabilities of its individual game results, and add that probability to the winning team's total. This is correct because every possible sequence of game winners is a mutually exclusive outcome, and the probability of the tournament champion is exactly the sum of the probabilities of all outcomes producing that champion.

The problem is the number of outcomes. Enumerating all of them requires (2^{n-1}) cases, and if each case is simulated through all (n-1) games, the worst-case number of game-resolution operations is exactly ((n-1)2^{n-1}). Even for (n=32), that is already more than 33 billion game operations. The exponential growth makes this approach unusable.

The useful observation is that we do not actually care about the complete history of a tournament. For a particular bracket position, all we need to know is the probability that each team reaches that position. Once those probabilities are known, we can calculate the probability that a specific team wins against the opponent emerging from the other half of the bracket.

Suppose a bracket block contains two smaller blocks. Let (p_i) be the probability that team (i) wins its smaller block. If team (i) is in the left block, the probability that it wins the combined block is

[
p_i \sum_j p_j P_{i,j},
]

where (j) ranges over teams in the right block and (P_{i,j}) is the probability that (i) beats (j). The same formula works for teams in the right block.

The brute-force method works because it considers every possible combination of these events. The observation that only the winner distribution of each smaller bracket matters lets us combine entire subtrees without enumerating their internal outcomes. We process the tournament one round at a time, keeping one probability for every team.

There is one structural detail to handle first. The seeds are not stored in the order in which their leaves occur in the bracket. We recursively construct the actual bracket order. For eight teams it is

[
[1,8,4,5,2,7,3,6].
]

Once the teams are arranged this way, every tournament round corresponds to combining adjacent blocks, which makes the dynamic programming straightforward.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | (O(n2^n)) | (O(n)) | Too slow |
| Optimal | (O(n^2\log n)) | (O(n^2)) | Accepted |

## Algorithm Walkthrough

1. Read the team names and the complete matrix of head-to-head win probabilities. Convert every matrix entry from a percentage into a number between 0 and 1, so multiplication directly represents probability multiplication.
2. Construct the actual leaf order of the tournament bracket. For an interval of consecutive seeds from (l) to (r), recursively construct the order of its lower half. Reflect every seed (x) across the interval using (l+r-x), then interleave the original and reflected orders. For example, the interval (1\ldots4) becomes ([1,4,2,3]), and (1\ldots8) becomes ([1,8,4,5,2,7,3,6]). This mirrors exactly how the stated seed pairings feed into later rounds.
3. Initialize the probability of every team winning its current one-team block to 1. At this point no match has been played, so every team reaches its own starting position with certainty.
4. Process block sizes (2,4,8,\ldots,n). For every block of the current size, split it into its left and right halves. The probability that team (i) wins the whole block equals its probability of winning its own half multiplied by the probability that it beats whichever team emerges from the opposite half.
5. For a team (i) in the left half, calculate

[
new_i = old_i
\sum_{j\in right} old_j P_{i,j}.
]

The sum is a weighted average over all possible opponents from the right half. The same calculation is performed for every team in the right half, using the left half as the possible opponent set.

1. Replace the old probability array with the newly calculated values and continue to the next block size. After the block size reaches (n), each probability represents the probability that the corresponding team wins the entire tournament.
2. Sort the teams by their unrounded tournament-winning probabilities in descending order. Keeping the unrounded values during sorting is required because the statement explicitly says rounding happens only after sorting.
3. Convert each probability to a percentage and round it to the nearest integer. Using `int(probability * 100 + 0.5)` implements the required half-up rounding for non-negative probabilities. Print the team name followed by this rounded percentage.

The key invariant is that after processing block size (2^k), `dp[pos]` is exactly the probability that the team stored at `order[pos]` wins every game required to become the winner of that (2^k)-team bracket block. The base case is true because a one-team block is won with probability 1. When two blocks are combined, every possible opponent from the other block is represented by its probability of emerging, and multiplying by the corresponding head-to-head probability gives the probability of that complete path. Summing over all possible opponents accounts for every mutually exclusive way the team can win the combined block. Thus the invariant remains true at every round, and at the final round it gives the desired championship probabilities.

## Python Solution

```python
import sys
input = sys.stdin.readline

def bracket_order(lo, hi):
    if lo == hi:
        return [lo]

    mid = (lo + hi) // 2
    left = bracket_order(lo, mid)

    # Reflect the seeds in the interval.
    right = [lo + hi - x for x in left]

    order = []
    for a, b in zip(left, right):
        order.append(a)
        order.append(b)

    return order

def solve():
    n = int(input())
    names = input().split()

    win = []
    for _ in range(n):
        row = list(map(int, input().split()))
        win.append([x / 100.0 for x in row])

    order = bracket_order(0, n - 1)

    # dp[pos] is the probability that order[pos] wins
    # its current bracket block.
    dp = [1.0] * n

    size = 2
    while size <= n:
        half = size // 2
        new_dp = [0.0] * n

        for start in range(0, n, size):
            middle = start + half
            end = start + size

            for i in range(start, middle):
                team_i = order[i]
                opponent_probability = 0.0

                for j in range(middle, end):
                    team_j = order[j]
                    opponent_probability += (
                        dp[j] * win[team_i][team_j]
                    )

                new_dp[i] = dp[i] * opponent_probability

            for i in range(middle, end):
                team_i = order[i]
                opponent_probability = 0.0

                for j in range(start, middle):
                    team_j = order[j]
                    opponent_probability += (
                        dp[j] * win[team_i][team_j]
                    )

                new_dp[i] = dp[i] * opponent_probability

        dp = new_dp
        size *= 2

    probability = [0.0] * n
    for pos, team in enumerate(order):
        probability[team] = dp[pos]

    teams = list(range(n))
    teams.sort(key=lambda i: (-probability[i], i))

    out = []
    for team in teams:
        rounded = int(probability[team] * 100.0 + 0.5)
        out.append(f"{names[team]} {rounded}")

    sys.stdout.write("\n".join(out))

if __name__ == "__main__":
    solve()
```

The `bracket_order` function is responsible only for translating seed numbers into physical bracket positions. Its recursive reflection is what turns the simple rule that seed (s) plays seed (n-s+1) into an ordering where every later round consists of adjacent blocks.

The `dp` array is indexed by bracket position rather than team number. Initially every entry is 1 because every team certainly occupies its own one-team block. During a round, `new_dp` is used instead of modifying `dp` in place. This is necessary because every calculation in the current round must use probabilities from the previous round. Updating in place would let one team see a probability that already includes the current round, producing an incorrect result.

The matrix is still indexed by the original team numbers, so `order[i]` and `order[j]` are used whenever a head-to-head probability is requested. This separation between bracket position and team identity prevents the most common indexing error in this problem.

The final `probability` array converts the bracket-position probabilities back to the original team numbering. Sorting then uses these exact floating-point values. The secondary seed index is only a deterministic tie breaker and does not affect the required ordering when probabilities differ.

All probabilities are non-negative, so adding `0.5` before converting to `int` performs the required nearest-integer rounding without Python's banker-rounding behavior. Python integers also have arbitrary precision, so there is no integer-overflow issue.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | (O(n^2\log n)) | There are (\log_2 n) rounds, and each round considers (O(n^2)) team-opponent pairs in total. |
| Space | (O(n^2)) | The probability matrix uses (O(n^2)) space, while the dynamic-programming arrays use (O(n)). |

The (n \times n) probability matrix already requires quadratic input space, so the (O(n^2)) storage is unavoidable for the given representation. The dynamic programming adds only linear extra space. The running time grows by a logarithmic factor for the tournament rounds, while avoiding the exponential (2^{n-1}) complete tournament outcomes of brute force.

## Edge Cases

For the one-team case,

```
1
Solo
50
```

`bracket_order(0, 0)` returns `[0]`. The round loop never executes because the initial block size is already larger than (n). The only team's probability remains 1, so the printed value is 100. The diagonal value 50 is never interpreted as an actual game.

For the deterministic two-team case,

```
2
A B
50 100
0 50
```

the bracket order is `[A, B]`. During the only round, A's previous probability is 1 and the probability of beating B is 1, so A receives probability 1. B receives (1 \times 0 = 0). The final output is `A 100` and `B 0`. This catches implementations that accidentally use the self-probability or reverse the matrix indices.

For the symmetric four-team case,

```
4
A B C D
50 50 50 50
50 50 50 50
50 50 50 50
50 50 50 50
```

the first round gives every team probability (0.5) of winning its pair. In the final, each team has probability (0.5) of reaching the final and then a weighted 50% chance of beating the opponent, giving (0.25). Every team consequently prints 25. This confirms the invariant that the probability stored for a team includes every game it has already needed to win.

For the bracket-order boundary, four seeds must appear as `[1,4,2,3]`, not `[1,2,3,4]`. The recursive construction first creates `[1,2]`, reflects it to `[4,3]`, and interleaves them to obtain `[1,4,2,3]`. Thus the first pair is seeds 1 and 4, exactly as required by the tournament rules. For eight seeds the same construction gives `[1,8,4,5,2,7,3,6]`, so an upset changes the team occupying a bracket position without changing which position advances to the next round.

For the large symmetric case with 64 teams, every team has championship probability (1/64), which is (1.5625%). The algorithm performs six rounds, doubling the block size each time, and the final probability remains (1/64) for every team. Since (1.5625) rounds to 2, every team is printed with probability 2. This exercises every dynamic-programming round and also confirms that probabilities are rounded only after the final sorting step.

The published problem statement gives the number of teams only as a positive power of two, without a numeric maximum, so the 64-team test above should be read as a representative large input rather than an asserted official maximum. The algorithm itself does not depend on a particular power of two, only on the bracket structure and the (n \times n) probability matrix.
