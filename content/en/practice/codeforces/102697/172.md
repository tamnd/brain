## Solution
## Problem Understanding

There are (n) people. Person (i) has a coat color and a boot color. During the fight, person (i) throws exactly one snowball at person (j) when the two people have different coat colors and different boot colors. A person never throws at themselves.

The task is to count all such ordered pairs ((i,j)). The direction matters: if person (i) can throw at person (j), that contributes one snowball, and the reverse throw is counted separately if it is also possible.

The input gives the number of people, followed by the (n) coat colors and the (n) boot colors in matching order. The output is the total number of snowballs thrown.

The published problem page gives a one-second time limit and 256 MB of memory, but does not expose an explicit upper bound for (n). That makes an (O(n^2)) solution unsafe, because the natural brute-force method examines every ordered pair. An (O(n)) solution is preferable and uses only frequency information, so its performance remains good even when (n) is large.

The first edge case is a single person.

```
1
red
blue
```

The answer is `0`. There is nobody else to throw at. A formula that simply counts people with different attributes must be careful not to count the person themselves.

A second edge case occurs when everyone has the same coat color but different boots.

```
3
red red red
blue green yellow
```

The answer is `0`. Every pair shares the same coat, so nobody is a valid target. A careless solution that only checks boot colors would incorrectly count all six ordered pairs.

The opposite situation is equally important.

```
3
red green blue
black black black
```

The answer is `0`, because every pair shares the same boots. The two conditions are both required.

Finally, people can share both attributes.

```
3
red red blue
black black green
```

The only valid ordered pairs are between the `red/black` group and the `blue/green` person, giving `2`. If we subtract people sharing coats and people sharing boots independently without correcting the overlap, the pair of people who share both attributes is subtracted twice.

## Approaches

The direct approach considers every ordered pair of distinct people. For each pair, compare their coat colors and boot colors, and add one to the answer precisely when both colors differ. This is correct because every possible throw corresponds to exactly one ordered pair, and every valid ordered pair contributes exactly one throw.

There are (n(n-1)) ordered pairs, so the brute-force solution performs (\Theta(n^2)) pair checks. For example, (n=100000) would mean (9,999,900,000) checks, far beyond what a one-second solution can reasonably perform.

The useful observation is that we do not actually care which particular person has a color. For a fixed person (i), suppose their coat color occurs (C_i) times, their boot color occurs (B_i) times, and the exact combination of their coat and boots occurs (P_i) times.

Among all (n) possible targets, (C_i) have the same coat and (B_i) have the same boots. We want to remove both groups. People who have both the same coat and the same boots were removed twice, so we add them back once. Thus the number of valid targets for person (i) is

[
n-C_i-B_i+P_i.
]

The person's own entry is already handled correctly by this formula. They belong to all three frequency groups, so their contribution is

[
1-1-1+1=0.
]

We can obtain all three frequencies with hash maps in one pass and then sum the formula for every person. The brute-force works because it explicitly tests every possible target, but fails because there are quadratically many pairs. The frequency observation lets us count all valid targets for an entire person without examining those targets individually.

An equivalent global derivation uses inclusion-exclusion. Start with (n(n-1)) possible throws, subtract ordered pairs sharing a coat, subtract ordered pairs sharing boots, and add back ordered pairs sharing both. If a color appears (k) times, it creates (k(k-1)) ordered pairs of distinct people. The per-person formula is simpler to implement because all required frequencies are immediately available.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | (O(n^2)) | (O(1)) | Too slow for large (n) |
| Optimal | (O(n)) expected | (O(n)) | Accepted |

## Algorithm Walkthrough

1. Read the number of people, their coat colors, and their boot colors. The three pieces of information at the same index describe one person, so we preserve their positions while counting frequencies.
2. Build a frequency map for coat colors. For every person, record how many people have the same coat.
3. Build a frequency map for boot colors. This gives the number of people who would be excluded because they share boots with each person.
4. Build a frequency map for pairs `(coat, boots)`. This is needed because people sharing both properties were counted in both exclusion groups.
5. For every person, calculate

[
n-\text{coat_count}-\text{boot_count}+\text{pair_count}.
]

This is inclusion-exclusion: start with every possible target, remove targets with the same coat, remove targets with the same boots, then restore targets removed twice.
6. Add these values to the answer and print the result. Each valid ordered pair is counted exactly once, from the perspective of its throwing person.

### Why it works

For each person (i), every possible target is initially included in the (n) candidates. Any target with the same coat must be removed, giving (n-C_i). Among the remaining candidates, we must also remove everyone with the same boots. The people sharing both coat and boots were removed by both operations, so they must be added back once. The resulting value (n-C_i-B_i+P_i) is exactly the number of people with both a different coat and different boots.

The person's own entry lies in all three frequency groups, so it contributes zero. Summing this exact count over every person counts every valid directed throw once and no invalid throw.

## Python Solution

```python
import sys
input = sys.stdin.readline

from collections import Counter

def solve():
    n = int(input())
    coats = input().split()
    boots = input().split()

    coat_count = Counter(coats)
    boot_count = Counter(boots)
    pair_count = Counter(zip(coats, boots))

    answer = 0

    for coat, boot in zip(coats, boots):
        answer += n - coat_count[coat] - boot_count[boot] + pair_count[(coat, boot)]

    print(answer)

if __name__ == "__main__":
    solve()
```

The three `Counter` objects correspond directly to the three frequencies from the algorithm. `coat_count[coat]` tells us (C_i), `boot_count[boot]` tells us (B_i), and `pair_count[(coat, boot)]` tells us (P_i).

The `zip` operation keeps the coat and boot belonging to the same person together. This is especially important when constructing the pair-frequency map, because counting coats and boots independently would lose the information about which combinations actually occur.

The expression

```
n - coat_count[coat] - boot_count[boot] + pair_count[(coat, boot)]
```

implements inclusion-exclusion directly. No special subtraction for the current person is necessary because the person's own combination is already accounted for by the formula.

Python integers do not overflow, so the answer is safe even if the number of ordered pairs is large. The input uses `sys.stdin.readline` as requested, although the input itself is small enough that ordinary input would also be sufficient.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | (O(n)) expected | Three frequency-map constructions and one pass over the people |
| Space | (O(n)) | The coat, boot, and pair frequency maps contain at most (n) distinct entries each |

The algorithm performs a constant amount of expected hash-map work for each person, so it scales linearly with (n). This avoids the quadratic pair enumeration that would become impractical for a large number of people, and the memory usage remains linear.

## Edge Cases

For a single person,

```
1
red
blue
```

the three frequencies are all one. The formula gives (1-1-1+1=0), so the algorithm correctly avoids counting a person throwing at themselves.

When every person has the same coat,

```
3
red red red
blue green yellow
```

each person has `coat_count = 3`. Their valid-target count is (3-3-1+1=0). Even though the boots are different, the shared coat is enough to prevent every throw.

When every person has the same boots,

```
3
red green blue
black black black
```

each person has `boot_count = 3`, giving (3-1-3+1=0). The shared boots eliminate every possible throw.

When several people share both properties,

```
3
red red blue
black black green
```

the first two people each have coat count two, boot count two, and pair count two. Their valid-target count is (3-2-2+2=1), corresponding to the `blue/green` person. The third person has one valid target, giving a total of `2`.

This last case is the main inclusion-exclusion trap. If the exact-pair frequency were not added back, the first two people would each incorrectly receive zero valid targets because their shared coat and shared boots would have been subtracted twice.
