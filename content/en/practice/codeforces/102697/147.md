## Problem Understanding

We are given the vertices of a convex polygon in their boundary order. Each vertex has integer coordinates, and the polygon may have arbitrary side lengths and angles. The task is to compute the exact area of the polygon and print it as a decimal number. The official constraints shown for this archived problem do not give a numerical upper bound for n, but the time limit is only 1 second and the memory limit is 256 MB. The polygon has more than three vertices, and no polygon edge is completely vertical. The convexity guarantee means every boundary turn has the same orientation, so the vertices describe one simple convex region rather than a self-intersecting polygon.

The absence of a stated coordinate bound means we should avoid floating-point geometry whenever an exact integer calculation is available. With integer coordinates, the doubled area of a polygon is always an integer, so we can compute that quantity using integer arithmetic and divide by two only when formatting the answer. Python integers also remove the overflow concern that would arise in fixed-width languages if the coordinates were large.

The main edge cases are caused by the fact that the answer may be an integer or a half-integer. For example,

```
40 02 02 10 1
```

has area 2, so the correct output is `2.0`. An implementation that always treats the answer as an integer would lose the required decimal representation.

A second example is the diamond from the first sample:

```
40 55 00 -5-5 0
```

Its area is 50, so the correct output is `50.0`. A careless implementation can obtain a negative signed area if the vertices are given clockwise rather than counterclockwise. The polygon is valid in either orientation, so the absolute value of the signed area is required.

A third useful case is a polygon whose doubled area is odd:

```
56 64 32 11 53 7
```

The correct output is `15.5`. Computing with integer doubled area avoids any rounding issue.

## Approaches

A direct triangulation approach is easy to derive. Choose one vertex, say P 0 ​, and split the convex polygon into the triangles (P 0 ​ ,P 1 ​ ,P 2 ​ ), (P 0 ​ ,P 2 ​ ,P 3 ​ ), and so on. Since the polygon is convex, every one of these triangles lies inside the polygon, and together they cover it exactly. We can calculate each triangle's area with a cross product and add the results.

That approach is already O(n), because a polygon with n vertices produces exactly n−2 triangles. A genuinely brute-force method that tries every possible triangulation would be much worse, since the number of triangulations of an n-gon is the Catalan number C n−2 ​, which grows exponentially. There is no reason to explore those possibilities because convexity gives us one particularly simple triangulation for free.

There is an even cleaner way to express the same geometry. The doubled signed area of triangle ABC is

(x A ​ y B ​ +x B ​ y C ​ +x C ​ y A ​ )−(y A ​ x B ​ +y B ​ x C ​ +y C ​ x A ​ ).

If we triangulate the polygon from P 0 ​, all terms involving P 0 ​ telescope when the triangle areas are added. What remains is exactly

i=0 ∑ n−1 ​ (x i ​ y i+1 ​ −y i ​ x i+1 ​ ),

where P n ​ =P 0 ​. This is the shoelace formula.

The important insight is that triangulation does not require us to explicitly construct the triangles. Their signed areas can be accumulated edge by edge. That reduces the implementation to one pass over the polygon, while retaining the exact integer arithmetic of the triangulation argument.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Explicit fan triangulation | O(n) | O(n) | Accepted |
| Shoelace formula | O(n) | O(n) | Accepted |

The shoelace implementation is preferable because it needs only the consecutive edges and has fewer opportunities for indexing mistakes.

## Algorithm Walkthrough

1. Read the n vertices in the order in which they appear around the polygon. Store their coordinates so that the final edge from the last vertex back to the first can be processed.
2. Initialize an integer accumulator `twice_area` to zero. We deliberately store twice the signed area, because the cross product naturally produces this value and avoids floating-point arithmetic.
3. For every vertex P i ​ =(x i ​ ,y i ​ ), let P j ​ be the next vertex, with j=(i+1)modn. Add

x i ​ y j ​ −y i ​ x j ​

to `twice_area`. This is the signed cross product of the two position vectors and represents twice the signed area contribution of the edge.
4. Take the absolute value of `twice_area`. Clockwise input gives a negative sum, while counterclockwise input gives a positive sum, but both describe the same geometric area.
5. Print `abs(twice_area) / 2`. Since the doubled area is an integer, the result is always either an integer or ends in `.5`. Printing with one digit after the decimal point gives the required decimal representation.

### Why it works

Consider the triangles formed by connecting every polygon vertex to the origin. The cross product for each boundary edge gives the signed area of the corresponding triangle. When these signed triangles overlap outside the polygon, their contributions cancel in pairs. The only uncancelled signed area is the polygon itself. Equivalently, the shoelace sum is exactly the sum of the signed areas of a fan triangulation, with all terms involving the chosen fan vertex cancelling. Taking the absolute value removes the dependence on whether the vertices are listed clockwise or counterclockwise.

## Python Solution

```python
Pythonimport sysinput = sys.stdin.readline

def solve():    n = int(input())    points = [tuple(map(int, input().split())) for _ in range(n)]
    twice_area = 0
    for i in range(n):        x1, y1 = points[i]        x2, y2 = points[(i + 1) % n]        twice_area += x1 * y2 - y1 * x2
    twice_area = abs(twice_area)
    print(f"{twice_area / 2:.1f}")

if __name__ == "__main__":    solve()
```

The first part reads and stores the vertices. Keeping the whole list makes the wraparound edge simple: `(i + 1) % n` maps the final vertex back to vertex zero.

The main loop implements the shoelace sum directly. The expression `x1 * y2 - y1 * x2` must not be replaced by an absolute value for each edge. Individual edges can have positive or negative signed contributions, and those signs are what make the cancellation work.

The absolute value is applied only after the complete sum has been computed. Applying it inside the loop would compute a different quantity and generally give the wrong area.

Python integers can grow as necessary, so the accumulator does not overflow even if the coordinate products are large. The final division is safe because the value is already exact before formatting. The problem asks for a decimal number, so `f"{twice_area / 2:.1f}"` prints both `50.0` and `15.5` correctly.

## Edge Cases

The first edge case is the smallest legal polygon. For

```
40 01 01 10 1
```

the cross contributions are `0`, `1`, `1`, and `0`, giving a doubled area of `2` and output `1.0`. The modulo expression `(i + 1) % n` is what correctly includes the final edge from `(0,1)` back to `(0,0)`.

The second edge case is an odd doubled area. For

```
40 03 02 10 1
```

the contributions are `0`, `3`, `2`, and `0`, so the doubled area is `5`. The algorithm prints `5 / 2 = 2.5`, showing why using integer doubled area is preferable to prematurely converting coordinates or partial areas to floating point.

The third edge case is clockwise input. For

```
40 00 23 23 0
```

the shoelace sum is `-12`, even though the geometric area is positive. The algorithm computes `abs(-12) = 12` and prints `6.0`. A solution that assumes the input must be counterclockwise would incorrectly print a negative area.

The final subtle case is the closing edge. If the implementation processes only pairs `(P_i,P_{i+1})` for `i < n-1`, it silently omits the edge from the last vertex to the first. For the unit square above, those three processed edges contribute only `1`, giving `0.5` instead of `1.0`. The modulo indexing includes exactly the missing edge and avoids a special-case branch.
