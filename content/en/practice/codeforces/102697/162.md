## Solution
## Problem Understanding

The input contains two linear equations, each already written in slope-intercept form, `y=mx+b`. The coefficient `m` is the slope of the line, while `b` only determines where the line crosses the y-axis. The task is to decide whether the two lines are parallel and print `PARALLEL` if they are, or `NOT PARALLEL` otherwise. The official statement explicitly guarantees that the coefficient of `x` appears before the `x` term, including when the coefficient is `1`.

Two non-vertical lines are parallel exactly when their slopes are equal. Thus, for equations `y=m1x+b1` and `y=m2x+b2`, the only value we need to compare is `m1` versus `m2`. The intercepts `b1` and `b2` do not affect the direction of the lines.

There is no large array or graph hidden in this problem. The input consists of exactly two equations, so the amount of computation is constant regardless of how large the coefficients are. The one-second time limit is consequently more than sufficient for an O(1) algorithm. Python integers also avoid overflow when the coefficients are large.

The main parsing edge case is a negative slope. For example:

```
y=-8x+3
y=-8x+1
```

The correct output is:

```
PARALLEL
```

A careless parser that assumes the coefficient consists only of positive digits could fail to read `-8` correctly. The minus sign must be included when extracting the substring before `x`.

Another edge case is a slope of `1`:

```
y=1x+5
y=1x-20
```

The correct output is:

```
PARALLEL
```

The statement specifically allows `m=1` to be written explicitly as `1x`, so the parser must not expect the coefficient to be omitted.

The intercept can also be negative without affecting the answer:

```
y=7x-100
y=7x+200
```

The correct output is:

```
PARALLEL
```

A solution that compares the complete equations, rather than their slopes, would incorrectly reject this case. Different intercepts simply mean the two parallel lines are located at different positions.

Finally, equations can have very large coefficients. For example:

```
y=1000000000000000000x+7
y=1000000000000000000x-9
```

The answer is still `PARALLEL`. There is no need for floating-point arithmetic, so there is no precision problem.

## Approaches

A literal brute-force approach would try to determine whether the two lines have the same direction by examining points on them. For example, one could choose many values of `x`, calculate the corresponding `y` values on both lines, and try to infer whether the two graphs stay at a constant vertical distance. The problem is that a line contains infinitely many points, so a literal search has no finite worst-case operation count. Even if we arbitrarily stopped after some fixed number of x-values, that would not constitute a mathematical proof that the lines are parallel.

The brute-force idea fails because it is examining consequences of the slope instead of the slope itself. The equations already give us the exact slope directly. In `y=mx+b`, `m` is the direction of the line, and parallel lines have exactly the same direction. The observation reduces the entire problem to extracting the coefficient immediately before `x` from each equation and comparing those two integers.

Because there are only two input strings, the parsing work is proportional to the length of those strings. If the input strings have length `L`, the running time is O(L), which is effectively constant for this problem. The algorithm uses O(1) additional space apart from the two input strings.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | Unbounded | O(1) | Too slow / Not a finite algorithm |
| Optimal | O(L), where L is the input length | O(1) | Accepted |

## Algorithm Walkthrough

1. Read the two equations as strings. We keep them as strings because the input is formatted as an equation such as `y=-8x+3`, not as a sequence of whitespace-separated integers.
2. Find the position of the character `x` in each equation. Everything between the initial `y=` and `x` is the slope.
3. Convert the extracted substring to an integer. Python's `int` correctly handles both positive and negative coefficients, so strings such as `17` and `-8` become the corresponding integer slopes.
4. Compare the two slopes. If they are equal, the two equations describe lines with the same direction, so print `PARALLEL`. Otherwise, print `NOT PARALLEL`.

### Why it works

For a line written as `y=mx+b`, the coefficient `m` is its slope. Two lines of this form are parallel exactly when their slopes are equal. The algorithm extracts exactly this coefficient from both equations and compares it without modifying or approximating it. The intercept is deliberately ignored because changing `b` translates a line vertically but does not change its direction. Thus the algorithm prints `PARALLEL` exactly for the cases required by the problem.

## Python Solution

```python
import sys
input = sys.stdin.readline

def slope(equation):
    x_pos = equation.index('x')
    return int(equation[2:x_pos])

def main():
    line1 = input().strip()
    line2 = input().strip()

    m1 = slope(line1)
    m2 = slope(line2)

    if m1 == m2:
        print("PARALLEL")
    else:
        print("NOT PARALLEL")

if __name__ == "__main__":
    main()
```

The `slope` function searches for `x`, since the statement guarantees that the coefficient of `x` appears before that character. The prefix `y=` occupies positions `0` and `1`, so `equation[2:x_pos]` contains exactly the slope.

Using `int` instead of floating-point conversion is deliberate. Slopes in the given format are represented as integer coefficients, and integer comparison is exact. There is no reason to introduce floating-point rounding into a problem that only asks whether two exact coefficients are equal.

The comparison happens after both slopes have been extracted. The intercept is never parsed because it cannot affect parallelism. The `.strip()` calls remove the newline read from standard input, although the substring extraction would also work without it because the newline appears after the `x` term and therefore does not enter the slope.

## Edge Cases

For a negative slope, consider:

```
y=-8x+3
y=-8x+1
```

The first `x` occurs after `y=-8`, so the extracted substring is `-8`. The second equation produces the same integer. The comparison succeeds and the output is `PARALLEL`. This catches parsers that accidentally discard the minus sign.

For an explicit slope of `1`, consider:

```
y=1x+5
y=1x-20
```

The substring before `x` is `1` in both equations. The algorithm does not special-case the coefficient, so it naturally produces `PARALLEL`. This follows the input format, which explicitly keeps `1` before `x`.

For different intercepts, consider:

```
y=7x-100
y=7x+200
```

The extracted slopes are both `7`. The algorithm never reads the intercepts, so it prints `PARALLEL`. Geometrically, the two lines have the same direction and are shifted relative to each other.

For very large coefficients, consider:

```
y=1000000000000000000x+7
y=1000000000000000000x-9
```

Both slope substrings convert to the same Python integer. Python integers have arbitrary precision, so the comparison remains exact and the output is `PARALLEL`. The algorithm does not perform multiplication or division, which also keeps the implementation simpler than trying to reason about numerical overflow.

For different slopes with otherwise similar equations, consider:

```
y=-1x+100
y=1x-100
```

The extracted values are `-1` and `1`. Since they differ, the output is `NOT PARALLEL`. This confirms that the algorithm compares the signed slope rather than merely comparing its absolute value.
