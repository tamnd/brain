## Solution
## Problem Understanding

We are given a positive integer (n) and an integer (k). We must print the (k) positive palindromic integers closest to (n). The ordering is determined first by the absolute distance from (n), and when two palindromes are equally far away, the smaller palindrome comes first. The number (n) itself is included when it is a palindrome, as shown by the sample with (n=6).

For example, around (600), the palindromes immediately surrounding it are (595) and (606). Their distances are (5) and (6), so they are the first two answers. The next lower and upper palindromes are (585) and (616), giving distances (15) and (16).

The published statement specifies a one-second time limit and 256 MB of memory, but does not expose explicit upper bounds for (n) and (k) in the statement currently available. That makes a solution that scans ordinary integers especially unattractive. More importantly, the output itself contains (k) numbers, so any solution must spend at least (\Omega(k)) time simply producing the answer. The natural target is consequently (O(k \log n)), or (O(kd)) where (d) is the number of decimal digits of (n).

Several boundary cases can make a simple implementation fail. If (n) is itself a palindrome, it must be printed first. For input `6 10`, the correct output begins with `6`, followed by `5`, `7`, `4`, `8`, and so on. An implementation that searches only for palindromes strictly smaller and strictly larger than (n) would incorrectly omit `6`.

The lower boundary is also special because only positive integers are allowed. For input `1 2`, the nearest positive palindromes are `1` and `2`. The ordinary predecessor of `1` is `0`, but `0` cannot be printed. A careless implementation that blindly accepts the predecessor would produce an invalid answer.

Crossing a power of ten is another common source of errors. For input `99 3`, the next palindrome is `101`, not a three-digit palindrome obtained by incorrectly mirroring a prefix that no longer has the original length. Similarly, for `1000`, the previous palindrome is `999`, while the next one is `1001`.

Finally, ties must be resolved by the smaller number. For input `10 3`, the closest palindromes are `9` and `11`, both at distance (1), so `9` must be printed first. A comparison based only on distance would leave the output order unspecified and can fail the judge.

## Approaches

The direct approach is to start at (n), move outward one integer at a time, and test every integer for being a palindrome. Whenever a palindrome is found, it is added to the answer until (k) palindromes have been collected. This is correct because every positive integer is examined in increasing distance from (n), and the smaller number is encountered first when distances are equal.

The problem is that palindromes are sparse. For a (d)-digit range, there are only about (10^{\lceil d/2\rceil}) palindromes, so a search can pass through a very large number of non-palindromic integers before finding enough answers. If the farthest selected palindrome is at distance (R), the brute-force method performs (\Theta(R)) palindrome checks. Checking one number costs (O(d)), giving (\Theta(Rd)) digit operations. Since (R) is not bounded by (k), this can be much larger than the unavoidable (O(k)) output cost.

The key observation is that palindromes of a fixed digit length are completely determined by their first half, including the middle digit when the length is odd. Once that prefix is chosen, the remaining digits are forced by reflection. This means we do not need to search through ordinary integers at all. We can jump directly from one palindrome to the previous or next palindrome.

For a number such as `753`, take the first two digits, `75`, because (\lceil 3/2\rceil=2). Mirroring this prefix gives `757`, the smallest palindrome at or near the original prefix. Decreasing the prefix to `74` gives `747`, and decreasing again gives `737`. Increasing it gives `767`, then `777`, and so forth. These are exactly the palindromes surrounding `753` in numeric order.

Once we can obtain the immediate predecessor and successor palindrome of any value, the remaining task becomes a two-way merge. Keep one candidate below (n) and one above (n). At every iteration, compare their distances from (n). Output the closer one, and on a tie output the smaller one. Then replace that side with its next palindrome. Because palindromes on each side are generated in sorted order, this produces the global order required by the problem.

| Brute Force | (O(Rd)), where (R) is the required search radius | (O(k)) | Too slow when palindromes are sparse |
| Optimal | (O(kd)) | (O(k+d)) | Accepted |

## Algorithm Walkthrough

1. Convert (n) to a decimal string and determine its length. We work with decimal prefixes because a palindrome is defined by mirroring its first half.
2. Construct the palindrome obtained by taking the first (\lceil d/2\rceil) digits of (n) and reflecting them across the center. This gives the palindrome whose defining prefix is exactly the prefix of (n).
3. To find the largest palindrome strictly smaller than a value (x), first construct the palindrome from (x)'s prefix. If that palindrome is already smaller than (x), it is the answer. Otherwise decrement the prefix by one and mirror it again. Decreasing the prefix is the smallest possible change to the most significant part that can make the palindrome smaller.
4. To find the smallest palindrome strictly greater than (x), construct the palindrome from (x)'s prefix. If it is greater than (x), it is the answer. Otherwise increment the prefix by one and mirror it. This gives the smallest possible larger palindrome.
5. Initialize the lower candidate as the predecessor of (n) and the upper candidate as the successor of (n). If (n) itself is a palindrome, print it first and then continue with these two strict neighbors. The samples show that (n) counts as one of the requested palindromes.
6. Compare the lower and upper candidates by the pair `(distance, value)`. The candidate with the smaller pair is exactly the one required next, because distance is the primary ordering criterion and value is the tie breaker.
7. After printing the lower candidate, replace it with the next palindrome strictly below it. After printing the upper candidate, replace it with the next palindrome strictly above it. Repeat until (k) palindromes have been produced.
8. If the lower side reaches zero, mark it as unavailable. Zero is not a valid output, so all remaining answers must come from the upper side.

The invariant is that before every iteration, `lower` is the largest not-yet-printed positive palindrome below (n), while `upper` is the smallest not-yet-printed palindrome above (n). Every unprinted palindrome on the lower side is no larger than `lower` and hence no closer to (n) than it, and the same property holds symmetrically for `upper`. Thus the closest remaining palindrome must always be one of these two candidates. Comparing them by `(distance, value)` selects exactly the required next answer.

## Python Solution

```python
import sys
input = sys.stdin.readline

def make_pal(prefix: int, length: int) -> int:
    s = str(prefix)
    if length % 2 == 0:
        return int(s + s[::-1])
    return int(s + s[-2::-1])

def prev_pal(x: int) -> int:
    s = str(x)
    length = len(s)
    half = (length + 1) // 2
    prefix = int(s[:half])

    p = make_pal(prefix, length)
    if p < x:
        return p

    prefix -= 1

    if prefix == 0:
        return 0

    return make_pal(prefix, length)

def next_pal(x: int) -> int:
    s = str(x)
    length = len(s)
    half = (length + 1) // 2
    prefix = int(s[:half])

    p = make_pal(prefix, length)
    if p > x:
        return p

    prefix += 1

    if prefix == 10 ** half:
        return 10 ** length + 1

    return make_pal(prefix, length)

def solve():
    n, k = map(int, input().split())

    answer = []

    if str(n) == str(n)[::-1]:
        answer.append(n)

    lower = prev_pal(n)
    upper = next_pal(n)

    while len(answer) < k:
        if lower <= 0:
            answer.append(upper)
            upper = next_pal(upper)
            continue

        if upper <= 0:
            answer.append(lower)
            lower = prev_pal(lower)
            continue

        dl = n - lower
        du = upper - n

        if dl <= du:
            answer.append(lower)
            lower = prev_pal(lower)
        else:
            answer.append(upper)
            upper = next_pal(upper)

    sys.stdout.write("\n".join(map(str, answer)))

if __name__ == "__main__":
    solve()
```

`make_pal` is the central construction routine. For an even number of digits, the entire prefix is reflected. For an odd number of digits, the last prefix digit is the center and must not be duplicated, so `s[-2::-1]` reflects everything before the center.

`prev_pal` first mirrors the current prefix. If the resulting palindrome is already below `x`, no smaller change can produce a closer palindrome. Otherwise, the prefix is decremented once. If that makes the prefix zero, there is no positive palindrome with the same number of digits below the current value, so returning `0` marks the lower side as exhausted.

`next_pal` follows the symmetric logic. If incrementing the prefix would create a new number of digits, the next palindrome has the form `100...001`. For example, after `999`, incrementing the defining prefix crosses the length boundary and produces `1001`.

The main loop treats the lower and upper sequences as two sorted streams. The comparison `dl <= du` deliberately uses `<=`, not `<`. When the distances are equal, choosing the lower candidate implements the problem's requirement that the smaller palindrome comes first.

Python integers have arbitrary precision, so the implementation does not have a fixed-width overflow issue. The only potentially expensive operation is converting and mirroring a decimal prefix, whose cost is proportional to the number of digits.
