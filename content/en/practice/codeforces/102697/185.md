## Solution
## Problem Understanding

A number is called pleasing when every prime factor appearing in its factorization is either 2 or 3. Equivalently, the number must have the form

[
2^a3^b
]

for some non-negative integers (a) and (b). The value 1 also qualifies because it has no prime factors at all.

For example, 18 is pleasing because (18=2\cdot3^2), while 35 is not because (35=5\cdot7). The task is simply to determine whether the given positive integer has this property and print `YES` or `NO`. The original problem has a single integer input, with (n\le1000), a 1 second time limit, and a 256 MB memory limit.

The bound of 1000 makes even a simple trial-division solution easily fast enough. A loop checking every possible divisor performs at most about 1000 iterations, so there is no need for advanced number theory. Still, there is a cleaner solution that directly follows the definition: repeatedly remove every factor of 2 and every factor of 3. If anything larger than 1 remains, that remainder contains a forbidden prime factor.

There are a few small cases where an implementation can silently go wrong. For input `1`, the correct output is `YES`, because 1 has no prime factors. A solution that insists on finding at least one factor of 2 or 3 would incorrectly reject it.

For input `6`, the correct output is `YES`, since (6=2\cdot3). A careless solution that checks whether the number is divisible by exactly one of 2 and 3 could reject it, even though both factors are allowed.

For input `12`, the correct output is `YES`, because (12=2^2\cdot3). The divisions have to be repeated until no factor remains. Dividing by 2 only once would leave 6 and could incorrectly conclude that 6 contains an unwanted factor.

For input `1000`, the correct output is `NO`. We can remove three factors of 2 and obtain 125, but 125 contains the prime factor 5. A solution that only checks divisibility by 2 and stops after finding it would incorrectly accept the number.

## Approaches

The most direct brute-force approach is to test whether (n) has any prime divisor other than 2 or 3. We could try every integer (d) from 2 through (n), determine whether (d) divides (n), and, when it does, determine whether (d) is prime and different from 2 and 3. If such a divisor exists, the answer is `NO`; otherwise it is `YES`. This is correct because every composite number has a prime divisor, so a forbidden prime factor must eventually be discovered.

For (n=1000), this brute force needs at most 999 divisor checks, plus any primality work used for those divisors. That is already comfortably within the limits, so this problem does not actually require an optimization for acceptance.

The more useful observation is that we do not need to discover the prime factors one by one. The definition says that every factor must be 2 or 3, so we can remove exactly those factors and inspect what survives. Starting with (n), repeatedly divide by 2 while possible, then repeatedly divide by 3 while possible. If the final value is 1, the entire factorization consisted of 2s and 3s. If the final value is greater than 1, that remaining value must contain at least one prime factor other than 2 or 3.

The brute-force works because it explicitly searches for forbidden factors, but fails to use the special structure of the allowed factors. The observation that the only permitted primes are 2 and 3 lets us strip those factors directly, reducing the work to logarithmically many divisions.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(n) divisor checks, with extra work if primality is tested | O(1) | Accepted for (n\le1000) |
| Optimal | O(log n) | O(1) | Accepted |

## Algorithm Walkthrough

1. Read the positive integer (n). We keep the number itself rather than constructing its complete prime factorization because only the presence of forbidden factors matters.
2. While (n) is divisible by 2, divide it by 2. Every such division removes one allowed prime factor and cannot change whether the original number is pleasing.
3. While (n) is divisible by 3, divide it by 3. Repeating the operation removes all remaining allowed factors of 3.
4. Check the remaining value. If it is exactly 1, every prime factor of the original number was 2 or 3, so print `YES`. Otherwise, some factor other than 2 or 3 remains, so print `NO`.

Why it works: after the first two loops, the current value has no factor of 2 and no factor of 3. Every division performed before that removed only allowed factors. If the remaining value is greater than 1, its prime factorization must contain a prime other than 2 or 3, which makes the original number non-pleasing. If the remaining value is 1, nothing except factors of 2 and 3 was needed to construct the original number, so the number is pleasing.

## Python Solution

```python
import sys
input = sys.stdin.readline

n = int(input())

while n % 2 == 0:
    n //= 2

while n % 3 == 0:
    n //= 3

print("YES" if n == 1 else "NO")
```

The first loop removes every occurrence of the prime factor 2. It must be a `while` loop rather than an `if`, because a number such as 16 contains four factors of 2.

The second loop does the same for 3. The order of these two loops does not affect the result because multiplication of prime factors is commutative, so all factors of 2 and 3 can be removed in either order.

The final comparison with 1 is the key boundary condition. Reaching 1 means nothing forbidden remains. In particular, the input `1` enters neither loop and is immediately accepted.

Python integers do not have an overflow problem here, and the input bound is only 1000. The implementation also needs no array or auxiliary data structure.

## Worked Examples

### Sample 1

For the input `18`, the algorithm repeatedly removes the allowed factors.

| Step | (n) before | Operation | (n) after |
| --- | --- | --- | --- |
| 1 | 18 | divide by 2 | 9 |
| 2 | 9 | divide by 3 | 3 |
| 3 | 3 | divide by 3 | 1 |
| 4 | 1 | stop | 1 |

The remaining value is 1, so the output is `YES`. This demonstrates that factors may occur multiple times and all of them must be removed.

### Sample 2

For the input `35`, neither 2 nor 3 divides the number.

| Step | (n) before | Operation | (n) after |
| --- | --- | --- | --- |
| 1 | 35 | not divisible by 2 | 35 |
| 2 | 35 | not divisible by 3 | 35 |
| 3 | 35 | remaining value is not 1 | 35 |

The output is `NO`. The remaining 35 has prime factors 5 and 7, both of which are forbidden.

## Edge Cases

The input `1` is the most important special case. The algorithm starts with (n=1), so both divisibility loops are skipped. The final value is already 1, producing `YES`. This matches the mathematical definition because 1 has no prime factors, so it does not contain any forbidden prime.

For input `6`, the execution is `6 -> 3` after removing a factor of 2, followed by `3 -> 1` after removing a factor of 3. The output is `YES`. This confirms that having both allowed primes is perfectly valid.

For input `12`, the execution is `12 -> 6 -> 3 -> 1`. The first loop removes both factors of 2 before the second loop removes the factor of 3. The result is `YES`, showing why each divisibility test has to be repeated rather than performed only once.

For input `1000`, the factor-2 loop produces `1000 -> 500 -> 250 -> 125`. The factor-3 loop makes no changes because 125 is not divisible by 3. Since 125 is greater than 1, the algorithm prints `NO`. The surviving value contains the forbidden prime factor 5, so the rejection is correct.

For input `35`, neither loop changes the value. It remains 35, which is greater than 1, so the output is `NO`. This is the simplest case where a forbidden prime factor is present from the beginning.
