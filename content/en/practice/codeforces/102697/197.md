## Solution
## Problem Understanding

We are given three non-parallel lines in the coordinate plane. Each line is written as `y = mx + b`, so every line is completely described by its slope `m` and y-intercept `b`. Every pair of lines intersects at exactly one point. Those three pairwise intersection points form a triangle, and we need to output its area as a decimal number.

The input contains exactly three equations, so there is no parameter that grows with the input. The time limit is one second and the memory limit is 256 MB, but this problem is already constant-sized: regardless of the numerical values in the equations, we perform only three line intersections and one triangle-area calculation.

There are no explicit bounds on the numerical values in the statement, so the implementation should use floating-point arithmetic rather than integer arithmetic. Python's `float` is sufficient because the judge accepts answers within a small numerical tolerance.

A subtle case is when all three lines pass through the same point. For example,

```
y = x + 5
y = 2x + 5
y = 3x + 5
```

All three intersections are `(0, 5)`, so the correct area is `0.0`. A careless implementation might assume that three non-parallel lines always form a non-degenerate triangle and fail to handle zero area.

Another edge case is negative slopes and negative intercepts. For example,

```
y = -2x - 3
y = x + 1
y = 4x - 8
```

The signs are part of the equation and must not be lost while parsing. Splitting the input around spaces is fragile because the statement describes mathematical equations rather than a fixed token format. Removing spaces first makes both `y = -2x - 3` and `y=-2x-3` equivalent.

A third case is an intersection whose coordinates are fractional. For example,

```
y = 2x + 3
y = -2x + 9
y = x - 2
```

produces non-integer intersection coordinates and an area of `28.166666666666664`. Using integer division would silently corrupt the calculation.

## Approaches

The most direct approach is to construct the three vertices explicitly. For every pair of lines, solve the two linear equations to obtain their intersection point. Then apply the standard determinant formula for the area of a triangle.

This approach is already constant time. There are exactly three pairs of lines, namely `(1, 2)`, `(1, 3)`, and `(2, 3)`. Each intersection requires a fixed number of arithmetic operations, followed by a fixed-size shoelace calculation. In mathematical terms, the worst case is exactly three intersection computations and one area computation, roughly 21 elementary arithmetic operations for the three coordinate pairs before counting the final determinant operations. There is no input-dependent loop that could become slow.

So the usual distinction between a slow brute force and an asymptotically faster solution does not really exist for this problem. The useful optimization is algebraic rather than asymptotic. Instead of searching over possible points or using a geometric construction, we use the fact that every line already has the form `y = mx + b`, which gives its intersection with another line immediately.

For lines

`y = m1 x + b1`

and

`y = m2 x + b2`,

their intersection satisfies

`m1 x + b1 = m2 x + b2`.

Rearranging gives

`x = (b2 - b1) / (m1 - m2)`.

Once `x` is known, substitute it into either line to obtain `y`. The statement guarantees that no two lines are parallel, so `m1 - m2` is never zero.

We can then use the three intersection points `(x1, y1)`, `(x2, y2)`, and `(x3, y3)` in the determinant formula

`area = |x1(y2-y3) + x2(y3-y1) + x3(y1-y2)| / 2`.

The result is constant time and constant extra space.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Explicit intersections + shoelace | O(1) | O(1) | Accepted |
| Direct algebraic geometry | O(1) | O(1) | Accepted |

The two approaches have the same asymptotic complexity because the input always contains exactly three lines. The second presentation is preferable because it exposes the mathematical structure directly and avoids any unnecessary geometric machinery.

## Algorithm Walkthrough

1. Read the three equations and convert each one into a pair `(m, b)`. Removing spaces first makes the parser independent of whether the input contains spaces around `=`, `x`, and the signs.
2. For every pair of lines `(i, j)`, compute their intersection using

`x = (bj - bi) / (mi - mj)`.

The denominator is nonzero because the problem guarantees that no two lines are parallel.
3. Compute the corresponding y-coordinate with

`y = mi * x + bi`.

Using the first line of the pair is enough because the point lies on both lines.
4. Store the three intersection points. The pair `(0, 1)` gives the first vertex, `(0, 2)` gives the second, and `(1, 2)` gives the third.
5. Apply the shoelace formula to those three points and divide the absolute value by two. Taking the absolute value handles either clockwise or counterclockwise ordering of the vertices.
6. Print the resulting floating-point value. The judge accepts a small numerical error, so there is no need to force a particular decimal representation.

Why it works: the intersection formula is obtained directly from the two equations of a pair of lines, so every generated point is exactly the required pairwise intersection. The algorithm generates all three pairwise intersections, which are precisely the vertices defined by the problem. The shoelace formula gives the exact area of the triangle determined by those three points, including zero when the three lines are concurrent. Hence the final value is the required triangle area.

## Python Solution

```python
import sys
input = sys.stdin.readline

def parse_line(line):
    s = line.replace(" ", "")
    left, right = s.split("x")
    m = float(left.split("=")[1])
    b = float(right)
    return m, b

def intersection(a, b):
    m1, b1 = a
    m2, b2 = b

    x = (b2 - b1) / (m1 - m2)
    y = m1 * x + b1
    return x, y

def solve():
    lines = [parse_line(input().strip()) for _ in range(3)]

    p1 = intersection(lines[0], lines[1])
    p2 = intersection(lines[0], lines[2])
    p3 = intersection(lines[1], lines[2])

    x1, y1 = p1
    x2, y2 = p2
    x3, y3 = p3

    area = abs(
        x1 * (y2 - y3)
        + x2 * (y3 - y1)
        + x3 * (y1 - y2)
    ) / 2.0

    print(area)

if __name__ == "__main__":
    solve()
```

The parser first removes every space from an equation. After that, an equation such as `y = -2x + 9` becomes `y=-2x+9`. Splitting at `x` separates the slope portion from the intercept portion, and `float` handles positive and negative values as well as decimal values.

The `intersection` function implements the equation derived in the algorithm walkthrough. The denominator uses `m1 - m2`, so the only division by zero possibility would be two equal slopes, which the problem explicitly rules out.

The three calls use each possible pair exactly once. Their order does not matter for the area because the shoelace expression is wrapped in `abs`.

Python integers do not create overflow problems, but the computation here uses `float` throughout because the intersection coordinates and final area can be fractional. No rounding is performed before printing, matching the problem's floating-point output requirement.

## Edge Cases

For concurrent lines, consider

```
y = x + 5
y = 2x + 5
y = 3x + 5
```

The first and second lines intersect at `(0, 5)`. The first and third lines also intersect at `(0, 5)`, and the second and third lines do the same. The three stored points are identical, so every term in the shoelace determinant cancels and the algorithm prints `0.0`. No special branch is needed.

For negative coefficients, consider

```
y = -2x - 3
y = x + 1
y = 4x - 8
```

The first two lines intersect at `(-4/3, 5/3)`, the first and third intersect at `(-1/2, -2)`, and the second and third intersect at `(9/5, 14/5)`. The resulting area is `6.25`. The parser preserves both minus signs because the entire equation is converted to a compact form before extracting the slope and intercept.

For fractional intersections, the first sample already provides the relevant case. The intersection of the second and third lines is `(11/3, 5/3)`. A floating-point implementation preserves those fractions well enough for the judge's tolerance, while integer division would turn them into incorrect integers.

For a zero slope, consider

```
y = 1000x + 1
y = -1000x + 1
y = 0x - 1000000
```

The third line is horizontal, which is completely valid because only parallel pairs are forbidden. The first two lines meet at `(0, 1)`, while the other two intersections have x-coordinates `-1000.001` and `1000.001`. The resulting area is `1000002000.001`, demonstrating that the formula also works when one of the lines is horizontal and the triangle is very large.
