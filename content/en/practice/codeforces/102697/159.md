## Solution
## Problem Understanding

Pascal's Triangle starts with row 0 containing only `1`. Each later row is formed by placing `1` at both ends and making every interior value the sum of the two values directly above it. For example, rows 0 through 5 are

```
1
1 1
1 2 1
1 3 3 1
1 4 6 4 1
1 5 10 10 5 1
```

The input is a single integer `n`, identifying the row whose maximum value we need. The output is that maximum value, not the whole row.

The Codeforces statement currently specifies a one-second time limit and 256 MB of memory, but the accessible statement does not publish an upper bound for `n`. That missing bound does not change the mathematical solution. A method that explicitly constructs all rows up to `n` performs a quadratic number of additions, while the useful structure of Pascal's Triangle lets us calculate only the middle coefficient in linear arithmetic steps.

There are two indexing details that can easily cause an incorrect answer. The first is that the top row is row 0. For input `0`, the only value is `1`, so the output is `1`. A solution that treats the input as a one-based row number would accidentally inspect the second row, which also happens to give `1`, hiding the indexing bug on this particular case.

The second issue is that odd-numbered rows have two equal central values. For input `5`, the row is `1 5 10 10 5 1`, so the answer is `10`. A solution that uses a non-central position such as `n // 2 - 1` can still work for some even rows but can fail at the smallest odd rows. For example, input `3` produces `1 3 3 1`, whose correct answer is `3`.

A final edge case is row `1`, where every value is equal. The input

```
1
```

has output

```
1
```

A careless implementation that assumes there is always an interior element would fail because this row has only its two boundary values.

## Approaches

The direct approach is to construct Pascal's Triangle row by row. We begin with `[1]`, generate the next row from adjacent pairs, and continue until row `n`. This is correct because the construction rule is exactly the definition of Pascal's Triangle. However, generating every value is unnecessary when we only want the maximum of one row.

To reach row `n`, the construction performs roughly

[
1 + 2 + \cdots + n = \frac{n(n+1)}{2}
]

value-generation operations. Thus the worst-case running time is `O(n^2)`, with the final row itself containing `n + 1` values. If `n` is large, the quadratic number of operations is the first thing to eliminate.

The key observation comes from recognizing every entry as a binomial coefficient. Position `k` in row `n` is

[
\binom{n}{k}.
]

The coefficients increase while we move toward the middle of the row and then decrease symmetrically. Algebraically,

\frac{n-k}{k+1}.
]

As long as `k < n/2`, this ratio is greater than or equal to `1`, so the coefficients do not decrease. After the middle, the symmetry

[
\binom{n}{k} = \binom{n}{n-k}
]

takes over. Consequently, the maximum is always the central coefficient

[
\binom{n}{\lfloor n/2 \rfloor}.
]

We now only have to calculate one binomial coefficient. Computing it from the multiplicative formula avoids constructing the entire triangle:

\prod_{i=1}^{k}\frac{n-k+i}{i},
\qquad
k=\left\lfloor\frac n2\right\rfloor.
]

Each division is exact at every iteration because the running value is itself a binomial coefficient. Python's arbitrary-precision integers also allow the result to be represented exactly, with no fixed-width integer overflow.

The brute-force method works because it follows Pascal's recurrence directly, but it spends work on every value in every preceding row. The observation that only the central coefficient can be maximal reduces the problem from constructing `Θ(n²)` entries to computing `Θ(n)` exact multiplicative updates.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(n²) | O(n) | Too slow for large `n` |
| Optimal | O(n) arithmetic iterations | O(1) auxiliary space | Accepted |

The complexity above counts arithmetic updates as constant-time operations. Since the answer itself grows exponentially with `n`, its integer representation also grows, so the actual bit complexity necessarily includes the cost of manipulating large integers.

## Algorithm Walkthrough

1. Read the requested row number `n`. The row is zero-indexed, so row `n` contains the coefficients of `(1+x)^n`.
2. Set `k = n // 2`. The largest coefficient occurs at this position. For odd `n`, the two middle coefficients are equal, so either middle position gives the same answer.
3. Initialize `value = 1`, representing the first coefficient, `C(n, 0)`.
4. For every `i` from `1` through `k`, update the coefficient using

\binom{n}{i-1}\frac{n-i+1}{i}.
]

The multiplication and division are performed in this order:

```
value = value * (n - i + 1) // i
```

The division is exact because `value * (n-i+1) / i` is precisely the next binomial coefficient.

1. After the loop, `value` equals `C(n, k)`, which is the maximum value in row `n`. Print it.

### Why it works

The invariant is that after iteration `i`, `value` is exactly `C(n, i)`. It is true initially because `C(n, 0) = 1`. If `value = C(n, i-1)`, the update gives

# \frac{n!}{i!(n-i)!}

C(n,i).
]

Thus the invariant holds throughout the loop. When `i = floor(n/2)`, the value is the central binomial coefficient. Pascal's Triangle is symmetric, and its coefficients are nondecreasing up to the middle, so this coefficient is the maximum in the entire row.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = int(input())

    k = n // 2
    value = 1

    for i in range(1, k + 1):
        value = value * (n - i + 1) // i

    print(value)

if __name__ == "__main__":
    solve()
```

The input contains only one integer, so `solve` needs no test-case loop. The expression `n // 2` selects a central position using integer arithmetic and works for both even and odd rows.

The loop starts at `1` because `C(n, 0)` has already been initialized to `1`. Its upper endpoint is `k`, inclusive, so exactly the required central coefficient is computed. The recurrence uses `n - i + 1`, not `n - i`, because the transition from `C(n, i-1)` to `C(n, i)` introduces that specific numerator.

Python integers automatically expand to accommodate the potentially very large answer. In languages with fixed-width integer types, overflow would need separate consideration, but there is no such issue in Python.

## Worked Examples

### Example 1

Consider input `5`. We need the maximum coefficient in row 5. The central position is `5 // 2 = 2`.

| `i` | `value` before update | Update | `value` after update |
| --- | --- | --- | --- |
| 0 | 1 | initial `C(5, 0)` | 1 |
| 1 | 1 | `1 * 5 // 1` | 5 |
| 2 | 5 | `5 * 4 // 2` | 10 |

The final value is `10`, matching the row `1 5 10 10 5 1`. The two central entries are equal because row 5 is symmetric.

### Example 2

Consider input `6`. The central position is `6 // 2 = 3`.

| `i` | `value` before update | Update | `value` after update |
| --- | --- | --- | --- |
| 0 | 1 | initial `C(6, 0)` | 1 |
| 1 | 1 | `1 * 6 // 1` | 6 |
| 2 | 6 | `6 * 5 // 2` | 15 |
| 3 | 15 | `15 * 4 // 3` | 20 |

Row 6 is `1 6 15 20 15 6 1`, so `20` is the unique central maximum. The trace also demonstrates that the algorithm never needs to store the rest of the row.

## Edge Cases

For row `0`, the exact input is

```
0
```

The algorithm sets `k = 0`, so the loop executes zero times and prints the initial value `1`. This is correct because Pascal's Triangle begins with the single coefficient `C(0,0) = 1`.

For row `1`, the input is

```
1
```

Here `k = 0`, so again no loop iteration is required. The result is `1`, matching the row `1 1`. This handles the boundary-only row without assuming that an interior coefficient exists.

For an odd row such as

```
3
```

the algorithm computes `k = 1` and obtains

[
\binom31=3.
]

The complete row is `1 3 3 1`, so the second central value has the same maximum. Choosing `floor(n/2)` is sufficient because symmetry guarantees the other central position has exactly the same value.

For an even row such as

```
6
```

the algorithm computes `k = 3` and obtains

[
\binom63=20.
]

The row is `1 6 15 20 15 6 1`, so the central coefficient is the unique maximum. The loop reaches exactly this position and stops, avoiding unnecessary computation of the symmetric half.

For a large row, the numerical value can exceed standard 32-bit or 64-bit integer ranges by a huge margin. Python stores the coefficient as an arbitrary-precision integer, so the recurrence remains exact. No floating-point calculation is used, which also avoids rounding errors that could corrupt a binomial coefficient.

The central mathematical property is that every coefficient before the midpoint is at least as large as the previous one, while symmetry mirrors those coefficients after the midpoint. That single property is what lets the algorithm ignore every non-central position without risking the maximum.
