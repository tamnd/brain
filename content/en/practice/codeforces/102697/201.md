## Solution
## Problem Understanding

A Ken Ken board here is always a 5 by 5 grid. Every cell must contain an integer from 1 through 5, with the additional Latin-square condition that no number repeats within a row or within a column.

The board is divided into cages. A cage is a connected group of cells, and its first cell in reading order contains a target and an operation. A one-cell cage is simply fixed to that target. For a larger cage, addition and multiplication apply to all cells in the cage, while subtraction and division are only used for exactly two cells. For subtraction, either ordering is valid as long as the absolute difference equals the target. For division, either ordering is valid as long as the larger value divided by the smaller value equals the target.

The input is slightly unusual because the cage structure is encoded as an ASCII drawing. Every cell occupies a 2 by 2 position in that drawing. A vertical `|` between two cells means the cells are separated, while a missing vertical wall means they belong to the same cage. The same idea applies horizontally with `-`. The operation text appears inside the topmost, then leftmost, cell of each cage.

The output is the completed 5 by 5 grid. Since every value is between 1 and 5, each row can be printed directly as five digits.

The fixed size of `n = 5` changes the algorithmic tradeoff substantially. A general Latin-square search on 25 cells has up to `5^25` assignments, which is roughly `3 × 10^17`, so blindly enumerating the board is impossible. At the same time, the domain of every cell contains only five values, and a cage contains at most 25 cells. That makes constraint-based backtracking practical, especially when cage arithmetic is checked as soon as enough information is available.

Several details can make a naive implementation silently incorrect. A subtraction cage is unordered. For example, a cage described by `2-` can contain `1,3` or `3,1`, so checking only `a - b == 2` would reject valid solutions. Similarly, a `2/` cage accepts `1,2`, `2,1`, `2,4`, and `4,2`; checking only the first cell divided by the second is wrong.

A cage may also contain repeated values. For example, a three-cell `6+` cage can legally contain `1,2,3` or `2,2,2`. The Latin constraint applies to rows and columns, not to cages. An implementation that forces all cells inside a cage to be distinct can reject valid solutions.

Finally, a cage can span several rows or columns and need not be rectangular. A connected L-shaped cage is valid. For example, the first sample contains cages whose cells are connected through missing walls rather than simply being contiguous intervals in a row. Treating each visually rectangular region as a cage would construct the wrong constraints.

## Approaches

The most direct brute-force solution assigns one of five values to every empty cell and checks the Latin-square and cage conditions after constructing a complete board. It is correct because every possible board is eventually considered, and the first valid board is a solution. The problem is the search space: 25 cells with five choices each gives `5^25 = 298,023,223,876,953,125` possible assignments before constraints are used.

The natural improvement is to turn the problem into constraint search. As soon as a value is assigned, the row and column immediately restrict the values available to other cells. More importantly, the cage operation gives another constraint that can often reject a partial assignment long before the cage is complete.

For addition cages, a partial sum can be compared against the smallest and largest sums still achievable. For multiplication cages, the same idea works with products. Suppose a `12+` cage has five cells and the first three currently sum to 10. The remaining two cells must sum to exactly 2, which is impossible because every cell is at least 1. We can stop exploring that branch immediately.

For subtraction and division cages, there are exactly two cells, so checking the operation when both values have been assigned is enough. A singleton cage is even simpler because its value is fixed before the search begins.

The resulting search is still technically exponential, but it is exponential in a tiny domain with strong pruning. The brute-force works because checking every board is logically sufficient, but fails because almost all boards are rejected only after many irrelevant assignments. The observation that rows, columns, and cages can reject partial assignments lets us cut those branches at the moment they become impossible.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | `O(5^25)` | `O(25)` | Too slow |
| Constraint Backtracking | `O(5^25)` worst case, much smaller in practice | `O(25 + C)` | Accepted |

The worst-case asymptotic bound remains exponential because Ken Ken is a constraint satisfaction problem. The practical difference is that the search rarely reaches anything close to all `5^25` assignments for these 5 by 5 puzzles.

## Algorithm Walkthrough

1. Read the ASCII board and determine which grid cells belong to the same cage. For every pair of horizontally adjacent cells, inspect the character between them on the corresponding drawing line. If there is no `|`, merge the two cells. For vertically adjacent cells, inspect the character between them on the horizontal boundary line. If there is no `-`, merge them. A disjoint-set union structure is a convenient way to perform these merges.
2. After all merges, group cells by their DSU root. Each group is one cage. Sort its cells in row-major order so the first cell is precisely the cell where the puzzle specifies that the operation is written.
3. Read the operation from the first cell of every cage. A singleton cage contains a fixed integer such as `2`. A multi-cell cage contains a number followed by `+`, `x`, `-`, or `/`. Store the target and operation with the cage.
4. Maintain the current board and two sets for every row and column. When assigning a value to `(r, c)`, reject it immediately if that value already appears in row `r` or column `c`. This enforces the Latin-square condition incrementally rather than after the entire board has been guessed.
5. Track the assigned values, sum, and product for every cage. For an addition cage, calculate the current sum and compare it with the minimum and maximum sums possible for its unassigned cells. If the target lies outside that interval, the branch cannot possibly work. For a multiplication cage, perform the equivalent product bound.
6. When a subtraction or division cage becomes complete, evaluate its operation directly. For subtraction, use the absolute difference. For division, first take the larger value and divide it by the smaller one, requiring exact divisibility and the target quotient.
7. When a cage becomes complete, verify its operation exactly. This catches constraints that cannot be represented by a simple partial sum or product bound.
8. Choose the next unassigned cell and try values from 1 through 5. A row-major traversal is sufficient for this fixed 5 by 5 problem, because each attempted value is cheap and the cage pruning is strong. Assign the value, update all affected state, recurse, and undo the assignment if the branch fails.
9. Stop as soon as all 25 cells are assigned. At that point every row and column is distinct, and every cage has already passed its arithmetic constraint, so the board is a valid Ken Ken solution.

### Why it works

The invariant during backtracking is that every assigned cell satisfies its row and column constraints, and every partially assigned cage remains capable of reaching its target. When a branch is rejected, either a row or column already contains a duplicate, a cage can no longer reach its arithmetic target, or a completed cage violates its operation. In each case there is no valid completion of that branch, so pruning it cannot discard a solution. When the search reaches a completely assigned board, the invariant gives valid rows and columns, while every cage has been checked against its required operation. Thus the returned board is a valid solution.

import sys
import re

input = sys.stdin.readline

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        a = self.find(a)
        b = self.find(b)
        if a == b:
            return
        if self.size[a] < self.size[b]:
            a, b = b, a
        self.parent[b] = a
        self.size[a] += self.size[b]

        for c in range(n - 1):

            if wall != '|':

    # are in the same cage.
    for r in range(n - 1):

        for c in range(n):
