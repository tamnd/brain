## Solution
## Problem Understanding

The facility is represented by an `n × m` grid. A cell containing `X` is a wall, while `.` is walkable empty space and `P` is a walkable cell containing an aircraft. Movement is allowed only between horizontally or vertically adjacent cells, so diagonal movement is forbidden. A room is exactly a connected region of cells that are not walls. Since the team may choose only one room, the answer is the largest number of `P` cells belonging to any single connected component of walkable cells. The published statement confirms that aircraft cells themselves can be traversed, which is the detail that makes `P` behave like `.` for connectivity purposes.

The statement does not publish explicit bounds for `n` and `m`, but the grid has exactly `n × m` cells, and the time limit is one second with 256 MB of memory. A solution should consequently avoid repeatedly scanning the entire grid. A linear or near-linear pass over the cells is the natural target. An `O((nm)^2)` solution can become expensive as soon as the grid contains many walkable cells, while an `O(nm)` traversal processes each cell a constant number of times.

The first edge case is a single aircraft. For the input

```
1 1
P
```

the correct output is `1`. A careless implementation that only starts searching from `.` cells would never visit the aircraft, even though the statement explicitly allows walking through a `P` cell.

A second edge case is several aircraft separated by walls:

```
1 3
PXP
```

The correct output is `1`. The two aircraft are in different rooms because the middle cell is an impassable wall. Counting every aircraft in the entire grid would incorrectly return `2`.

A third edge case is that aircraft can belong to the same room even when they are not adjacent:

```
3 3
P..
.X.
..P
```

The correct output is `2`. Both `P` cells are connected through the walkable cells around the wall. An approach that groups aircraft only when they touch directly would incorrectly return `1`.

Finally, cells on the boundary need exactly the same treatment as interior cells. For

```
2 2
PP
XX
```

the answer is `2`. A traversal must check bounds before accessing a neighbor, otherwise moving upward from the first row or downward from the second row can cause an invalid access or accidentally wrap around in languages where indexing behavior permits it.

## Approaches

A direct but inefficient solution is to start a graph search from every aircraft cell. For each `P`, we can run BFS or DFS through every reachable walkable cell and count how many aircraft are encountered. This is correct because every room reachable from that starting aircraft is precisely its connected component, so the search gives the number of aircraft in that room.

The problem is that many starting aircraft can belong to the same large room. If the grid has `N = nm` cells and almost all of them are walkable aircraft-containing or empty cells, a single search can touch `Θ(N)` cells, and there can be `Θ(N)` starting aircraft. The worst case is consequently `Θ(N²) = Θ((nm)²)` cell visits. A grid with 10,000 cells can already lead to around 100 million cell visits before accounting for neighbor checks.

The brute-force approach works because a traversal correctly identifies one room, but it repeatedly solves the same connected-component problem. The key observation is that connected components partition all walkable cells. Once one search has completely explored a room, every cell in that room has already been classified, so there is no reason to explore it again.

We can exploit this by scanning the grid once. Whenever we encounter an unvisited non-wall cell, we start a BFS or DFS from it. During that traversal, we count every `P` encountered. When the traversal ends, we have the exact number of aircraft in that room, so we update the global maximum. Each walkable cell is visited exactly once, giving linear time in the number of grid cells.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | `O((nm)²)` | `O(nm)` | Too slow |
| Optimal | `O(nm)` | `O(nm)` | Accepted |

## Algorithm Walkthrough

1. Read the grid and create a visited structure with one entry for every cell. A wall does not need to be traversed, but keeping the visited structure rectangular makes neighbor handling straightforward.
2. Scan every cell from top to bottom and from left to right. If the cell is a wall or has already been visited, skip it because it cannot begin a new room.
3. When an unvisited walkable cell is found, start a BFS from that cell and mark it visited immediately. The starting cell can be either `.` or `P`, since both are walkable and belong to the same connectivity graph.
4. Maintain a counter for the current room. Increment it whenever the BFS removes a `P` cell from the queue, or equivalently when the cell is first discovered.
5. For each visited cell, inspect its four orthogonal neighbors. Ignore a neighbor if it lies outside the grid, is a wall, or has already been visited. Every remaining neighbor belongs to the same room, so mark it visited and add it to the BFS queue.
6. When the BFS queue becomes empty, the entire connected component has been explored. Compare its aircraft count with the maximum found so far and keep the larger value.
7. Continue the outer scan until every grid cell has been considered. The stored maximum is the largest number of aircraft contained in any single room, so output it.

### Why it works

The invariant is that whenever a BFS starts, its starting cell belongs to a connected component that has not been explored before, and the BFS visits exactly every walkable cell in that component. Because a cell is marked visited when it is discovered, no cell can be processed twice. Every `P` in the component is consequently counted exactly once, while every `P` outside the component is excluded. Since the outer scan starts a BFS for every previously unexplored component, every room is considered exactly once. Taking the maximum count over those components therefore gives exactly the best room for the tour.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n, m = map(int, input().split())
    grid = [input().strip() for _ in range(n)]

    visited = [[False] * m for _ in range(n)]
    best = 0

    directions = ((1, 0), (-1, 0), (0, 1), (0, -1))

    for r in range(n):
        for c in range(m):
            if grid[r][c] == 'X' or visited[r][c]:
                continue

            queue = [(r, c)]
            visited[r][c] = True
            head = 0
            aircraft = 0

            while head < len(queue):
                cr, cc = queue[head]
                head += 1

                if grid[cr][cc] == 'P':
                    aircraft += 1

                for dr, dc in directions:
                    nr = cr + dr
                    nc = cc + dc

                    if not (0 <= nr < n and 0 <= nc < m):
                        continue
                    if visited[nr][nc] or grid[nr][nc] == 'X':
                        continue

                    visited[nr][nc] = True
                    queue.append((nr, nc))

            best = max(best, aircraft)

    print(best)

if __name__ == "__main__":
    solve()
```

The outer double loop implements the component discovery described in steps 2 and 7. A cell is ignored if it is a wall or has already been assigned to a previously explored room.

The queue stores the cells belonging to the current BFS. The integer `head` points to the next cell to process, so the implementation avoids repeatedly removing from the front of a Python list. Removing with `pop(0)` would shift all remaining elements and could make the traversal unnecessarily expensive.

A cell is marked visited when it is added to the queue rather than when it is removed. This prevents the same cell from being inserted several times through different neighboring cells.

The four direction pairs represent exactly the allowed movements. The bounds check is performed before indexing `grid[nr][nc]`, which handles boundary cells safely. There is no special case for `P`, because an aircraft cell is walkable and therefore participates in the same BFS as an empty cell.

Python integers have arbitrary precision, so there is no integer-overflow concern when counting aircraft. The maximum count is at most `n × m`.

## Complexity Analysis

| Measure | Complexity | Explanation |
| --- | --- | --- |
| Time | `O(nm)` | Every cell is examined by the outer scan, and every walkable cell is processed once by BFS. |
| Space | `O(nm)` | The visited matrix and BFS queue can each contain `O(nm)` cells. |

The linear complexity is appropriate because the input itself contains `nm` grid characters, so reading the grid already requires `O(nm)` time. The algorithm performs only a constant amount of additional work per cell and therefore avoids the repeated searches of the brute-force method. The 256 MB memory limit is sufficient for the grid, visited matrix, and queue for typical grid sizes supported by this problem. The published statement gives a one-second time limit and 256 MB memory limit, although it does not specify explicit `n` and `m` bounds.

## Edge Cases

For the single-cell case

```
1 1
P
```

the outer scan sees `(0,0)` as an unvisited walkable cell and starts BFS. The cell is marked visited, the aircraft counter becomes `1`, and the queue becomes empty. The global maximum changes from `0` to `1`, so the output is `1`. No separate handling for a one-cell grid is required.

For the disconnected case

```
1 3
PXP
```

the first `P` starts a component containing only itself, producing a count of `1`. The middle `X` is skipped. The final `P` starts another one-cell component, also producing `1`. The maximum remains `1`. A solution that simply counts every `P` without respecting walls would incorrectly return `2`.

For the connected-but-non-adjacent case

```
3 3
P..
.X.
..P
```

the first BFS starts at the upper-left `P`. It moves through the surrounding `.` cells and eventually reaches the lower-right `P`. Both aircraft are counted during the same traversal, giving `2`. The diagonal separation caused by the central wall does not matter because there is an orthogonal path around it.

For the boundary case

```
2 2
PP
XX
```

the BFS starts at `(0,0)`, reaches `(0,1)`, and then rejects the upward, leftward, and out-of-range neighbors through the bounds check. The two `P` cells are counted in one component, giving `2`. The algorithm never attempts to access a negative row or a column outside the grid.

For the large connected case, every cell is `P`, so the first BFS reaches all `n × m` cells and counts every aircraft exactly once. Every subsequent outer-loop position is already marked visited, so no additional BFS is started. This is the key behavior behind the `O(nm)` bound: even in the densest possible walkable region, each cell enters the queue only once.
