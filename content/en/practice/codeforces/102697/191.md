## Solution
## Problem Understanding

The task is to encrypt a lowercase plaintext using the Morbit cipher. The encryption has two representations in the middle: Morse code and two-character Morse blocks.

Every letter is replaced by its standard Morse representation. Between consecutive letters we place one `x`, while between consecutive words we place two `x` characters. Thus `ab` becomes `.-x-...`, because `a` is `.-`, the letters are separated by `x`, and `b` is `-...`. The complete Morse string is then split from left to right into pairs. If its length is odd, one final `x` is appended.

There are exactly nine possible pairs because each position can contain `.`, `-`, or `x`. The nine key lines give a permutation of these nine pairs. The first line is the pair represented by digit `1`, the second is the pair represented by digit `2`, and so on through digit `9`. The required output is the digit corresponding to every consecutive pair in the constructed Morse string. The official statement specifies a 1 second time limit and 256 MB memory limit.

The statement does not provide an explicit maximum plaintext length. That means the safe design is a single linear pass over the text, rather than anything whose work grows quadratically. Since the key contains only nine entries, even a simple lookup over all nine entries is bounded by a very small constant, but a dictionary gives a cleaner `O(1)` lookup for every Morse pair.

The first edge case is a plaintext whose Morse representation has odd length. For example, with the key

```
xx
.-
-.
x.
.x
..
--
-x
x-
```

the input

```
e
xx
.-
-.
x.
.x
..
--
-x
x-
```

has Morse code `.`. It must be padded to `.x`, which maps to `5`, so the output is `5`. A careless implementation that only processes complete pairs would lose the final character.

The second edge case is a word boundary. With the same key, the plaintext `ab` produces `.-x-...`. Its pairs are `.-`, `x-`, `-.`, and `..`, giving `2936`. A common mistake is to use one `x` for a space, but a space requires two `x` characters. The distinction changes every pair after the boundary. The problem explicitly defines one `x` between letters and two between words.

The third edge case is a single-letter word whose Morse representation itself has length one. For example, `e` is simply `.`, so the padding rule is required. The resulting pair is `.x`, not just `.`.

## Approaches

A direct approach can first construct the complete Morse string, then process it two characters at a time. For every pair, we could scan the nine key entries until finding the matching pair. This is correct because the key defines exactly which digit represents every possible two-character block. If the Morse string contains `P` characters, there are `P / 2` pairs, and each lookup can inspect up to nine entries, giving at most `9P / 2` pair comparisons. The problem has no stated maximum for `P`, so repeatedly scanning the key is unnecessary work, even though the constant is small.

The observation that makes the cleaner solution immediate is that the key is fixed and contains only nine possible pair values. We can invert the key once by storing `pair -> digit`. Then each Morse pair is converted to its digit with one dictionary lookup. The expensive part is no longer searching the key, so the entire encryption becomes linear in the size of the generated Morse string.

The Morse conversion itself is also naturally linear. We map each plaintext letter through a fixed 26-entry table, insert `x` after a letter when another letter follows it, and insert `xx` when the next character begins another word. After constructing the Morse representation, padding and pair processing each take another linear pass.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(9P) | O(P) | Accepted for modest input, but unnecessary repeated lookup |
| Optimal | O(P) | O(P) | Accepted |

Here `P` denotes the length of the generated Morse string, including separators and possible padding. Since every Morse encoding has constant length at most four and every letter contributes only a constant amount of separator information, `P` is linear in the plaintext length.

## Algorithm Walkthrough

1. Read the complete plaintext line without discarding spaces. The spaces are meaningful because they determine where two `x` characters must be inserted.
2. Read the nine key pairs and create a dictionary whose key is the two-character block and whose value is its digit from `1` through `9`. This reverses the direction in which the key is given, matching exactly what encryption needs.
3. Convert the plaintext into Morse code. For every word, convert its letters using the standard A to Z Morse table and put one `x` between consecutive letters. Put two `x` characters between consecutive words.
4. If the resulting Morse string has odd length, append one `x`. This makes every character belong to exactly one two-character block.
5. Traverse the Morse string in steps of two. Extract each pair and look it up in the key dictionary. Append the corresponding digit to the answer.
6. Print the accumulated digits as one string. Each pair contributes exactly one digit, so no separators belong in the output.

**Why it works.** After Morse conversion, the constructed string is exactly the intermediate representation required by the cipher, because letters use their Morse codes and word and letter boundaries use the specified `x` separators. Padding changes only the required final unmatched position and is performed exactly when the length is odd. The string is then partitioned into the same consecutive two-character blocks defined by the cipher. The inverse key dictionary maps every such block to precisely the digit assigned to it, so every output digit is correct and every block is processed exactly once.

## Python Solution

```python
import sys
input = sys.stdin.readline

MORSE = [
    ".-", "-...", "-.-.", "-..", ".", "..-.", "--.", "....", "..",
    ".---", "-.-", ".-..", "--", "-.", "---", ".--.", "--.-", ".-.",
    "...", "-", "..-", "...-", ".--", "-..-", "-.--", "--.."
]

def solve():
    text = input().rstrip("\n")

    key = {}
    for digit in range(1, 10):
        pair = input().strip()
        key[pair] = str(digit)

    words = text.split()
    morse_parts = []

    for word_index, word in enumerate(words):
        for i, ch in enumerate(word):
            morse_parts.append(MORSE[ord(ch) - ord("a")])
            if i + 1 < len(word):
                morse_parts.append("x")

        if word_index + 1 < len(words):
            morse_parts.append("xx")

    morse = "".join(morse_parts)

    if len(morse) % 2:
        morse += "x"

    answer = []
    for i in range(0, len(morse), 2):
        answer.append(key[morse[i:i + 2]])

    print("".join(answer))

if __name__ == "__main__":
    solve()
```

The `MORSE` array is indexed with `ord(ch) - ord("a")`, so `a` selects index `0`, `b` selects index `1`, and so forth. This avoids a chain of conditional statements and gives constant-time letter conversion.

The plaintext is split into words so that a word boundary can be represented by exactly `xx`. Within each word, the code explicitly inserts a single `x` only between two letters. This avoids accidentally adding a separator after the final letter of a word.

The key dictionary is built in the opposite direction from the input. If the fifth key line is `.x`, then `key[".x"]` becomes `"5"`. This is the lookup direction required during encryption.

Padding is done only after the entire Morse string has been constructed. That ordering matters because the final `x` is padding, not a word separator. A plaintext ending in a word boundary should not acquire an additional artificial separator.

The pair loop advances by two characters, so the two characters used to form one lookup key never overlap with the next pair. The odd-length check before this loop guarantees that the final slice always has exactly two characters.

Python integers do not create any overflow concern here, and the output is accumulated as strings because the ciphertext is a sequence of digits rather than a number.
