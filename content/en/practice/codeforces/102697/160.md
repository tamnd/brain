## Solution
## Problem Understanding

A Ken Ken puzzle is an (n \times n) grid, so it contains exactly (n^2) cells. Some of those cells are already filled in the book. These are the (k) freebie cells, so they do not need to be filled by the solver.

The task is simply to determine how many cells remain to be filled. Since every cell is either one of the (k) freebies or one of the cells we must fill, the answer is

[
n^2-k.
]

The input contains (n), the side length of the square grid, followed by (k), the number of cells that are already filled. The output is the number of cells that still require an entry. The original problem gives only that (n) is positive, so there is no need for a data structure or an algorithm whose complexity depends on a large collection of input elements. The entire computation consists of one multiplication and one subtraction.

A useful edge case is a (1 \times 1) puzzle with its only cell already filled:

```
1
1
```

The correct output is:

```
0
```

A careless solution that assumes at least one cell must be filled could incorrectly produce (1).

Another boundary case is when every cell is a freebie. For example:

```
3
9
```

There are (3^2=9) cells and all nine are already filled, so the answer is:

```
0
```

The common mistake here is to output (n^2) without subtracting the freebies.

At the other extreme, consider a (4 \times 4) puzzle with two freebies:

```
4
2
```

There are (16) cells in total, and (2) require no work, leaving (16-2=14) cells to fill. The correct output is:

```
14
```

## Approaches

A direct brute-force interpretation would explicitly consider all (n^2) cells and count how many are not among the (k) already filled cells. That approach is correct because every cell contributes exactly once to either the filled-in count or the remaining count. Its worst-case operation count is proportional to (n^2), with one visit per grid cell.

The problem, however, does not provide the locations of the freebies. It gives only their count. That means there is no information that could make individual cell inspection useful. Once we know that the grid has (n^2) cells and exactly (k) of them are already filled, the number of remaining cells is determined immediately.

The observation that unlocks the optimal solution is simply that the locations of the freebies do not matter. We only need the total number of cells and the number that have already been completed. Computing (n^2-k) reduces the work from visiting every cell to a constant number of arithmetic operations.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | O(n²) | O(1) | Accepted in principle, but unnecessary |
| Optimal | O(1) | O(1) | Accepted |

## Algorithm Walkthrough

1. Read (n), the side length of the Ken Ken grid. A square with side length (n) contains (n \times n=n^2) cells.
2. Read (k), the number of cells that are already filled. These cells are excluded from the work we still have to do.
3. Compute (n^2-k). This is exactly the number of cells that are not freebies.
4. Print the result.

### Why it works

The complete grid contains exactly (n^2) cells. The (k) freebie cells are already filled, so they account for exactly (k) cells that do not need to be filled again. Every other cell does need to be filled. Thus the remaining number of cells is exactly (n^2-k), which is what the algorithm prints.

## Python Solution

```python
import sys
input = sys.stdin.readline

n = int(input())
k = int(input())

print(n * n - k)
```

The first `input()` reads the grid dimension. The second reads the number of freebies. There is no need to store the grid because the locations of the filled cells never appear in the input.

The expression `n * n` computes the total number of cells. Subtracting `k` gives the number still requiring values. Python integers handle the arithmetic without an overflow issue.

There is also no loop, so the implementation directly reflects the mathematical observation from the algorithm walkthrough.

## Edge Cases

For the minimum-size case

```
1
1
```

the algorithm computes (1^2-1=0). There is one cell and it is already a freebie, so there is nothing left to fill. The subtraction naturally handles the zero answer without any special case.

For the all-freebies case

```
3
9
```

the algorithm computes (3^2-9=0). The fact that no cells remain does not require a separate branch. The formula already represents the situation exactly.

For the case where only one cell remains,

```
10
99
```

the grid contains (10^2=100) cells. After excluding the (99) freebies, the result is (100-99=1). This catches implementations that accidentally subtract one too many or confuse the total number of cells with the number of cells that still need filling.

The key property across all of these cases is unchanged: the answer depends only on the total number of cells and the number of cells that are already filled. No information about the actual positions of those cells is needed.
