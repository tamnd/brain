## Solution
## Problem Understanding

The task is to determine whether the given positive integer is divisible by 2. If it is, we print `YES`; otherwise, we print `NO`. The input contains exactly one positive integer, and there are no multiple test cases. The required output is a single word describing whether the number is a multiple of two.

The statement does not publish a numerical upper bound for the integer. The time limit is 1 second and the memory limit is 256 MB. Since the required property depends only on divisibility by 2, the size of the integer does not require us to perform arithmetic proportional to its value. We can inspect its decimal representation directly, giving constant work with respect to the number of digits. This is also safer than constructing a Python integer if an input were extremely long.

The key edge cases are small values and values whose last digit is zero. For example, the input `1` must produce `NO`, because 1 is not divisible by 2. A careless implementation that checks only whether the number is positive would incorrectly accept it. The input `2` must produce `YES`, because 2 itself is the smallest positive multiple of two. The input `10` must produce `YES`, even though its final digit is zero rather than another even digit. A check based on the last digit handles all three cases directly.

## Approaches

A straightforward brute-force method would try to determine whether the number has an even quotient by repeatedly considering possible multiples of two. An even simpler brute-force interpretation is to enumerate integers from 2 up to the given number and check which ones are multiples of two, stopping when the input is reached. This is correct because every positive multiple of two appears in that sequence, but it performs `n - 1` iterations for an input value of `n`. If `n` is large, that is far more work than the problem requires, and the statement gives no small upper bound that would make such enumeration reasonable.

The structure of decimal notation gives a much stronger observation. A decimal integer is divisible by 2 exactly when its final digit is one of `0`, `2`, `4`, `6`, or `8`. We do not need to examine any earlier digit. For example, `123456` is even because its last digit is `6`, while `987653` is odd because its last digit is `3`. The brute-force method works because it eventually discovers the divisibility property through repeated arithmetic, but fails because it ignores this local property of the decimal representation. Looking only at the final digit reduces the problem to one character check.

The optimal approach is thus constant time in the mathematical sense if the input fits into a machine integer, and `O(L)` in the strict input-size sense if `L` is the number of decimal digits, because reading the input itself requires `O(L)` time. The actual decision after reading the input takes `O(1)` time.

| --- | --- | --- | --- |
| Brute Force | O(n) | O(1) | Too slow for large n |
| Last Digit | O(L) including input reading | O(L) for the input string | Accepted |

## Algorithm Walkthrough

1. Read the positive integer as a string. Reading the decimal representation directly avoids depending on a particular integer size.
2. Take the final character of the string. Divisibility by 2 depends only on this digit, so no other part of the number needs to be processed.
3. Check whether the final digit belongs to `02468`. If it does, print `YES`; otherwise, print `NO`.
4. The result is determined immediately after this single membership test, so there is no loop, division, or enumeration of candidate multiples.

Why it works: every decimal integer is even exactly when its units digit is even. The possible even decimal digits are `0`, `2`, `4`, `6`, and `8`. Thus the algorithm accepts exactly the positive integers divisible by 2 and rejects exactly those that are not.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    n = input().strip()

    if n[-1] in "02468":
        print("YES")
    else:
        print("NO")

if __name__ == "__main__":
    solve()
```

The solution reads the input as a string rather than converting it with `int`. The only character that matters is `n[-1]`, which is the units digit. Membership in `"02468"` is a constant-size check.

Using a string also handles arbitrarily long decimal inputs without relying on Python's integer conversion limits. The problem only asks about divisibility by two, so converting the entire value would provide no useful information.

There is no off-by-one boundary in the algorithm because the input is guaranteed to be a positive integer, so the string always contains at least one digit. The value `0` does not need special handling under the stated input conditions.

## Edge Cases

The input `1` is the smallest positive integer. The algorithm reads the final digit `1`, finds that it is not in `02468`, and prints `NO`. There is no attempt to divide by zero or enumerate smaller candidates, so the boundary is handled directly.

The input `2` is the smallest positive integer that should produce `YES`. Its only digit is `2`, which is even, so the algorithm prints `YES`. This confirms that a single-digit input does not cause an indexing problem.

The input `10` exercises the special-looking final digit `0`. The final character is `0`, which belongs to the set of even digits, so the output is `YES`. A check that accidentally tests only for `2`, `4`, `6`, and `8` would fail here.

For a large value such as `123456789012345678901234567890`, the algorithm ignores every digit except the final `0` and prints `YES`. This demonstrates why the solution does not need to convert the number into a native integer or perform arithmetic proportional to its value. The divisibility decision is completely determined by the units digit.
