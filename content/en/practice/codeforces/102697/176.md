## Solution
## Problem Understanding

We have a catapult on one side of a vertical wall and a target on the other side. The catapult is (a) meters from the wall, while the target is (c) meters beyond the wall and (b) meters above the ground. The wall itself has height (d), with (b<d). We need the smallest possible value of the highest point reached by the projectile, among all trajectories that hit the target and pass above the wall. The official problem confirms that only algebra is needed, without explicitly working with projectile-motion equations.

Place the catapult at horizontal coordinate (x=0), the wall at (x=a), and the target at (x=a+c). Let

[
L=a+c.
]

The projectile starts at ((0,0)) and ends at ((L,b)). Since the trajectory is a downward-opening parabola, it can be written as

[
y(x)=kx(L-x)+\frac{b}{L}x,
]

where (k>0) determines how strongly the parabola bends downward. This form is convenient because the two endpoint conditions are already built in:

[
y(0)=0,\qquad y(L)=b.
]

At the wall, the trajectory must satisfy

[
y(a)\ge d.
]

The input consists of just four integers, so there is no large array, graph, or collection of test cases to process. The challenge is entirely mathematical. Since the desired answer is a real number, the implementation needs floating-point arithmetic, but the computation itself is constant size. Any algorithm depending on iterating through a large range of candidate trajectories would be unnecessary.

There are several edge cases that can expose an incorrect implementation. The first is when the target is on the ground. For example,

```
5 0 9 7
```

has the correct answer approximately

```
7.62222191701435
```

A careless derivation that divides by (b) would fail because (b=0). The trajectory formula above does not have that problem because (k) remains well defined.

Another useful case is when the wall is exactly below the trajectory's highest point. For

```
5 0 5 7
```

the wall is halfway between the launch point and target, so the lowest possible maximum height is exactly (7). The correct output is approximately

```
7.0000000000000195
```

A floating-point implementation should not compare its result against (7) using exact equality.

A third boundary case is when the target is high but still strictly below the wall. For

```
5 6 1 12
```

the correct answer is approximately (15.778572363190715). Here the wall is very close to the target horizontally, so the trajectory must rise substantially before descending to the target.

## Approaches

A brute-force approach would be to generate many possible parabolas joining the launch point and target, test whether each one reaches height at least (d) at the wall, and keep the smallest maximum height. If (P) candidate values of the parabola parameter are tested, the worst case takes (P) trajectory evaluations. The problem is that the parameter is continuous, so there is no natural finite set of candidates that guarantees the exact optimum. Making the discretization finer improves the answer but never turns the method into a mathematically exact solution.

The brute-force idea works because every candidate trajectory can be checked directly, but it fails because we are optimizing over a continuous family of parabolas. The key observation is that once the endpoints are fixed, only one parameter remains free. We can write the entire trajectory using that single parameter (k), express the wall condition as a lower bound on (k), and then express the maximum height directly as a function of (k).

The wall condition actually makes the optimization especially simple. Since the target is below the wall, the optimal trajectory is the one that passes through the top edge of the wall exactly. Any trajectory that rises higher at the wall can be reduced toward the target while lowering its maximum height. This immediately gives the optimal value of (k), after which the vertex formula gives the answer in constant time.

| Approach | Time Complexity | Space Complexity | Verdict |
| --- | --- | --- | --- |
| Brute Force | (O(P)) for (P) candidate trajectories | (O(1)) | Too slow or approximate |
| Optimal | (O(1)) | (O(1)) | Accepted |

## Algorithm Walkthrough

1. Let (L=a+c), the total horizontal distance from the catapult to the target. We use the coordinate system where the catapult is at (x=0), the wall is at (x=a), and the target is at (x=L).
2. Represent every possible trajectory reaching the target by

[
y(x)=kx(L-x)+\frac{b}{L}x.
]

The term (kx(L-x)) is zero at both endpoints, so changing (k) preserves both the launch point and the target. The linear term makes the trajectory reach height (b) at (x=L).
3. Evaluate the trajectory at the wall:

[
y(a)=ka(L-a)+\frac{ab}{L}.
]

Since (L-a=c),

[
y(a)=kac+\frac{ab}{L}.
]

To just clear the wall, the optimal trajectory satisfies (y(a)=d). Solving for (k) gives

[
k=\frac{d-\frac{ab}{L}}{ac}.
]

The numerator is positive because (d>b) and (\frac{a}{L}<1), so this is a valid downward-opening parabola.
4. Rewrite the trajectory in standard quadratic form:

[
y(x)=-kx^2+\left(kL+\frac{b}{L}\right)x.
]

Its vertex occurs at

[
x_v=\frac{kL+\frac{b}{L}}{2k}.
]

The value at the vertex is

[
h=\frac{\left(kL+\frac{b}{L}\right)^2}{4k}.
]

This is the minimum possible maximum height because we already chose the smallest feasible (k), namely the trajectory that touches the wall exactly.
5. Print (h) as a floating-point value. No iterative search or special rounding is required because the judge accepts answers within a numerical tolerance.

### Why it works

For every feasible trajectory, the endpoints are fixed at ((0,0)) and ((L,b)), so the trajectory can differ only through the coefficient (k). Increasing (k) raises the trajectory between the endpoints, including at the wall. Since (d>b), the feasible values of (k) lie on the side where increasing (k) also increases the parabola's maximum height. Thus the minimum-height feasible trajectory is exactly the one whose height at the wall is (d), not greater than (d). The formula for (k) constructs precisely that trajectory, and the vertex formula then gives its true maximum height.

## Python Solution

```python
import sys
input = sys.stdin.readline

def solve():
    a, b, c, d = map(int, input().split())

    L = a + c

    # The optimal trajectory passes exactly through the top
    # of the wall.
    k = (d - a * b / L) / (a * c)

    # Maximum value of
    # y(x) = k*x*(L-x) + (b/L)*x
    h = (k * L + b / L) ** 2 / (4 * k)

    print(f"{h:.15f}")

if __name__ == "__main__":
    solve()
```

The first calculation forms the complete horizontal distance (L=a+c). Keeping this value explicit makes the geometry easier to follow and avoids repeatedly writing the same sum.

The next line solves the wall equation directly. The expression `a * b / L` is the contribution of the linear part of the parabola at the wall, while `a * c` is the coefficient multiplying (k). The order of these operations matters because the division by (L) must happen before subtracting the contribution from the required wall height.

The final expression is the value of the quadratic at its vertex. It is preferable to evaluate the vertex height directly rather than first computing the vertex coordinate and then substituting it into the parabola. This uses fewer operations and avoids an unnecessary intermediate value.

All input values are integers, but `/` deliberately produces floating-point values. Python integers themselves do not overflow, and the remaining arithmetic uses Python's double-precision floating-point representation.

The output uses fifteen digits after the decimal point. The official statement allows numerical tolerance, so matching the sample's exact floating-point representation is unnecessary.

## Edge Cases

For the ground-level target case

```
5 0 9 7
```

the calculation gives (L=14) and

[
k=\frac{7}{5\cdot9}=\frac{7}{45}.
]

The maximum is

[
h=\frac{(14k)^2}{4k}=49k=\frac{343}{45}\approx7.622222.
]

Nothing in the algorithm divides by (b), so the zero target height causes no special case.

For the symmetric case

```
5 0 5 7
```

we obtain (L=10) and (k=7/25=0.28). The vertex occurs at (x=5), exactly where the wall stands, and its height is (7). The algorithm consequently returns (7.000000000000000) up to floating-point representation.

For a high target near the wall, consider

```
5 9 1 10
```

where (L=6). The wall equation gives

[
k=\frac{10-\frac{45}{6}}{5}
=\frac{1}{2}.
]

The maximum height is

[
h=\frac{(3+1.5)^2}{2}=10.125.
]

The calculation demonstrates why the target height must be included in both the wall constraint and the vertex formula. Treating the trajectory as if both endpoints were at ground level would produce a different and incorrect result.

Finally, the constraint (b<d) guarantees that the target is below the wall. This is what makes the optimal trajectory touch the wall exactly at height (d). If an implementation accidentally uses `>` instead of `>=` conceptually when deriving the wall condition, it may choose a trajectory unnecessarily higher than required and thus fail to minimize the maximum height.
