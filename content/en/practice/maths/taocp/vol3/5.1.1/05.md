[Section 5.1.1: Inversions](../)

**Exercise 5.** [*35*] The algorithm of exercise 4 requires an execution time roughly proportional to $n + b_1 + \cdots + b_n$ on typical computers, and this is $\Theta(n^2)$ on the average. Is there an algorithm whose worst-case running time is substantially better than order $n^2$?

**Verified:** yes  
**Solve time:** 6m03s  

---

## Setup

At the beginning of the iteration for \(j\), call a position *available* if no value has yet been assigned to it. The available positions will eventually contain the values \(j,j+1,\ldots,n\).

The constraint \(0\le b_j\le n-j\) implies
\[
1\le b_j+1\le n-j+1,
\]
so the \((b_j+1)\)st available position from the left always exists.

## Solution

Maintain the \(n\) positions \(1,2,\ldots,n\), initially all available. Process \(j=1,2,\ldots,n\). At step \(j\), select the \((b_j+1)\)st available position from the left, place \(j\) there, and mark that position unavailable.

The required operation is therefore an order-statistic operation on a dynamic set of positions. A Fenwick tree can implement it as follows. Let \(F[i]\) represent the usual Fenwick-tree partial sums for the indicator array
\[
c_i=
\begin{cases}
1,&\text{if position }i\text{ is available},\\
0,&\text{otherwise}.
\end{cases}
\]
Initially \(c_i=1\) for every \(i\). The operation \(\operatorname{select}(r)\) returns the least position \(p\) such that
\[
\sum_{i=1}^{p}c_i=r.
\]
It is found by the standard binary-lifting search in the Fenwick tree. After using position \(p\), perform the update \(c_p\gets c_p-1\).

Thus the algorithm is

\[
\begin{array}{l}
\textsc{Construct}(b_1,\ldots,b_n):\\
\qquad\text{initialize a Fenwick tree with }c_1=\cdots=c_n=1;\\
\qquad\text{for }j\gets 1\text{ to }n\text{ do}\\
\qquad\qquad p\gets \operatorname{select}(b_j+1);\\
\qquad\qquad a_p\gets j;\\
\qquad\qquad\text{update }c_p\gets c_p-1;\\
\qquad\text{return }a_1a_2\ldots a_n.
\end{array}
\]

### Correctness invariant

At the beginning of iteration \(j\), the available positions are exactly the positions that will contain
\[
j,j+1,\ldots,n
\]
in the completed permutation. Consequently, every available position to the left of the position selected for \(j\) will eventually contain a value greater than \(j\).

Initially, all positions are available, so the invariant holds for \(j=1\). Suppose it holds at the beginning of iteration \(j\). The algorithm selects the \((b_j+1)\)st available position, so exactly \(b_j\) available positions lie to its left. By the invariant, those positions will contain values greater than \(j\). After placing \(j\), the remaining available positions are precisely those that will contain
\[
j+1,j+2,\ldots,n,
\]
so the invariant holds for the next iteration.

Therefore, when the algorithm terminates, exactly \(b_j\) elements greater than \(j\) lie to the left of \(j\). Hence the resulting permutation has inversion table \(b_1b_2\ldots b_n\).

The algorithm terminates after exactly \(n\) iterations. Each iteration performs one order-statistic query and one Fenwick-tree update, each taking \(O(\log n)\) time. Initialization takes \(O(n)\) time, and the storage requirement is \(O(n)\). Thus the worst-case running time is
\[
O(n\log n),
\]
which is substantially better than \(\Theta(n^2)\).

For the inversion table
\[
2\ 3\ 6\ 4\ 0\ 2\ 2\ 1\ 0,
\]
the selected positions for \(j=1,2,\ldots,9\) are respectively
\[
3,5,9,7,1,6,8,4,2.
\]
Putting \(j\) in its selected position gives
\[
5\ 9\ 1\ 8\ 2\ 6\ 4\ 7\ 3,
\]
as required.

## Verification

Directly inspecting this permutation gives
\[
\begin{aligned}
b_1&=2, &&\text{from }5,9\text{ to the left of }1,\\
b_2&=3, &&\text{from }5,9,8\text{ to the left of }2,\\
b_3&=6, &&\text{from }5,9,8,6,4,7\text{ to the left of }3,\\
b_4&=4, &&\text{from }5,9,8,6\text{ to the left of }4,\\
b_5&=0,\\
b_6&=2, &&\text{from }9,8\text{ to the left of }6,\\
b_7&=2, &&\text{from }9,8\text{ to the left of }7,\\
b_8&=1, &&\text{from }9\text{ to the left of }8,\\
b_9&=0.
\end{aligned}
\]
This independently reproduces the prescribed inversion table.

\[
\boxed{\text{A Fenwick-tree order-statistic algorithm constructs the permutation in worst-case }O(n\log n)\text{ time and }O(n)\text{ space}.}
\]
